## 问题（按严重度）

### 1. 【低】分段下界的 m 对四道段边界一律取最小，理论上会在两处没有表面的地方造出「幻影墙」

- **现象（推导）**：`m = min(|z−襟翼 s0|, |z−襟翼 s1|, |z−缝翼 s0|, |z−缝翼 s1|)`，下界是 `min(d, max(完整翼型距离, m))`。它确实是下界，而且比旧值更小，所以不会越过表面。但球体追踪只要距离场接近 0 就判打中，所以下界还得「只在真表面上为 0」。有两块区域两侧都没有表面，下界却在那里降到 0：
  - s = 0.06（缝翼内端）这道平面上、完整翼型包络里 xi > 0.74 的部分。襟翼放下时，这一段两侧都只到整流罩末端，没有后缘。
  - s = 0.72（襟翼外端）这道平面上、xi < 0.09 的缝翼槽。缝翼伸出时，两侧都是 D 形前缘，槽里是空的。

  实现者踩过的「坑中坑」是同一类问题：只取竖直项时，后缘后面出现了一面墙。那次修掉了一处，这两处还在。
- **实测**：我做了一个分区下界的变体 `tight`：襟翼那两道边界只对 xi > 0.52 生效，缝翼那两道只对 xi < 0.14 生效。在同一页面、同一冻结时刻和 `new` 对照（`p1/`）：

  | 场景 | 非机翼像素差 | 机翼像素差 | 差 > 3 级（显示值） |
  | --- | --- | --- | --- |
  | 云里两个姿态 | 0 | 31–37 | 0 |
  | 正午 wing-pos 8，强制襟翼 25° / 缝翼 22° | 0 | 2941 | 8 |
  | 经济舱看前方，强制襟翼 / 缝翼 | 0 | 21983 | 104（翼根附近缝线上 1 像素的位置抖动，最大 34 级） |

  这几个视角里没看到成片的幻影墙，这两块区域从舱内基本看不到，或者被挡住了。
- **修法（建议合并前顺手改）**：把 m 按段分开，并各自限定弦向范围：

  ```glsl
  if (uFlap > 1e-3) { float mf = min(|z−S0f|, |z−S1f|); d = min(d, max(max(fd, mf), (0.52 − xi)·c·cosΛ)); }
  if (uSlat > 1e-3) { float ms = min(|z−S0s|, |z−S1s|); d = min(d, max(max(fd, ms), (xi − 0.14)·c·cosΛ)); }
  ```

  0.52 是整流罩下表面开始上收的位置，0.14 是 D 形前缘收圆结束的位置，所以这样仍然是下界。自阴影也走同一个距离场，改完这一处，阴影里的幻影墙也一起没了。如果不改，至少在 README 坑点里补一句「下界降到 0 的地方必须真有表面」。

## 按重点逐条核实

### 1. 距离场下界

- **是真下界**：段内截面（整流罩、D 形前缘）都是完整翼型的子集。我核对了 s = 0.72、xi = 0.74 处的 `yU − 0.04`：翼厚约 0.063·弦长，远大于 0.04 m，整流罩下表面不会伸出包络。离开本段至少要走 m，段外的材料都在包络里，所以 `真实距离 ≥ min(d, max(完整翼型距离, m))` 成立。新值只会 ≤ 旧值，不会越过表面。
- **Lipschitz ≤ 1 保持**：`|z−c|` 的斜率是 1，完整翼型距离和原来的 dx、dy 同一种构造，min / max 不会让斜率变大。
- **步数没有暴涨**（我用 `W-STAIR-iter.py` 复测，结果是确定的）：

  | 场景 | sdWing 调用总数 | 按块取最大（近似 warp） | 单像素最多步数 |
  | --- | --- | --- | --- |
  | sunset-wing（襟翼收起） | +0.13% | +0.07% | 不变 |
  | 云里 | +1.31% | +0.96% | 293 → 285 |
  | 正午加襟翼 | +1.76% | +1.53% | 300 → 291 |
  | 经济舱看前方加襟翼 | +1.17% | +0.67% | 281 → 276 |

  和实现者的 +0.13% / +1.30% 一致。最慢的像素反而变快了，因为不再一步扎进体内。
- **收起时逐位不变**：代码走 uniform 分支，没进分支时 `max(d, dz)` 和旧的 `max(max(dy,dx),dz)` 完全相同。实测 flaps-up 场景只有边缘像素有差，见第 2 条。

### 2. 饿死规则会不会误填

- 门槛的实际含义：pool 是 64 步，`SUB_MIN` 是 8。第 1 条子射线至少分到 40 步，永远不会被判饿死；从第 2 条起，只有前面的子射线用掉超过约 16 步，后面的才可能饿死。中心射线分到 128 步，也不会被判饿死。
- 以参考图（1024 + 8192，每条子射线 64 步）为准，我统计了五个场景（`starve/`）：
  - `new` 在「参考图没写机翼」的像素上**新写入 0 个**，在参考图写了机翼的像素上**漏写 0 个**，所以没有整像素的外扩。
  - 在都有机翼的像素上，`new` 比参考图「更实」的有 73–286 个，都是斜边上每一级台阶处 1 个像素（`*-more.png`）。和参考图相对差 > 10% 的像素只有 98–324 个，是 old / nostarve / new 三者里最少的，old 是 315–2989 个。
  - 放大图里看不到翼尖小翼、天线、襟翼滑轨缝、内外襟翼之间 4 cm 缝被填上的情况：`sunset-wing-more.png` 第二行的小台阶和参考图一致。
- **门槛 1/4 合理**：「一律按打中算」和「只算还在逼近的」两种做法，实现者都用参考图比过，都更差。我的数据也支持现在的门槛。它的风险在于偏向判「实」，代价是斜边每级台阶多约 1/5 像素的覆盖，目前看不出来。

### 3. 开销

- 同页批渲，我在这台机器上测了一次，old / new 交替 4 轮：sunset-wing 0.507 → 0.535 ms（+5.5%），云里 0.723 → 0.757 ms（+4.6%），和实现者的 +5.3% / +3.9% 一致。
- 逐项撤回（sunset，old / new / 撤回某一项交替）：去掉饿死规则 0.525，去掉中心样本 0.528，擦边判定改回 1 像素 0.527，去掉下界分支 0.528。**没有哪一项单独撤回能回到 0.505**，开销分散在几项上，也可能来自寄存器压力，砍掉任何一项都换不回来。
- 按门槛判断：绝对值约 0.03 ms 一帧，远低于 SOP 第 5 节第 4 条「帧时间退化超过 20% 要给理由」的线。「> 5%」只是触发审查的条件，不是否决线。**可以接受**，波次收尾复测时留意一下就行。
- 冷编译：wing +2.3%，wing-wet +3.2%，没超过单任务 ≤ 10% 的门槛，我没重测。机翼程序**离关键路径很近**：README 里 PERF-14 的记录是，批次中机翼在 6.5–7.8 s 编好，窗外在 6.8–8.5 s，差 0.2–0.7 s。+2.3% 大约是 +0.15 s，还在窗外之后。湿窗变体只在窗上有水时才编，不在冷启动批次里。请性能工程师收尾时在「批次各程序编好」里看一下机翼和窗外的间隔还剩多少。

### 4. TM02 的前提

- 我在五个场景统计了「旧版没写、新版写了」的像素：sunset 0 个，商务舱 1 个，云里 93 个，正午加襟翼 101 个，经济舱 0 个。它们和旧机翼的距离全部 ≤ 2 像素。这些像素的机翼覆盖率 ≥ 0.2（5 个样本里中心至少占 1 份），`dW` 远大于 1e-4，门控取 0，也就是按机翼处理。有写入的地方本来就该按机翼处理，所以不违背「无机翼像素逐位照抄」这个前提。
- **亮 / 暗环**：我在最终显示（含曝光合成）里检查了轮廓像素，看它们是否越出「背景显示值」和「9×9 内纯机翼显示值」的范围，容差 6 级。新写入的像素里，越界的是 0、0、0、1、0 个。轮廓整体的亮越界 old / new 差不多（80 / 77，227 / 230，200 / 204）。暗越界在两个白天场景略多（69 → 91，105 → 144），就是第 4 条说的前缘那几十个像素，和参考图一致，不是门控造成的环。
