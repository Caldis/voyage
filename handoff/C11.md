## 方案

resolve 的邻域夹取循环里本来就读了 3×3 个 texel，顺手求和；循环后：

```glsl
if (!depthHalf) cur = mix(cur, nsum * (1.0 / 9.0), clamp(uCloudImmersion * 1.0204 - 0.0204, 0.0, 1.0));
```

- 零额外取样。`uCloudImmersion` 与步进程序、曝光的 `uWhiteout` 是同一个 uniform 对象（`EXPOSURE_WHITEOUT`）。
- 历史收敛到的是本帧的 3×3 盒式滤波，也就是云缓冲上固定做一次 3×3 模糊，不会逐帧叠加变糊。云里满窗是几十米内的雾，没有要保的细节。
- **0.02 门槛**：whiteout 出云后按 0.5 s 指数衰减，要约一分钟才真正变成 0（第一次测 clouds-variety 时 imm 还有 0.007）。不设门槛的话，出云后几秒内还在做 1% 量级的平均，云外就不再逐位等于改动前。现在出云约 2 s 后权重为 0。
- 用 k = 1（满权重）。INCLOUD-CHECKER 的原型里 k = 0.5 只把相邻像素差除以 1.8，不够。

## 深度边处理（必须复核项）

- **不需要按深度 / 不透明度加权**。云缓冲左半只有云：步进程序不认识机翼、机身和地面（`seg` 只受云壳和 `AERIAL_MAX_DISTANCE` 限制；地面在窗外 pass 里按右半的深度 `cloudBeforeGround` 再合成，机翼在机翼 pass 里盖上去，雾色取机翼背后的云缓冲）。所以 3×3 里没有别的物体的边，平均跨不过深度边。
- 右半（深度 × 不透明度）不做平均，免得云在山前还是山后的判断被抹宽。
- 窗板外那圈 `(0, 0, 0, 1)` 只在 paneDistance 0.02–0.025 的范围里，在窗框后面，看不到。
- **实测**（`handoff/C11_wing.py`，8 个姿态 × 3 个放大区：翼尖小翼、翼根 / 襟翼整流罩、前缘对雾）：
  - 两张 16 帧平均图（old 和 new）之差，沿机翼轮廓**没有亮线或暗线**，只剩噪声（`|平均差|` 均值 0.03–1.1 /255，p99 ≤ 3.6）。唯一偏大的 ic_-30_-5 z2（均值 2.8）是整块亮度差：这个姿态的 HDR 均值 new / old ×1.018，与边无关。
  - 机翼边上的单帧 adj：z0 1.4–7.8 → 0.39–1.02，z1 0.6–4.8 → 0.57–1.00，z2 1.3–6.0 → 0.44–0.76。
  - **INCLOUD-CHECKER 说的「2 px 阶梯」是机翼 pass 自己的**：襟翼滑轨整流罩下面的点阵阴影、亮三角的斜边，在**改动前的 16 帧平均图**里一模一样（`D:\Code\opus-test\tmp\screenshot\c11\wing\stair_z1.png`，每行依次是 old 单帧、old 平均、new 单帧、new 平均，对比度拉伸），原来被云的噪声盖住了，现在露了出来。机翼不在本任务的归属里，建议另开任务（像是机翼自阴影或 AO 的逐像素抖动没有累积，16 帧平均也不收敛）。

### 静态检查与开销

- `typecheck`、`check:glsl`（全部通过，含场景表同步）、`build` 都通过，`dist/assets` 没有 0 字节文件。A/B 两轮 20 个 job 的控制台里，除 eox 瓦片的跨域报错外没有 console.error / pageerror。
- `shader-parity --base tmp/c11-base`：只有 `cloud-resolve` 不同，cloud-march 等其余程序逐字相同。
- **冷编译**（`shader-budget --baseline tmp/c11-base --only cloud-resolve --rounds 5`，最小值）：cloud-resolve 57 → 65 ms（**+14%**，MAD 1）。复测一次把门槛的 clamp 去掉，仍是 +12%，所以代价在 9 次 vec4 累加本身（循环是展开的），不在门槛。按绝对值算是 +8 ms；云程序合计（cloud-march 约 500 ms + resolve）约 +1.4%；resolve 和 cloud-march 在启动批次里并行编译，关键路径是 cloud-march（不变）。**单看 resolve 超过 5%，请协调者判断口径**；我认为不构成冷启动风险。
- GPU（`passes.mjs --only in-cloud --variants handoff/C11-variants-cost.mjs --material clouds.resolveMat`）：resolve 中位 0.036–0.037 ms，去掉平均和满权重之间没有差别。注意工具提示「换变体后 currentProgram 身份没变」，这个对照只能作参考；但 9 次加法本身可以忽略。
