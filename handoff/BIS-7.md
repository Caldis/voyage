### 机制（`src/render/exposure.ts`，T48 加的两段）

1. **AgX 之后的保色**：`hue = x · min(Y(AgX)/Y(x), 1/max(x))`，然后 `mix(a, hue, 0.45 · nightO · satKeep)`。无月夜的窗外适应亮度很低，曝光把灯推到中灰以上 4–7 档，`x` 的最大通道远远大于 1。`1/max(x)` 这一支把每一个过曝的灯都归一到「最大通道 = 1」，4 倍亮和 100 倍亮的灯结果一样。灯点、光晕、城区底色于是连成一块同亮度的奶油色平台（≥250 的像素从 21% 变成 0，就是这个原因）。
2. **浦肯野只保色度**：`c = c · Y(cs)/Y(c)`，亮度按视杆的光谱灵敏度走。钠灯橙在视杆下很暗，所以橙色路网的亮度跌了一大截，淹进城区的白色光晕里（`z-night-split.png` 第 2 张对第 3 张：只关 mesopic 保色，路网就回来了）。
3. G01 在这之上又抬了一档（亮度 +17、饱和度 +12）。原因是 EOX 2025 加航拍后，路灯聚落的阈值区亮起更多村镇（和 G01 合并记录「均值 73 → 83」一致）。这一条没有再往下拆开关，**属于推断**。

### 建议修法与归属

- **归属 `render/exposure.ts`（T48 的后续，建议开 T48b）**：
  1. 色调映射后的保色**不要归一到 `1/max`**：只拉色度，亮度保持 AgX 的结果，比如在 AgX 输出上按 `Y(a)` 重建「同色相」的颜色，放不下时向白色去饱和（这是正常的高光去饱和），不要降亮度。或者给 `nightChroma` 再乘一个按「AgX 前最大通道」的淡出，例如 `1 − smoothstep(1, 4, max(x))`，让真正过曝的灯芯保持发白，只在肩部以下保色。
  2. 浦肯野保色的亮度改成 `mix(Y视杆, Y明视, keep)`，不要整段按视杆算。否则钠灯路网在「够亮、进了中间视」的时候反而被压暗，这和 T48 自己的物理说法（像素已经刺激视锥细胞）是矛盾的。
  3. 验收：`night-city-off` 的城区相邻差 ≥ 6（T48 之前的水平；wave6 的 19 是月夜口径，不能直接对比），≥250 的像素 ≤ 3%，能看到橙色路网；`night-city-on` 和黄昏场景零回归。
- **归属：美术总监 / 协调者（口径）**：往后夜城跨波对比一律用 `scenarios.mjs` 的固定日期。wave6 的 night-city 截图是满月，不能当基线；建议在 ART_REVIEW_wave7 第 3 条补一句更正。
- **可以另立一项（`exposure.ts` 适应）**：无月夜城区在 T48 之前也有 20% 死白。4 km 看一座亮城时，全关档自动曝光抬得太高，这是更底层的问题，可以让曝光的测光权重对「大面积点光源」减敏。属于方向建议，没有做实验。

### 注意：测夜景时瓦片加载不稳

- `shots` 的 info 行写的「地面瓦片加载中（N）」是 `applyScene` 早期取的，`--settle` 等到 `ground.pending === 0` 以后它不会更新。我在场景 js 里实测，settle 后 pending 是 0，所以**这一行不能用来判断截图时瓦片是否已经加载完**。

- 时间窗拉长后斜纹基本消失（`z-blend-variety.png`），说明它是**没有收敛的采样噪声**，不是云密度或光照本身的结构。
- 主步进抖动换成白噪声以后，**斜纹的方向性完全消失**，变成各向同性的细颗粒（`z-jitter-white.png`）。颗粒的总量变大，所以数值是升的。噪声幅度约 1/4 来自主步进抖动，只换 `gDetailRnd` 的影响约为前者的 1/3。所以「斜纹 / 纱窗」的图样来自**主步进 IGN 抖动的空间结构**：每帧都是同一种对角图样，只是相位按 0.618 移动。8 帧的指数平均和 3×3 邻域夹取之后，留下来的残差还是对角的。
- 把 IGN 按帧整体平移也没用（`z-ignshift.png`）：IGN 每一帧自身就是对角的。

### 建议修法（给 C12）与归属

- **归属 `clouds/clouds.ts`（主步进 `jitter`，第 284 行附近）**：
  1. 首选：步进抖动改用**各向同性的蓝噪声纹理**（64² 或 128²，每帧按 R2 / 黄金比整体偏移，或者用时空蓝噪声 STBN 的 64 层）。白噪声实验说明，去掉 IGN 的空间结构就能去掉方向性；蓝噪声的颗粒应当比白噪声少。蓝噪声本身**没有测过**，这是推断。云程序的 sampler 余量要先查（`check:glsl` 的 sampler 表只覆盖场景 / 窗外程序）。
  2. 可以一起做：相机不动或慢动时，resolve 的 `blend` 按重投影速度自适应降到 0.03–0.05（实验 0.02 时对角高频 −63%）。运动时保持 0.12，避免拖影。
  3. `gDetailRnd` 是次要的，可以顺手换成同一张蓝噪声的另一层 / 另一偏移，不用单独立项。
- **不建议**把矛头放在 C03：C03 前后指标持平。它加的 `gDetailRnd` 只贡献噪声的一小部分。
- 验收：clouds-variety / backlit-cu / noon-cumulus 同一裁剪，**按亮度归一的相邻差回到 C01 之前的水平**（clouds-variety ≤ .017、noon-cumulus ≤ .015）。绝对相邻差不要求回到 1.9，C01 本来就把云的真实对比拉高了。放大 3 倍看不到平行斜纹；按 SOP 再测 8 个固定姿态的几何均值。
- C11（云里棋盘纹）大概率是同一个源头（主步进抖动 + C01 以后受光对 od 敏感）。建议和 C12 共用一个随机数方案。

## 证据强度汇总

- 夜城：T48 是真回归 ——**已证实**（开关复原）；月光口径 ——**已证实**（同提交换日期）；G01 的增量 ——二分定位**已证实**，机制是推断；G06 / C02 / TM01 无关 ——**已证实**。
- 云面：放大者 C01（普遍）、T12（逆光）、TM01（小）——二分**已证实**；图样来源是主步进 IGN 抖动 ——**已证实**（白噪声开关 + 时间窗开关）；蓝噪声修法 ——**推断**，没有实测。

## 开发体验反馈

- **哪里慢**：每个提交一轮（建 worktree 2 s + pnpm install 2 s + vite + shots）大约 1.5–2 分钟，一共跑了约 30 轮，总计约 1 小时。真正慢的是等瓦片：夜景每轮 settle 最多 40 s。
- **哪里卡**
  1. `shots` 的 info 行「地面瓦片加载中（N）」是 `applyScene` 早期的快照，settle 以后不更新，很容易误判「瓦片没加载完」（美术总监 wave7 的 night-city 写着 72，我一开始也以为是瓦片没加载完导致的糊）。**建议**：截图前重新取一次 info，或者在 JSON 里单独写 `groundPendingAtShot`。
  2. 反复拍带地面的场景后，EOX 开始成批返回 CORS 失败，城区整片没灯，但 `shots` 只打印「N 条 console error」，截图照样出。**建议**：`--settle` 超时或错误数超过阈值时，在 JSON 里标 `groundIncomplete: true`，并在控制台打一行醒目的警告。
  3. `--pair` 的 js 补丁会留在同一页面的后续场景里（README 写过，但 pair 模式下更容易踩：b 的补丁变成了下一个场景的 a）。我的 blend 实验因此丢了 backlit-cu 的对照。**建议**：`--pair` 每个场景结束后自动 reload，或者提供 `--pair-reset`。
  4. `--base-shader` 换不了云（C01 以后 uniform 变了），所以只能整棵切 worktree。美术总监提过的 `dev-browser bisect --commits a,b,c` 很有必要：我自己写了一个 `bis7-run.ps1`（建 worktree → vite → shots → 关进程），大约 40 行，可以直接收成正式工具。
- **怎么绕过的**：各个 worktree 共用 pnpm store（安装 2 s）；每个场景单独一个场景文件，避免补丁串到别的场景；瓦片失败的轮次作废重拍。
