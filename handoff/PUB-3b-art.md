## 阻塞级问题

### B1 默认首屏空无一物（首屏 / 默认设置）

- 截图：`c/first-1600-t3.png`、`c/first-1600-t15.png`、`c/first-390-t13.png`；做了反差拉伸的 `crop/first-sea-contrast.png`。
- 现象：这次打开是 16:50（JST），航段「当前位置 → 大阪关西」，天气晴空、云量 0%。窗下除了机翼，整片是灰蓝渐变：没有一朵云，海面也没有任何纹理（拉伸反差后仍然是光滑渐变），地平线也不清楚。手机竖屏上，这片空白占了画面的 2/3。
- 判断依据：这是用户看到的第一眼。「航行伴侣」的卖点是窗外的风景，但首屏读起来像「没加载出来」或「只有一张天空贴图」，属于任务定义里的「默认首屏明显难看」。它并不违反物理：顺光、薄霾、无云的海面从 10.7 km 看下去确实很平。问题在于连续航程把首屏交给了实时天气场，天气场随机到 0% 时没有兜底。
- 建议修法（任选其一，都只改 CPU 侧）：
  1. 首载兜底：连续航程第一次对齐天气时，若云量低于约 15%，本段导演用 nudge 把云量抬到 25–40% 的积云（这是 UX-2 已有的机制，面板照常标「自动」）。之后照天气场自然演变。
  2. 或者把 VOY-START（现为【降级】）提回第一档：首段固定为有云、有侧光的构图，时刻或地点可按真实时间挑。
- 难度：低（半天以内）。验证时要在不同真实时刻各打开几次，因为首屏依赖挂钟。

### B2 机翼襟翼滑轨整流罩下沿是阶梯锯齿（默认首屏可见）

- 截图：`crop/d-fairing.png`（首屏 1600 放大 4×）、`crop/m-fairing.png`（手机 3×）、`crop/noon-fairing.png`、`crop/sunset-fairing.png`。
- 现象：翼后缘下挂的几个整流罩（part 5），下沿和尾端竖边是 1 px 的硬台阶，没有覆盖率抗锯齿。主翼轮廓是平滑的，两者并排反差很明显。首屏整流罩是深色，背景是亮霾，对比度最高，所以最显眼；noon / sunset 各场景都有。
- 测量：`flicker --only noon-cumulus`，头部每帧移 0.06 mm。整流罩区（620,560,200,120）的爬行指标为 0.0012，旁边主翼后缘区（420,640,200,120）为 0.0005，约 2.4 倍。机翼随颠簸 / 头部晃动时，台阶会沿边爬。
- 判断依据：违反铁律「锯齿 / 闪烁是最高优先级」，而且就在默认首屏的视觉中心附近。它是 ART-8 已记的「尾端梳齿锯齿」，但 W-EDGE 做的「part 5 部分覆盖走 RGSS」没有覆盖到下沿 / 尾端对天空的这条轮廓。
- 建议修法：沿用 W-EDGE 的解析覆盖率思路，给整流罩截面（下沿曲线、尾端平切面）补距离覆盖率。或者尾端改成收尖、圆滑的截面，从几何上去掉竖直平切。验收：首屏和 sunset-wing 放大后没有台阶，flicker 整流罩区的爬行指标降到与主翼后缘同量级。
- 难度：中（机翼程序在冷启动批次里，要守冷编译门槛）。

### B3 奇观（巨柱群 / 天梯 / 建木）挡不住太阳圆盘，巨柱群还挡不住月亮（奇观模式内的几何穿帮）

- 截图：`d/p3b-pillars-sun.png` 与放大图 `crop/pillars-sun.png`（17:00 太阳约 8°，日面整盘压在一根巨柱上面）；`b/ws-pillars-dusk.png` 与放大图 `crop/pillars-dusk-dot.png`（满月整盘画在一根远柱的柱身上）。
- 现象：日面、月面都「贴」在柱子前面，柱子读成透明的。天梯 / 建木用的是同一条路径（`d/p3b-tether-sun.png` 这次太阳高过塔顶，没压到，但代码上同样不挡）。
- 判断依据：属于露馅 / 几何穿帮。黄昏窗朝太阳正是最常见的构图，奇观一旦出在太阳方位就会被看见。
- 根因（读代码，供实现者核实）：
  1. `src/render/outside-pass.ts` 第 247–253 行，只有 `ORBIT_RING` 与 `VERTICAL_CONTINENT` 两支把 `opticsSunDisk` 乘了 `(1 - 覆盖)`；`#else` 分支（巨柱群 OWP 与天梯 / 建木的 wonderSky 都走这里）直接加日面。
  2. 月面在第 216 行先加进背景 L。垂直大陆在 `continent.glsl.ts:298` 先从 `Lbg` 里减掉月面，天环在第 234 行按覆盖把月面减掉，巨柱群 / wonderSky 两处都没做。巨柱群着色里用 `Lbg`（含月面）参与前景空气与封顶计算，覆盖不满（浮现前沿 `visk` / 远柱 cov < 1）时月面还会透出来。
- 建议修法：在 `#ifdef OUTSIDE_WONDER` 内统一处理。日面改为 `L += opticsSunDisk(rd, hitGround) * (1.0 - gWonderCov)`；巨柱群与 wonderSky 进入时照 continent 的做法从 `Lbg` 扣掉月面，出口按 `gWonderCov` 把月面减掉。默认程序 OW 不受影响（只动 OUTSIDE_WONDER 分支），可用 check:glsl / shader-parity 证明逐字不变。
- 难度：低（一两行加复测；参照 WS08 审查、WS-STAR 的同类修法）。复测用 `handoff/PUB-3b-sun-jobs.json` 与 ws-pillars-dusk。

### B4 垂直大陆黄昏 / 正午读成半透明玻璃板（奇观模式内的「玻璃罩类假形状」）

- 截图：`b/ws-vcont-dusk.png`（最严重）、`b/ws-vcont-noon.png`。
- 现象：黄昏时，天空的橙色地平带、蓝色地影带原样横穿岩壁。岩壁下半段与背后天空几乎同色，只剩一圈轮廓，整体像一块立在云海上的磨砂玻璃板。正午时岩壁发白偏透，右段还有直线形的顶沿和竖向条带，读成一个半透明的盒子。夜景（`b/ws-vcont-night.png`）是剪影，没问题。
- 判断依据：任务定义里明确列出的「玻璃罩类假形状」。它不是细微的色差：第一眼读不出「岩石」。WS09-b 记的「正午偏磨砂、贯穿亮横带」就是这个问题，被归成了【降级】，从发布视角看这个定级偏轻。
- 建议修法：
  - 发布前（低难度）：在自动出场池里暂时去掉垂直大陆，或把它的权重降到接近 0，只保留 URL / 调试触发。改 catalog.ts 的一处权重或开关即可，不动着色器。
  - 根治（中高难度，归 WS09-b）：岩壁在相机到岩壁这段空气上的内散射，要按岩壁自身所处的受光 / 地影状态算，不能直接套背景天空的分带。岩壁反照率与自阴影要让它比同方向天空明显更实、更有明暗。
- 奇观模式默认关，所以这一条不影响默认体验。但用户打开奇观、随机抽中时，它是最出戏的一处。

## 总体结论

**默认体验（奇观关、非火车）没有闪烁、露馅或整帧伪影，可以作为稳定版对外。** 发布前建议补两件小事：

1. B1 首屏兜底（低难度）：实时天气抽到 0% 云时，首屏几乎是一张空白渐变，第一印象太弱。
2. B2 整流罩锯齿（中难度）：就在首屏视觉中心，而且是铁律里最高优先级的缺陷类型。如果来不及，可以先发，但排在稳定版之后的第一位。

奇观模式有两项真阻塞，但奇观默认关，可以低成本处理：B3 日 / 月穿柱是一两行的修复，建议直接修；B4 垂直大陆玻璃感建议先从自动出场池拿掉，根治留给 WS09-b。按此处理后，我同意对外。
