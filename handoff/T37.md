## 先测量：「栏杆」是什么

`handoff/T37-exp.mjs`（T26-exp 的副本，输出到 `tmp/screenshot/T37/<tag>/`）在 typhoon-eye 上逐项关：
- 关掉卷云盖 → 栏杆消失（`tmp/screenshot/T37/rail/cmp.png`，上 base、中 nocanopy、下 noover）。
- **根因**：卷云盖顶处处约 16 km（`HUR_TOP − …`），顶沿高度 `hurricaneRimTop(θ)` 在 14–17.4 km 之间变。顶沿低的扇区，从眼里看，顶沿后面露出一道比顶沿还高、光滑水平的卷云盖边，就是栏杆。
- 关掉卷云盖后，顶沿本身在圆顶之间也是一条水平线（圆顶是一个个孤立的小丘）；另外顶沿外侧的眼壁云体被抬到统一的 `HUR_TOP`，同样会在低扇区后面露出水平线。

## 改法

1. **眼壁顶沿**
   - 卷云盖顶改成 `hurricaneCanopyTop(θ, r)`：眼壁附近压在顶沿以下 1.2 km 并随顶沿起伏，3.5–6 倍眼半径以外回到原高度（往外回升那段从眼里看仰角比顶沿低，被挡住）。探针 / 云影用的大形 `hurricaneShadowDensity` 用同一个函数（T31 坑：两边高度要一致）。
   - 眼壁云顶不再往外抬到统一的 `HUR_TOP`，而是从顶沿往外缓慢下降（`hurricaneRimTop − 1.4·smoothstep(2Re, 5Re, r)`）。
   - 顶沿到处叠两级球冠起伏（`turret`，约 ±1 km），上冲圆顶从塔群里冒出来；再加一级细鼓包（新的水平切片噪声 `nR2`，θ × r），**只往下刻**。
   - （试过、撤回）卷云盖顶面 / 底面用丝缕噪声软化 ±0.5 km：typhoon-outer（13 km，就在卷云盖底下）云步进 +0.7 ms，相机附近多出一大片要细走的稀薄云。眼壁附近的卷云盖顶已压到顶沿以下、从眼里看不到，所以不做。
   - `rimZone` 改成离「卷云盖高度上的内缘」多远（和高度无关）。
2. **雨带塔**（新函数 `bandTowerAxis` / `bandTowerSdf`，完整版和受光版共用）
   - 主柱上宽下窄（底部 70–95%）；两个侧向气泡（上部的次级塔顶、中部侧面的隆起），大小 / 方位 / 高度每座塔不同，平滑并起来；
   - 塔轴顺高空风吹歪 0.1–0.35 倍塔高（约 6–19°），带一点横向；
   - 相邻塔平滑并成塔群（`sminStorm(…, 1.0)`）；菜花隆起幅度随高度增大；
   - 胖瘦 2.4–5 km（原 3.3–5）。
3. **雨带砧**：不再是「最近一座高塔一块透镜」，而是每座高塔一个下风拉长的核（顺风半轴 2–2.5 倍塔半径、上风方短一半、横向 0.7 倍），**核加起来**：相邻的砧融成一片；厚度随核值变薄（外缘薄到没有），顶面约 3 km 的鼓包（靠近砧心大、外缘小），底面絮状下垂的鼓包 + 靠近塔顶下弯；外缘用沿风拉长、随高度变的噪声撕碎。顶面 / 底面高度场只用水平切片噪声。
4. **单体窗口与带轴判断**（顺手修的正确性问题）
   - 3×3 窗口高处顺高空风往回挪 5 km：砧和吹歪的塔顶偏下风，窗口跟着；每座塔所有部分都落在「塔心 + 挪动量」13 km 以内，换格子时不截直边。
   - 格子的螺旋相位按格子中心求（原来从采样点一阶外推，内圈误差 0.4 rad，同一座塔在不同采样点上高矮不同）。方位角差用 atan 的有理近似 `x / (1 + 0.28x²)`（夹角 < 0.4 rad，误差 < 0.005 rad）：每格一个完整 atan 在 bands 上 +0.35 ms。
   - 进单体循环的判断从 `cb > 0.45` 改成按相位梯度折算的「离带轴相位差 < 1 + |∇φ|·够得着的距离」（7 km 以下 10 km、以上 13 km）。原判断在内圈会截掉离带轴远一点的塔和砧。
5. **雷暴（storm-day）**
   - 乳状云 `pouchField`：每格一个口袋，位置可以贴到格边、半径 0.3–0.75 格各不相同、1/4 空格，两级格子（1.4 km / 0.6 km），再乘一个约 11 km 的成簇遮罩（水平切片噪声），深浅随口袋大小。
   - 砧顶两级鼓包、幅度加大（中心 ±1 km、外缘 0.35 倍）；下风外缘厚度 1.3 → 0.85 km；外缘撕碎的噪声权重加大。

## 坑（建议写进 README）

1. **从眼里看，顶沿后面任何一层「高度处处相同」的云顶都会露成一根水平的管子**：卷云盖顶、顶沿外侧被抬到统一高度的云体都算。卷云盖在眼壁附近要压在顶沿以下、随顶沿起伏。识别：T37-exp 关卷云盖（`if (canopy > d)` → `if (false)`）看管子是否消失。
2. **内壁半径随高度起伏（3D 噪声隆起）时，往顶沿高度场里加「往上」的细尖峰会飘出碎云**：某一列只在几个高度段落在内壁外，尖峰高过连续部分就成了悬空的小块。细级起伏只往下刻（`hurCap − 最大值`）。
3. 雨带单体窗口只能完整罩住离塔心约 13 km 以内的东西：新加的塔 / 砧部件超出这个范围会被截出直边；要伸得更远就把窗口顺那个方向挪。
4. **大片稀薄云（卷云盖）的边界别随便加噪声软化**：相机就在它边上时（typhoon-outer），相机附近多出一大片 0.1 量级的稀薄云，步进要细走，开销比预期大得多（+0.7 ms）。识别：按 pass 计时 + 页面内逐项替换着色器。

## 还不够好 / 下一轮

1. 眼壁顶沿右侧有一段平顶的「台阶」带竖直侧面（T26 的 l1 / l2 平台在顶沿附近露出来），比栏杆轻，但仍有直线感。
2. typhoon-outer 顶上卷云盖底面的外缘是一条斜的直线（解析的 `canopyBase`，没有起伏）；打散它要找不增加相机附近稀薄云的做法（例如只改平面外缘、不改底面高度）。
3. 雨带塔受光面顶部有一块偏平、偏亮的顶（typhoon-bands 中间那座），可能是受光步进只算一座塔、不算砧的遮挡；outer 里远处的塔仍略像「高脚杯」。
4. 雨带砧下没有加乳状云（开销考虑）；storm-day 的砧顶从侧下方看起伏不明显（视角问题），要从高处看才评得出。
5. 眼壁正面的「石膏裂纹」质感、逆光顶沿的银边（美术总监同一条里提到的）不在本任务。

## 开发体验反馈

- `tmp/perf-cloud/passes.mjs` 的 `--variants` 很好用：配上 `T37-mkvar.mjs`，在 d3d11 上按 pass 逐项归因，一轮 5 个变体约 3 分钟。建议把 passes.mjs 和这个转换收进 `scripts/`。
- GPU 被别的代理占着时 `benchFrame` 整帧时间完全不可信（同一代码 7.6 → 12.4 ms）；GPU timer 按 pass 的数字很稳（两轮差 < 1%）。性能归因一律用后者。
- 分配端口时最好连对照端口一起分配（5238 被别人占着）。
