### 画法（`far-towers.ts` 文件头有全文）

- **选塔**：170–760 km、相机水平朝向 ±80°、按距离最近 32 座；位置按天气场漂移逐帧外推（连续，飞行中视差来自真实的本地坐标）；淡入淡出：出生 / 消散按强度（0.25→0.4）、距离两端各 40–60 km、程序编好 / 从无到有时整体 6 s 淡入。**摆放成体积雷暴的系统当帧从远景层撤掉，之后也不再回来**（体积摆放只发生在视野外或借遮挡，不会当面换）。
- **形态随生命周期**（天气场 `age01`）：生长期是没有砧的大圆头浓积云塔（塔顶从 55% 长到砧顶）；约 0.1–0.32 砧铺开；成熟时砧半径 = 塔身 2–4.6 倍、偏下风（系统漂移方向 ±25°）；0.6 以后塔身塌掉、砧继续摊开 → 最后只剩孤砧。塔身半径按 1.3 倍主塔（远处看到的是主塔 + 伴生塔整团）。
- **塔身**：竖直「圆柱」剖面（下窄上宽、有砧时上段张开并进砧底），轮廓与明暗由两级气泡场（2.4 km / 0.9 km 的随机圆鼓包，球冠法线受光）做出花椰菜；上冲穹顶只冒出砧顶 0.7 km；云底 1.3–1.8 km 参差渐隐，下面一层淡雨幡；砧底下那段在高太阳时受砧影。
- **砧**：水平圆盘（中心偏下风 0.45Ra），视线穿过的路程 = 水平弦长 × 这段视线高度落在砧的高度范围里的比例（解析，带 1 像素软边）；楔形（靠塔厚、下风薄）、砧顶几乎平直（对流层顶）、砧底参差、外缘纤维化；砧在塔前（塔顶藏进砧里）。
- **光照**：太阳按塔所在处的当地天顶（`keyLight` 带地影与变红）→ 黄昏时砧 / 塔顶被染成橙粉、下半截已进地影；背光的厚云面保底三成多次散射；逆光轮廓前向散射亮边；天空漫射。
- **空气透视**：≤ 400 km 查与体积云同一张 LUT；更远的一段透射率 = LUT@400 × 透射率 LUT 比值，内散射按源函数不变外推。
- **合成**：GL 混合叠进云步进的 raw（`DST_ALPHA, ONE` / `ZERO, SRC_ALPHA`；需要 `EXT_float_blend`，没有就关），不读 raw、不加任何程序的 sampler；scissor = 每座塔包围盒投影的并集（屏幕外的塔不计）。

### 对照真实照片（描述）

真实的「巡航高度看地平线上的积雨云」照片（NOAA / 航拍常见构图）：远处一排白塔立在地平线的霾带上，塔脚看不见；上面是平直的砧顶，砧向下风拉长、边缘变薄；越远越偏蓝灰、对比越低；日落时只有砧和塔顶是粉橙色，下半截已经暗了；消散的塔只剩一片孤砧。本实现对得上的：地平线 / 霾吃掉塔脚、平直砧顶与下风楔形、远处偏蓝灰、黄昏只染顶部、孤砧、生长期无砧的圆头塔、飑线砧连成一片。**还不像的**（留给后续，属细微打磨）：①砧的外缘在某些角度仍像圆润的「饼」（真实砧边更薄更锐、纤维更长）；②塔身气泡鼓包大小比较均匀，近看（≈ 200 km）略像泡沫，缺真实花椰菜那种「大团上长小团」的层级与竖向折痕；③逆光时 300 km 外的塔身几乎融进天空（物理上空气透视就这么强，但照片里常还能看出灰色轮廓）；④雨幡很淡，几乎看不见。

## 已知问题 / 给协调者

- **归属外改动**：`scripts/lint-shaders.mjs` 加了一段登记新程序（否则 check:glsl 不校验它）；`clouds.ts` 加了 `afterMarch` 钩子（不碰步进着色器）。
- **合成前提**：远塔永远在体积云后面（见 README 坑一）。TW04 若让体积雷暴画到 400 km 外、或 TW06 让远景层画 170 km 以内，要改成按 raw 深度前后合成。
- **近 170 km 的名额外单体**：既不画体积（名额满）也不画远景（在 170 km 内淡出）。窗内出现这种情况时会看到一座远塔在 170–210 km 慢慢淡掉；实际很少（名额满 + 正在窗前）。
- **构图带没动**（TW01 遗留的 40–90 km 挤一带）：远景层补上了 170 km 以外的层次，但近处体积雷暴仍挤在同一距离带。
- **闪电**：远塔不打闪（夜里地平线上的远雷暴闪光会很好看，可另开小项：远景层按天气场单体泊松闪光，改 uniform 即可，零编译成本）。
- 调试句柄：`__voyage.farTowers`（`towers` / `active` / `scissor` / `override` / `bench(n)` / `enabled`），URL `?fartowers=0` 关。

## 开发体验反馈

- **哪里慢**：等测量锁约 3 分钟（别的代理的 ab / gpu-ab）；每次 `shots` 连续航程场景要等雷暴变体编译 + onJump 两次约 30 s。
- **哪里卡**：
  1. `ab` / `gpu-ab` 变体的 `js` 副作用不复原，ABBA 交替时「关」一直生效，第一次 gpu-ab 量出「开关一样快」的假结论（已写进 README 工具坑点）。希望工具在变体里支持 `restore` js，或对 `js` 里改过的 `__voyage.*` 布尔 / 数值自动快照复原。
  2. 连续航程 scs 预设的首段航线是 HKG→HKG 的圈，自动驾驶一直 25° 坡度，窗外只有海；要手动 `setHeading` 保持航向才能验收。
  3. 冻结时 `farTowers.active` 这类「这一帧画了没有」的调试量不更新（云不渲染），在 gpu-ab 的变体断言里误导了一次。
  4. worktree 沙箱拒绝「含变量的 Bash 命令跑 python」「heredoc + &&」，只能先 Write 成脚本再用 PowerShell 跑。
- **希望有**：`shots` 场景字段 `faceBearing`（把航向转到让窗外正对某方位 / 某类对象），以及 `ab` 输出的同裁剪区多变体拼图（本次写了 `TW02-montage.py`）。
