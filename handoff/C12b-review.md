## 结论：返工（小）——只需改一处：reset 之后的收敛

算法本身正确，稳态收益可以复现、也站得住：静止噪声约减半，巡航更锐、对真值的误差更低，云里逐位不变。**唯一要改的是 reset 帧之后**：每次 `snap()`（换预设、天气、云底 / 云厚滑条、`setSize`，也就是画质档自动升降）以后，blend 0.04 让第一帧的 1 spp 噪声留得比 master 久得多：第 16 帧的误差是 master 的 ×2.4–3.1，要到约 48 帧才追上 master 的稳态。60 fps 下多出约 0.5 s 明显的颗粒，低档 30 fps 下约 1 s。这违反「闪烁 / 噪声最高优先」。修法已离线验证：一个 uniform 加一行代码，reset 后的收敛反而**比 master 更快**，稳态不变（见问题 1）。改完不必重新跑整轮审查，协调者复核问题 1 的曲线即可合并。

## 问题（按严重度）

### 1. 【必改】reset 后收敛变慢约 3 倍

- **证据**（`c12brev/reset2/reset.json`）：静止姿态，`snap()` 后第 k 帧读 HDR 裁剪区，对 256 帧等权真值算相对 rms 误差。取 3 个不同的 uFrame 起点求平均：

| 场景 | 变体 | k=4 | k=8 | k=16 | k=24 | k=32 | k=64（稳态） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| backlit-cu | master | 0.228 | 0.131 | 0.067 | 0.057 | 0.057 | 0.055 |
| | C12b | 0.287 | 0.230 | **0.159** | 0.111 | 0.084 | 0.030 |
| | 修后 | 0.130 | 0.082 | 0.053 | 0.033 | 0.025 | 0.022 |
| storm-day | master | 0.392 | 0.200 | 0.090 | 0.075 | 0.075 | 0.070 |
| | C12b | 0.503 | 0.403 | **0.289** | 0.209 | 0.155 | 0.064 |
| | 修后 | 0.186 | 0.078 | 0.059 | 0.054 | 0.056 | 0.053 |
| sunset-wing | master | 0.954 | 0.511 | 0.278 | 0.249 | 0.243 | 0.236 |
| | C12b | 1.225 | 0.969 | **0.697** | 0.516 | 0.404 | 0.240 |
| | 修后 | 0.497 | 0.268 | 0.233 | 0.226 | 0.226 | 0.226 |

  clouds-variety 的规律相同（第 16 帧：master 0.045 / C12b 0.106 / 修后 0.035）。
- **根因**：reset 帧只输出 `cur`（1 spp）。之后按 EMA 0.04 累积，第 0 帧的权重要 0.96ⁿ 才衰减掉（n=16 时还剩 0.52），master 是 0.88ⁿ（n=16 时剩 0.13）。
- **修法**（已验证，就是上表的「修后」）：CloudRenderer 里加一个自 reset 起的帧计数，resolve 在云外左半用累积平均兜底：
  ```glsl
  uniform float uSinceReset;   // reset 帧 = 0，之后每帧 +1
  ...
  if (c12b) blend = max(blend, 1.0 / (uSinceReset + 1.0));
  gl_FragColor = mix(hist, cur, blend);
  ```
  TS 侧：`render()` 里如果 `this.reset` 就把计数置 0，否则 +1（上限 1e4 即可），写进 `r.uSinceReset.value`。前 25 帧等价于等权平均（这正是真值的定义），之后自然交还给自适应 blend。这是零取样开销的一次 max。右半和云里保持原样，逐位不变。改完后用 `c12brev-reset.mjs` 的口径复测一次即可；脚本在审查者的 scratchpad，逻辑就是上面描述的，也可以照 `C12b-ab.mjs` 的 PAGE_LIB 改几行自己写。

### 2. 【观察，不阻塞】混合深度处的 3×3 平均深度

近云压在远云上的边缘，3×3 里两种深度各占一部分，平均深度对两者都不对。侧窗平移视差下，近云（约 2 km）和远云（约 20 km）混在一起时，每帧重投影误差可达约 1 px。master 用本像素深度，这里是对的，只是有噪声。实测没有变坏：backlit-close（1 km 高度的近云）巡航误差 ×0.89，clouds-variety 误差图上 master 左下云边的亮拖边反而在 C12b 里消失了（`c12b/final/z-motion-clouds-variety.png`）。邻域夹取也兜住了。以后如果在近云 / 远云交叠处看到云边拖影，先查这一条：可改成「3×3 里不透明度最高那一格的深度」或按深度分两簇。

### 3. 【观察，不阻塞】blend 依赖 fract(每帧位移) 可能形成空间带

每帧位移随深度 / 视角平滑变化，fract 接近 0 与接近 0.5 的区域 blend 分别是 0.04 和 0.12。理论上会沿「等位移线」出现噪声强弱的缓变带（噪声 σ 之比约 0.58）。master 的双线性也有同构的「模糊强弱带」，C12b 只是把它换成了噪声带。巡航 / 转弯的截图和误差图里没看到带状结构，但这一点没有专门测。美术总监看巡航实拍时留意一下；真看得出来，可以把 mix 的下限从 0.04 提到约 0.06 来收窄对比。

### 4. 【信息】转弯噪声 ×1.15

与实现者的说法一致：转弯误差图里 final 的误差是均匀颗粒，没有沿边的拖影（`z-turn-backlit-cu.png`），在 ×1.2 门槛内。

## 各审查要点的核实

1. **Catmull-Rom 超调 / 负值**：历史先 `clamp(…, mn, mx)` 夹到本帧 3×3 的最小 / 最大值，负瓣造成的暗圈、太阳附近和逆光银边的过冲、负值都被夹掉。RGB 和透射率 a 也各自被夹在 [mn, mx] 里（a ∈ [0,1]）。12 次取样的归一分母推导为 `1 − a_x·a_y`（a = ½f(1−f) ≤ 1/8），恒 ≥ 63/64，不会除零；f=0 时退化为单纹素，静止时逐位取历史。**双宽缓冲**：`c12bFetch` 把整数坐标夹在 `[0, uCloudResolution − 1]`，而 `setSize` 保证缓冲宽正好是 `2w`（w、h 取整），所以左半最右列只会重复自身，读不到右半的深度数据。`puv` 越界（blend=1）时 CR 取的是被夹住的有限值，`mix(hist, cur, 1)` 精确等于 cur。**画质档 0.75 / 0.5**（`c12brev/quality/`，backlit-cu、sunset-wing 各两档）：静止 relStd ×0.51（最差 ×0.69），巡航误差 ×0.89（最差 ×1.01），转弯误差峰值最差 ×1.13，巡航 σ 0.97/0.43 → 0.62/0.21，HDR ×1.001。与高档一致，坐标没有问题。
2. **3×3 加权深度**：`osum > 1e-3` 否则回退 `dCur`，无除零；全晴空时回退深度 400 km，只剩背景，无影响。晴空一侧的像素被赋予云的深度，等于 TAA 的深度膨胀，对云边的重投影是正确方向（这正是巡航误差降低的来源）。**wImm 0 ↔ >0 的切换**：wImm 是 uniform，同一帧整窗一起切换。切换那一帧只把「CR 取历史 + 0.04」换成「双线性 + 0.12」，历史还是同一张缓冲，差异只有一帧的亚像素滤波核，不会跳变。出云方向实现者已测（×0.91）。
3. **blend 公式**：`fract(hp − 0.5)` 与 CR 内部的 `q = p − 0.5` 在同一个纹素网格上（纹素中心在 .5），半纹素偏移正确。静止时 f≈0（或 ≈1，经 floor 取到下一格同样是单纹素）→ 0.04。reset 帧路径的问题见问题 1。镜头突变：换预设、天气、画质都走 snap；快速巡航 5× 实现者已测（×0.915）；转弯已测。
4. **冷编译**：离线 FXC `shader-budget --baseline 主仓库 --rounds 5 --only cloud-resolve`：**64 → 103 ms（+61%，约 +40 ms）**，与实现者的 67→106 一致。`dev-browser cold --port 5228 --baseline 5181 --repeat 2`（d3d11）中，云批次三个程序编好的时刻为 829/848/1013 ms，基线为 848/848/994 ms，**没有后移**。关键路径是窗外，编好时刻 min 6812 对 6930 ms（中位数 8390 对 6949，负载噪声，按 min 判）。resolve 在约 1 s 就编好，窗外要约 7 s，40 ms 的余量完全在关键路径之外。按 SOP「关键路径程序」口径，增量约 0，**不必降到 9 次取样**。性能工程师记账时请把这一项标成「非关键路径」。注：测 cold 时测量锁存在，脚本按规矩等锁后才测。
5. **斜纹指数 ×1.70**：核实是结构，不是 CR 引入的各向异性。①静止测试里 f=0，CR 精确退化为单纹素取样，**静止斜纹的变化与 CR 无关**，只来自 blend 降低。②用同一个指标算「16 帧平均显示图」（≈真实结构）：master 与 final 几乎相同，最大自相关都在 (0,1) 水平方向：backlit-cu 0.606 / 0.599，clouds-variety 0.340 / 0.377，storm-day 0.544 / 0.532；final 的单帧值（0.478 / 0.287 / 0.516）正在向这个结构值靠近。噪声越低，高通残差越由真实的横向层理主导，指数跟着升高。放大对照 `z-static-*.png` 里右图是更干净的同一组层理，没有新的斜向纹路（脚本 `c12brev-streak.py`）。
6. **冲突**：`git merge-tree` 对 T48c（a2abd，含最新 a589b44）和 W-STAIR（abbe8）均无冲突。C10（a3b5f）还没有提交，工作区只有未跟踪的 `handoff/C10-ab.mjs`，src 没动，目前无冲突风险。C10 以后改 clouds.ts 的步进 / 密度时与 RESOLVE_FRAG 不重叠，但同文件，合并时注意 README 云坑点一节的相邻行。

## 开发体验反馈

- `C12b-ab.mjs` 的确定性航迹加真值框架很好用。直接复用它测了画质档，只写了 scenes / jobs 两个 json。建议收进 `scripts/`，作为时间累积类改动的标准 A/B 工具，并加一个 `reset` 模式（snap 后按帧记误差曲线）。**时间累积类任务的验收清单应加上「reset 后收敛」一项**，本次的问题只有这个模式能抓到，静止 / 巡航 / 转弯三个模式都看不出。
- `C12b-metrics.py` 只认 `f*.png`，会误把 `full.png` 当成帧（我的复核脚本踩到了）。它自己用 `startswith("f")` 过滤，恰好靠排序躲过，建议改成 `f\d\d.png`。
- `dev-browser cold` 的输出没标明哪一行是关键路径、增量按什么口径算，还得人工去比「窗外」那一行。建议汇总末尾直接打印「关键路径（最晚编好的程序）Δmin」。
- 测量锁是目录（`tmp/measure.lock/owner.txt`），自写脚本用 `existsSync` 能查到，但文档里没写清楚是目录。
