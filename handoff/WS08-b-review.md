## 合并冲突解法（ring.glsl.ts 缆塔那段，唯一冲突）

NIGHT-AP-1 把缆塔的空气透视查表改成 `uApDir` / `uApIlluminance`，本分支在同一段把 `Lpil` 拆成 `Lsky / Lpil / LpilR`。取本分支的写法，查表两行换成 master 的 uniform：

```glsl
    Lsky += vec3(1.0, 0.8, 0.55) * 2e-3 * ringBandsAA(altP, pixA * tP * inversesqrt(max(1.0 - dot(rd, aP) * dot(rd, aP), 1e-6)), 25.0, 0.5);
    vec3 Lpil = 0.3 / M_PI * uSunIlluminance * tS * perp * ph + Lsky;
    vec3 LpilR = 0.3 / M_PI * uSunIlluminance * tSR * perp * ph + Lsky; // 封顶比例按半影的参考透射率定（同环体）
    vec3 uvw = aerialPerspectiveUvw(rd, uApDir, min(tP, AERIAL_MAX_DISTANCE));
    vec3 apL = texture(uAerialInscatterS, uvw).rgb * uApIlluminance;
```

`pillars.glsl.ts`、`README.md` 自动合并正确（巨柱群的查表已是 `uApDir` / `uApIlluminance`，本分支改的光照 / 封顶行不受影响）。天环 / 巨柱群里其余的 `uSunDir` 都是光照方向（地影、朝向、`dayF`），不是空气透视查表，不该改；`check:glsl` 新加的「所有程序都按 uApDir / uApIlluminance 查空气透视 LUT」断言通过，解错（保留 `uSunDir`）会被它拦下。
另：交接里「NIGHT-AP-1 合并时预计无冲突」不成立——两边改的是同一段缆塔代码。

## 2. 半影

- **物理**：`penumbra.glsl.ts` 的推导对——日面弓形面积 `acos(−x) + x√(1−x²)`、弓形形心 `(2/3)(1−x²)^{3/2}/A`（x → −1 时极限为 1，与 `A ≤ 1e−5` 分支的 1.0 连续）、折射压扁的近地点高度差 `2θ / (1/D + 0.02/7.5·e^{−h/7.5})`（天环 D ≈ 3000 km 时约 3 km）、近地点 0–8 km 的云 / 霾渐隐。大气层内的点在 x = 1 时 `GrazeT` 退回 `transmittanceToTop(r, μ)`，受光段与原来一致。封顶按参考透射率定、「有太阳 / 无太阳」两份按 vis 混的思路正确，确实是硬线根因。
- **NaN 保护**：`rp` 的 sqrt 有 max；`A` 有 max；`uc` 有 `A > 1e−5` 保护；`1/max(D,1)`、`hc / (0.5·dh)`（dh 恒 > 0）安全；`GrazeT` 的 sqrt 有 max；天环封顶 `capD` 有下限、`pow(x, −0.82)` 只在 x > 1 时算；灯团 `pb / max(p, 1e−6)`。`sx = sqrt(1 − x·x)` 没包 max，但 x 已 clamp 到 [−1, 1]，x·x 不会超过 1，实测无问题（见遗留 4）。
- **整帧刷白**：`framemean.py` 逐帧平均亮度（裁剪区）：黄昏天环 on 46.79–47.11、on2 46.54–46.66、转向 46.76–47.58 / 43.71–46.22（环在画面里平移），相邻帧均值跳变最大 0.03；巨柱群 114.7–115.4，最大跳变 0.009；无月夜 34.1–35.3。**240 帧 × 5 个变体没有一帧刷白。**
- **画面**：`cmp-dusk-edge-x4.png` + 第 820 列逐像素：master 交界 184 → 182 → 179 → 144 → 40（一像素切），合并树 182 → 156 → 111 → 65 → 49 → 39（约 4 像素过渡，位置上移约 2 像素），交界前的红带与 master 逐像素几乎一致。`cmp-pillars.png`：巨柱群一像素横切线消失，柱顶粉色往下渐暗没入地影蓝灰，没有比地影更暗的带，柱顶受光段与 master 相同。天环 1000 km 外半影只有 3–5 像素，物理上本来如此，不是缺陷。

## 非阻塞遗留（按严重度）

1. **大气层内的点在「μ = 0」处有一道半影跳变（巨柱群柱脚、天环缆塔下段，中低）**：`penumbra.glsl.ts:46` 的提前返回（`mu >= 0.0`）不乘云 / 霾渐隐，而 μ 稍小于 0 时 `q` 立刻乘上 `smoothstep(0, 8, he)`（he ≈ 这个点自己的高度）。所以 8 km 以下的柱身在「太阳恰好落到本地水平线」那一刻亮度一步跳到约 1/3（3 km 处 ×0.32），而且 μ 沿柱宽方向有微小差别，这条分界会在几秒内扫过柱身成一道竖向的缝。只在本地日落 / 日出那几秒出现，柱脚大多埋在云和霾里，本次场景（太阳早已在柱位下方）看不到，所以不阻塞。修法方向：让渐隐在 μ 跨 0 时连续，例如提前返回分支里对大气层内的点也乘 `mix(smoothstep(0.0, 8.0, r − BOTTOM), 1.0, smoothstep(0.0, 0.05, mu))`，vis 取它的平方根（掠射光贴地走得远才被云挡，太阳高了就不挡）。
2. **灯团格子大过环宽时，灯团会落到腹面外、能量丢失（低）**：`ring.glsl.ts:137` 灯心 `lc` 在正方形格子里取，格边 C = 8·2^lv km；环半宽 W2 = 60–110 km，lv ≥ 4（C ≥ 128 km）时大半灯团落在 |v| > W2 处，腹面像素收不到，按 W2 = 80 算 lv 4 / 5 / 6 分别只剩约 68% / 23% / 更少。要到足迹 > 43 km（极掠射、贴地平线的环端）才出现，本次两个夜景框量不到变暗（最远框 ×1.17–1.27），所以只记遗留。修法：横向格边取 `min(C, 2·W2)`，或把 `lc.y` 夹进 [−W2, W2]（能量不变，只是位置挤在环宽内）。
3. **高级灯团的枢纽 / 桁架是在格子中心点采样（低）**：`ringLampP` 的 `hubP`、`truss` 在 lv ≥ 1 时没有按格过滤（城区疏密过滤了），64 km 以上的格子中心落在枢纽里就整格按 0.35、落在桁架段里就整格为 0。期望对位置平均仍守恒，远处读不出来；另外 `ring.glsl.ts:346` 的枢纽底光没有乘 `(1 − truss)`。都不影响观感，记录备查。
4. **防御性写法（低）**：`penumbra.glsl.ts:53` 的 `sqrt(1.0 − x * x)` 建议包 `max(0.0, …)`（x 已 clamp，理论上安全；但同文件已经栽过「理论上非负、FXC 给出 −1e−8」的坑）；`ring.glsl.ts:143` 的 `e / p`（master 原有）在 p = 0 时是 0/0，只靠三目的 select 挡住，可顺手改成 `e / max(p, 1e−6)`。
5. **天环交界的半影只有 3–5 像素（观感，低）**：物理上对（1000 km 外近地点每像素约 5 km），比原来的一像素硬线软，但远看仍是一条「较软的线」而不是一段渐变。WS08 审查说的「越靠近交界越红越暗」原来就有（红带与 master 一致）。若美术上还想更软，只能靠非物理的加宽，不建议。
6. 巨柱群交界色调偏「粉 → 暗紫 → 蓝灰」、月光地影仍用太阳视半径——实现者已记，同意。
7. `OWT` 离线 FXC +8%：见上；若同一波还有别的任务往天环程序加东西，要一起记账。
