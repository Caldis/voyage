## 改了什么

### C01 · 多次散射（`clouds.ts` 云步进受光段，所有变体共用的公共主体，没有新 uniform、没有新分支）

| 项 | 改前 | 改后 | 出处 |
| --- | --- | --- | --- |
| 阶数 | 6 | 3（单次 + 2 个高阶） | UE Volumetric Cloud「Multi Scattering Approximation Octaves」最多加到 2 |
| 衰减 a / b / c | 0.62 / 0.35 / 0.5（a > b，**不守恒**） | 0.5 / 0.5 / 0.5（雷暴 / 台风 0.6 / 0.6 / 0.5，只在 `#ifdef CLOUD_WEATHER` 里） | Wrenninge 2013 要求 a ≤ b；Hillaire 2016（Frostbite）沿用，UE 默认 0.5 |
| 能量标定 | 无（靠多加阶补） | 高阶（k ≥ 1）× `CLOUD_MS_ALBEDO = 6`，与光学厚度无关的常数 | 按「厚云有效反照率 0.7–0.8」标定（见下） |
| 粉末效应 | 乘在整个太阳项上（顺光时把受光的云边也压暗） | 只乘高阶散射（「刚进云的薄层里多次散射还没攒起来」），单次散射不压；逆光淡出不变（T12） | Schneider 2015 的物理解释 |
| 前向衍射峰（T12） | 0.6·hg(0.9)·e^(−0.25 od) | 不变 | Joseph 1976 |

**能量标定怎么来的**（`handoff/C01-albedo.py`）：页面内把每个样本的 S 换成「同照度的朗伯白面」E/π（E = 太阳直射在水平面上的照度 + 天空照度），关掉空气透视，逐像素 R = πL/E。noon-cumulus（10.7 km 俯看、太阳 58°，E ≈ 96 klux）的不透明云：

| | 改前（6 阶） | 3 阶不标定 | ×3 | ×4 | **×6（定稿）** |
| --- | ---: | ---: | ---: | ---: | ---: |
| R 中位数 | 0.30 | 0.14 | 0.30 | 0.38 | **0.53** |
| R p90（受光云顶） | 0.35 | 0.21 | 0.43 | 0.53 | **0.75** |

改前的 6 阶其实也只有 0.35（T12 以为补回了能量，其实是把背光面灌满了），3 阶不标定只剩 0.21；×6 让受光云顶到 0.75（厚云 0.7–0.8）。

### C02 · 白天窗外曝光（`exposure.ts` 的 `EXPOSURE_MODEL`）

两个方案比较后选了 **物理 EV 锚定 + 有限自适应**：
- 方案 A「扩展 `uSnowEv` 判据覆盖有空隙的云海」：要在测光里另测「高亮像素比例」（测光 pass 是单线程串行采样链，T28 的教训），而且判据是个开关，云飘进飘出时会有边界；clouds-variety 的 h − o 在 0.16–0.43 之间，和 fuji-day（0.12–0.13）、storm-day（0.47–0.86）混在一起，找不到干净的阈值。
- 方案 B（采用）：`eO = max(eO, log2(1000/1.2) − EV100)`，EV100 = 15（sunny-16），乘白天程度 `day`。含义是「再亮的窗外，眼睛（相机）也不会继续往下压到中灰」。比锚点暗的视野（海、陆地、天空为主、黄昏、夜里）照旧自动曝光，一个比特不变；不改测光、零帧时间。新 uniform `uDayEvAnchor = (15, 1)`，`y = 0` 就是改前（同页 A/B 用它）。
- 锚点放在舱内约束（③ ④）**之前**：锚定之后眼睛就适应在这个水平上。第一版放在之后，满窗云海时舱壁被 ④「舱内最多比窗外多提亮 4.5 档」一起压暗（clouds-variety 139 → 123）；挪到之前后 139 → 148（更接近 T23 的 150–185）。
- EV 取值：14.0 / 14.5 / 15.0 都试过（`tmp/screenshot/c01/r5`）。14.5 时 clouds-variety 最亮 1% 云 215、但 AgX 肩部把云芯明暗压回 ×1.3；15 时 203、明暗 ×1.47，取 15（也正好是 sunny-16）。

**顺手修的回归**：C01 以后云里的雾不再被高阶散射抹匀，机翼比雾亮，in-cloud 的 h − o 从 0.016 升到 0.097，⑤ 雪景补偿的统计判据（0.05–0.12）掉到边缘，窗外 188 → 141 一片灰。加宽阈值会碰到 fuji-day（0.129），所以改为直接判「飞机在云里」：`clouds.ts` 的 `keyVisibility` 里按密度探针的 `immersed` 做 0.5 s 平滑，写进模块级 uniform `EXPOSURE_WHITEOUT`（`exposure.ts` 导出，同 `EXPOSURE_STATE` 的做法，不用改 main.ts），⑤ 取 `max(统计判据, uWhiteout)`。in-cloud 恢复到 186。

## 已推翻 / 踩到的坑

- **「C01 会让云整体变暗 7–20%」只对了一半**（研究报告 §3）：HDR 里确实变暗，但满窗云时自动曝光把它补回去了，显示上 cu-side 反而变亮（ymean 140 → 153）。「整体亮度」要看 HDR 辐亮度（`C01-albedo.py` / 读云缓冲），不能看截图。
- **改前的 6 阶并没有把厚云反照率补到 0.7–0.8**（T12 的说法）：实测 πL/E 只有 0.30–0.35，它补的是背光面。
- 页面内补丁里写 `${s} * (…)`，s = 1 时拼出 `1 * (…)`：GLSL ES 里 int × float 编译失败，three 照画上一份缓冲 / 半成品，截图是一片斜纹点阵，差点当成「粉末让累积失效」。补丁里的数一律 `toFixed`；测量脚本现在编译后检查 `diagnostics.runnable`。
- 锚点放在舱内约束之后时舱壁一起变暗（见上）。
- in-cloud 的雪景补偿统计判据被 C01 带到边缘（见上）。

## 还不够好

1. **显示上的云芯对比被 AgX 肩部压掉约三成**（HDR ×1.7 → 显示 ×1.4）。要同时「亮」和「对比」，需要色调映射在高光段更陡（AgX punchy / 提高中间调对比，研究报告 §1.7 交给美术总监）。本任务没动色调映射。
2. **逆光银边（backlit rim）没有明显变亮**：1.15 → 1.15（HDR 里 1.16）。前向峰和云芯同比例被曝光抬高后又被肩部压。要让银边「比云芯亮得明显」可能要在 AgX 之前单独保高光，或加大 T12 的前向衍射峰——都超出本任务范围，建议另开任务。
3. typhoon-bands 背光塔身更暗更蓝：物理上是对的（高阶不再灌满），但 T38 / T44 调过的「圆桶 / 拱洞」观感需要美术总监复看；要压回去的话调台风的环境光下限（`#ifdef CLOUD_TYPHOON` 里），不要动公共主体。
4. noon-cumulus 的云只到 190（锚定不起作用，是海面为主的窗按原样自动曝光的结果）。要再亮就得让锚点也作用于混合视野，会带着海面一起亮，没做。
5. clouds-variety 远处云带上的水平横纹（掠射大步长）在对比升高后更容易看出来——那是 C03 的范围。
