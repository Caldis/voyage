## 做了什么

| 项 | 做法 | 文件 |
| --- | --- | --- |
| 1 mip 按层生成 | Worker 在 `packRoads` 之后给这一层算 mip 链（`mips.ts`：影像在线性空间 2×2 平均、再编码回 sRGB，逐级从浮点结果往下算；水体 8 位逐级平均）；主线程按层按级上传，不再调整组 `generateMipmap`。A 通道：影像 mip 写「有影像比例」的合法编码（比例 1 → 128，否则 `比例×127.5` ≤ 127），`min(A·2,1)` 在 mip 上恰好是覆盖比例；水体 mip 的 A = 255（无路）。着色器读 A 编码的地方仍全部 `textureLod(…,0)` | `src/ground/mips.ts`（新）、`road-raster.ts`、`road-raster.worker.ts`、`clipmap.ts` |
| 1b（顺带修的旧闪烁） | PERF-8 起一批三张纹理分三帧传、最后才换中心：中间 1–2 帧是「新影像 + 旧中心」，整级错位 1/8 边长（master 实测每次重建 2 帧尖峰）。改成暂存上传：每帧 ≤ 4 MB 写进 PIXEL_UNPACK_BUFFER，写完后同一帧里拷进影像 / 水体（含 mip）、传高度、换中心 | `clipmap.ts`（`drainStaged`） |
| 2 首载先粗后细 | `warm` 标志：reset 后各级先按 1024 缩放级建，全部 valid 后放开 fine，后台逐级升级；**夜里（太阳 < +6°）不走这条**，直接按细级建（理由见下）；`imageryStats.warmup` 记粗版 / 细版就位时刻 | `clipmap.ts` |
| 3 按 GPU 启动定档 | `quality.ts` 的 `GROUND_RES_DECISION` 在模块加载时定一次：node 离线 → 2048；`?groundres=` → 指定；上次手动档「高」→ 2048、「中 / 低」→ 1024；否则临时 WebGL2 上下文读渲染器字符串 + MAX_TEXTURE_SIZE + deviceMemory：高性能独显（RTX / GTX 16、1060–1080 / Quadro RTX、RTX A / Radeon RX、Pro / Arc A、B / Apple M Pro、Max、Ultra，排除 GT、MX、GTX ≤1050、Quadro K/P/M、Vega APU）→ 2048，其他 → 1024（仍带 mip + 16× 各向异性）。`clipmap.ts` 的 `GROUND_RES` 取自它，着色器常量随之冻结——运行时自动档怎么升降都不动它，不重编。面板手动改档写 localStorage `voyage.quality`，状态行提示「地面 2048²，下次载入改为 1024²」；载入时恢复手动档（面板与地面一致） | `src/quality.ts`、`clipmap.ts` |

**热点文件 `main.ts` 只改一行**：`ground.attachGl(renderer)`（原来传 `renderer.getContext()`；现在要 renderer 以便 `initTexture` 立即分配纹理对象）。没碰着色器、clouds、exposure、scene / cabin / wing。

「着色器常量改 uniform 或变体」按「启动时定的常量」实现：值在 `ground.glsl.ts` 模块求值前就定了、之后不变，所以运行时不会重编；2048 档的着色器文本与 G06 逐字相同（`shader-parity` 39 个程序全部相同），离线 FXC 自然不回退，也不用动 `ground.glsl.ts` / `terrain-shading` / `far-view`（不在归属内）。代价：同一台机器换档后第一次载入是冷编译（着色器文本里常量不同）。

## 还没做 / 已知问题

- **1× 帧间隔的权威复测**请在安静窗口做（`node handoff/G07-spikes.mjs <端口> 60 3 1`，看 `over16Near`），以及有集显的机器上的整组 vs 按层对比（本机测不出）。
- **夜里先粗后细关着**：夜里首载仍是 G06 的时长（EOX 顺畅时约 14 s，限流时 30–40 s）。要让夜里也能先粗后细，得让灯点 / 路灯的建成区判据不随影像缩放级变（例如判据用固定缩放级的影像，或存进单独通道），不在本任务归属内。同一问题在加速航程 > 2× 降回 1× 后的重建里也有（G06 起就有）。
- 暂存缓冲只有一个，队首一批写完才轮到下一批（每批 2048 档约 11 帧）；60× 实测队列最长 1，够用。
- 上下文丢失：`pbo` / `glTex` 是旧上下文的句柄，恢复后不可用（项目本来就不处理上下文恢复）。

## 复现

```bash
# apps/voyage 下
node handoff/G07-load.mjs <端口> <输出目录> fuji-day|route-hnd-cts|night-city|route-hnd-cts-night [&groundres=1024]   # 首载时间线 + 相邻差
node handoff/G07-pair.mjs <端口> <输出目录> all          # 同页 A/B（G07_SELF=1 噪声底）；再 node handoff/G07-diffs.mjs 目录 .a 目录 .b
node handoff/G07-shots.mjs <端口> <输出目录> all [--query groundres=1024]   # 跨版本冻结截图
node handoff/G07-recenter.mjs <端口> 4                   # 挪中心重建的逐帧差异
node handoff/G07-spikes.mjs <端口> 60 3 1                # 同页交替：上传帧与尖峰
node handoff/G07-stream.mjs <端口> <流速> <秒> ; node handoff/G07-brief.cjs <输出.json>
node handoff/G07-upbench.mjs <端口>                      # 一层上传含 GPU 的代价
node handoff/G07-tier.mjs <端口>                         # 定档与面板提示
node --import ./scripts/lib/ts-resolve.mjs --experimental-transform-types --no-warnings handoff/G07-gpu-rules.mts
node --import ./scripts/lib/ts-resolve.mjs --experimental-transform-types --no-warnings handoff/G07-mipbench.mts
```
调试句柄：`__voyage.ground.gpuMips`（true = G06 的整组生成）、`.stagedUpload`（false = PERF-8 的每帧直传一张）、`.rebuildAll()`、`.imageryStats.{res,warm,warmup}`；`__voyage.quality.groundRes`（精度与依据）。
