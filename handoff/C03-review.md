## 问题

### 1. 实时单帧里有交叉细纹，不只是 64 帧平均没收敛（铁律：锯齿 / 棋盘优先）

交付报告说交叉细纹是「64 帧未收敛」，实时截图里看不到。复核结果相反：在真实的时间累积路径上，同一页面、同一机位、静止相机，稳态单帧截图里交叉纹清楚可见。看 `rt/zoom-variety-c.png`、`variety/zoom-a.png`、`variety/zoom-b.png`（左 old，中 new）：云侧阴影面上是一层菱形网纹。

相邻像素差（adj）看不出这种纹，因为它和 old 的横纹是此消彼长的。改用对角高频能量占比（FFT 中 |fx|、|fy| 都大于 0.2 的能量 ÷ 半径大于 0.02 的总能量，`hf.py`）来量：

| 场景（实时单帧） | old | **new（交付）** | ign2（增量 0.7549，空间项换独立 IGN） | sqrt2（增量 0.4142，空间项仍是 13·ign） | **sqrt2ign（建议）** |
| --- | --- | --- | --- | --- | --- |
| clouds-variety 对角高频 | 0.0071 | **0.0095（+34%）** | 0.0106 | 0.0097 | **0.0077（+8%）** |
| backlit-cu 对角高频 | 0.0084 | **0.0094（+12%）** | 0.0097 | — | **0.0086（+2%）** |
| noon-cumulus 对角高频 | 0.0117 | 0.0120 | 0.0125 | — | 0.0118 |
| variety 横纹能量 streak / 各向同性 iso（`C03-streak.py`） | 3.43 / 1.71 | 2.96 / 1.90 | 2.93 / 1.82 | — | **2.94 / 1.72** |
| backlit 横纹能量 streak / iso | 8.79 / 3.43 | 7.94 / 3.64 | 7.92 / 3.63 | — | **7.92 / 3.49** |
| variety adj | 4.05 | 4.13 | 4.19 | 4.13 | **3.99** |

两个首轮数值（variety old 0.0071、new 0.0095）在两次独立运行里逐位复现。只换空间项（ign2）或只换增量（sqrt2）都消不掉交叉纹，两样一起换（sqrt2ign）才消掉。建议写法去横纹的效果与交付版相同，各向同性噪声和 adj 更低。

### 2. 数学：去相关不彻底，而且把「挑格点」的时间分层变差了

- **`ign·13` 对去相关没有贡献。** 13 是整数，所以 `fract(13·ign) = fract(13·(jitter − 0.618·f))`，新序列可以精确改写成 `fract(13·jitter + 0.7205·f + i·φ)`，仍然是 jitter 的函数。决定逐像素时间联合分布的只有增量对 (0.618, 0.7549)，空间项只决定屏幕上的图样。交叉纹正出在这个 13 倍放大的 IGN 上：IGN 的蓝噪声邻域性质乘 13 以后就没了。
- **联合分布还有一条近有理关系。** 4·0.61803 + 6·0.75488 = 7.0014，每帧只漂 0.0014，64 帧才走 0.09 圈。(jitter, gDetailRnd) 在整个 64 帧周期里都贴着直线族 4x + 6y = 常数，所以 (4, 6) 次谐波上的深度与格点相关一直没被平均掉。这可能就是横纹比只降了 12–19%、没降到 1 附近的原因之一。对照：√2−1 与 0.618 在 |k| ≤ 10 的低阶谐波里，最慢的一个 64 帧也走 0.42 圈（`scan.py`）。
- **一维分层变差。** 0.7549 是 R2 的 x 分量，要和 0.5698 配对才好；单独当一维序列用，4 × 0.7549 = 3.0195，在 TAA 窗口（blend 0.12，约 8 帧）里只落在大约 4 个值上（两两挨着）。模拟 EMA(0.12) 下三格点指示函数的估计误差：时间标准差 old 0.045 → new 0.071（+57%），周期大于 15 帧的低频成分占比 0.32 → 0.73（`seq.py`）。√2−1 是 0.045，与 φ 相当。
- **实测时间波动**（静止相机，云缓冲亮度，逐像素相对标准差 / 16 帧块平均后的标准差，`rt/*/meta.json`）：

| 场景 | old | new | sqrt2ign |
| --- | --- | --- | --- |
| clouds-variety | 4.82% / 1.66% | 5.64% / **2.64%（+59%）** | 5.77% / 2.42%（+46%） |
| backlit-cu | 6.74% / 2.18% | 7.89% / **3.47%（+59%）** | 8.03% / 3.16%（+45%） |
| noon-cumulus | 32.3% / 7.02% | 32.6% / 7.42% | 32.6% / 7.31% |

  去相关后方差变大是预期内的：old 的相关采样有偏，但方差低。可是 new 把增量主要推到了低频（约 1–4 Hz 的「呼吸」），这类闪烁比高频颗粒更显眼。sqrt2ign 的低频少一截。两者都要在返工后用下面第 3 条说的方法，在运动相机下看一次。
- **`uFrame` 精度 / 溢出：没问题。** `uFrame = frame++ % 64`，最大 63·0.7549 ≈ 47.6，float 误差约 4e-6。freeze 跳过 `clouds.render`，`frame` 不推进；画质档切换 / resize 只置 `reset`（history 清空），`frame` 继续走。这些都不会让序列退化。64 帧回卷处的跳变 jitter 原来就有，这次没有变坏。

### 3. 交付报告的闪烁证据无效（`dev-browser flicker` 对云是瞎的）

`flicker` 在 `freeze` 下微移头部连拍，而 `main.ts` 冻结时整次跳过 `clouds.render`（DX-08），所以连拍期间云缓冲一直是同一块。复核结果：clouds-variety 在分支 5185 和 master 5186 上都是 CV p90 0.0001 / p98 0.0003、爬行 0.0001，两边逐位相同。交付表里 variety「0.0001 → 同」测的不是云；noon 那点差异来自地面 / 头部视差，也不是云的时间噪声。云的时间稳定性要用上面第 2 条的逐帧读缓冲来量（`C03rev-rt.mjs`，或者给 `flicker` 加一个「冻结但云照常渲染」的模式，见文末反馈）。

### 4. 次要

- 代码注释和交付报告把 0.7549 叫作「每帧增量 0.7549」，简报里写的是「R1 增量」，其实它是 R2 的 x 分量，和 R1（φ）不是一回事。返工改成 √2−1 后注释要跟着改，并写明选它的理由：与 0.618 的低阶联合谐波漂移快，一维分层与 φ 相当，空间项用与 jitter 无关的 IGN（不能用整数倍 ign）。
- README 新坑点里写的修法 `ign·13 + uFrame·0.7549` 要同步改掉，另补一句：**整数倍的 ign 仍是 jitter 的函数，只能起换图样的作用**。
- 交付报告的诊断表写「`gDetailRnd` 换一条与 jitter 无关的序列 → 消失」，但最终指标只降了 12–19%（ratio 3.52 → 2.99）。两者口径不一样（诊断用的是 RND_NEW，即 `ign(yx·1.37 + …)`，不是最终的 RND_D），应该写清楚。

## 开发体验反馈

- **哪里慢**：离线 FXC 等了约 10 分钟，因为另一个 shader-budget 进程占着测量锁，最后只好带着负载测。给每个变体搭实时对照脚本约 15 分钟。
- **哪里卡**：
  - `dev-browser flicker` 在 freeze 下对云完全不敏感（冻结跳过 `clouds.render`），任何改云时间行为的任务用它自证「不闪」都会得到假阴性。实现代理和简报都没意识到这一点，DEV_SOP 也没写。
  - `shots --freeze` 截到的是冻结那一刻的历史缓冲，两个服务器截图机位不同，只能比统计量。`--pair` / `--base-shader` 同样因为冻结而换不动云的着色器（不渲染云），对云程序没法做同机位 A/B。
  - adj（相邻像素差）对「横纹换成交叉纹」这种此消彼长的变化不敏感，交付自证用的正是 adj。
- **怎么绕过的**：改 C01-measure，冻结后手动调用 `v.clouds.render`：blend 0.12，开邻域夹取，零运动，预热 96 帧后逐帧 `readRenderTargetPixels`，统计逐像素时间标准差和 16 帧块平均后的低频波动，再截稳态单帧。另外用 FFT 对角频段能量量交叉纹。
- **希望有**：① `flicker` / `shots` 加 `--cloud-live`（冻结其余一切，但云照常按真实 blend 渲染 N 帧），`flicker` 同时输出云缓冲的逐像素时间标准差和低频成分；② 把 `C03rev-rt.mjs` 的实时路径并进 `C01-measure.mjs`，做成 `--realtime` 选项；③ `C01-texture.py` / `compare.mjs` 加一个方向性高频指标（横 / 纵 / 对角频段能量），让交叉纹、横纹能被数出来；④ DEV_SOP 测量约定补一句：「flicker 不测云的时间噪声」。
