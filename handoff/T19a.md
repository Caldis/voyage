## 做了什么

| 文件 | 内容 |
| --- | --- |
| `src/routes.ts`（新） | 15 个东亚机场（真实坐标，来源见文件头）和 56 条真实存在的城市对（示例性质的网络，没有核对时刻表）；距离和方位用大圆公式；`pickNextLeg` 按「地区 ×2 + 机场」的到访次数降权再乘随机数，不立刻折返；巡航高度按航程选（<450 km 7.6 km，<900 km 约 9.4–10 km，更远 10.1–11.3 km） |
| `src/director.ts`（新） | 导演。①航段接力 `relay()`：到达终点 40 km 内直接接下一段，不瞬移，也不调 setPreset；②剖面：爬升 12 m/s → 巡航 → 按下降率与地速算出的距离开始下降（10 m/s）到 3 km（陆地上被 T18 的下限抬高）→ 到达上空后转弯接下一段的爬升；短程航段会压低巡航高度，保证爬升和下降装得下；③时间：`simDt = dt × rate`，时间和飞行一起加速；④遮挡切换：`request({id, covers:["cloud"\|"night"], minCoverS, force, run})` 排队，等遮挡持续够久再执行；`onCover(fn)` 在遮挡开始时回调（留给第二阶段的钩子）；⑤本阶段唯一用到遮挡的切换是换原点（离原点 >1200 km 等穿云，>2000 km 深夜也行，>3000 km 且高度安全时硬切）；⑥地区霾沿航段在两地之间插值并平滑，时区过半程时换成目的地的；⑦自动舱灯：入夜（太阳 < −4°）切到睡眠档，天亮（> −2°）开灯，否则夜里窗板会罩一层灰（T24）；⑧连续性遥测 `telemetry` |
| `src/main.ts` | 接入导演；`stepFlight` 把加速后的模拟步长拆成 ≤0.5 s 的小步（航向控制器按角度差 ×0.3 转，大步长会过冲）；`rebaseFrame()`：原点移到飞机正下方，地面重建，雷暴、台风、闪电通道平移，云做 snap；按流速停用地面最细级 |
| `src/flight.ts` / `state.ts` | `state.altRateKms`（导演设成真实值，没设时仍用飞行阶段按钮的 10× 值）；onReachDest 的注释 |
| `src/ui.ts` / `index.html` | 连续航程开关、航程流速、背景板模式（面板和光标隐藏、鼠标移动时显示提示和退出按钮）；连续航程开着时旧的「时间流速」按钮置灰，免得两套一起推时间；信息栏多一行航段信息 |
| `src/ground/clipmap.ts`（**不在归属范围内，改动很小**） | `setMinLevel(n)`：停用最细几级（标记为无效，在途的构建完成后也不再启用）。不改的话 60× 会把 EOX 打到限流，见 README 坑点 |

## 验收结果（`tmp/screenshot/T19a/`，vulkan，60×，真实 8 分钟 ≈ 模拟 7.9 小时）

- 航段：HND→CTS（预设）→ CTS→TPE（2713 km）→ TPE→HKG → HKG→PVG → PVG→CAN，共 5 段，跨越日落（太阳高度 22.7° → −51°）。
- 连续性（每帧）：大圆位移 / 期望位移最大 **1.02**（>3 才算瞬移）；高度变化率最大 **0.012 km/s**（等于爬升率上限，没有跳变）；转弯率最大 **2.4°/s**（25° 坡度内）。2 秒采样的最大速度 0.252 km/s，等于巡航地速。
- 换原点：1 次，在 18:3x 太阳低于 −12° 时借深夜执行（离原点 2437 km）。这一轮全程晴空、没穿过云，所以没触发穿云这个遮挡。
- 背景板模式：B 开启后 `panelHidden=true`；静止 3 秒后 `body.backdrop-idle`，`cursor: none`；Esc 退出，面板回来，连续航程继续。
- 控制台 0 error；瓦片请求每分钟 EOX 545、OpenFreeMap 558（1× 基线 95）。
- 回归（d3d11）：`regression/` 下的 noon-cumulus、route-hnd-cts、night-city 画面正常，帧时间 3.4 / 2.4 / 3.0 ms。连续航程默认关，回归脚本不受影响。
- `montage.jpg` 是 24 张时间序列的缩略图。

## 坑 / 已知限制

1. 60× 时停用了细级别，下降到 3–4 km 的陆地上空时地面偏糊（64 km 级，约 60 m/像素）。1× 不受影响。更好的办法是在 clipmap 里按速度决定最细级，并加上请求预算。
2. 换原点时云场和海浪的噪声原点会跳。深夜遮挡下有月光时，云的位置变化理论上可见，这一轮截图没捕捉到那一帧。第二阶段有了天气场之后，最好改成主动安排一次「穿云」来遮挡。
3. 时区过半程就切换，面板上的当地时刻会跳 1 小时（例如 17:48 → 17:09）。这是当地时间的正确表现，但截图文件名看起来像时间倒退了。
4. 连续航程开着时，高度目标由导演接管，面板的「飞行阶段」按钮会在下一帧被覆盖。
5. 雷暴、台风预设在接力后留在原地、被飞机甩在身后（第二阶段由天气场接管）。

## 第二阶段接口建议

- **天气场**：`weather.ts` 加一个 `sampleField(lat, lon, simTime) → {coverage, cloudType, storms…}`。导演每 N 秒按当前经纬度取样，把云参数按分钟级插值推给 `cloudUniforms`。雷暴、台风的生成与回收按经纬度来（换原点时平移，`rebaseFrame` 里已经有平移雷暴的代码）。需要硬切的参数变化（换云型、换 preset）走 `director.request({covers:["cloud"], ...})`。
- **奇观之门**：奇观系统用 `director.onCover(kind => …)` 或 `request({id:"wonder-in", covers:["cloud"], minCoverS: 3, run})`。要主动制造遮挡时，由天气场在航线前方放一堵云墙（「穿云墙」），导演在 `cloud` 遮挡里切换奇观开关。海市蜃楼那一版的门不需要遮挡，适合做成 `request` 里一种新的 `CoverKind`（例如 `"haze-horizon"`）。
- `CoverKind` 可以扩展：`lightning`（雷暴闪光）、`lowHaze`（T18 的低空霾）；只需在 `updateCovers()` 里加一条判定。
