## 交互说明

- 画面上**按住不动**（180 ms 内位移 ≤ 5 px）→ 进入聚焦：视场收窄到「默认 / 倍率」，过渡 200 ms（smootherstep 缓入缓出，倍率在对数域插值）；松开同样 200 ms 还原。
- **按下就拖走**（180 ms 内超过 5 px）→ 原来的转头，这一按不再聚焦。聚焦后照样可以拖动转头，灵敏度 ÷ 当前倍数（画面上的移动速度和不放大时相当）。
- 触屏长按同理（pointer 事件，`touch-action: none` 原本就有）。键盘**按住 Z**（守卫与 H / B / M / N 相同：焦点在文字框 / 日期框 / 下拉里不触发；松开 Z 时不看焦点，免得卡在放大状态）。
- 暗角：CSS 径向渐变叠层，强度 × 过渡进度；默认 40%（四角最多压暗约 18%），不聚焦时 `hidden`，画布逐位不变。
- 双击画布复位视角（原行为），双击滑条 / 标签复位该项。

### 头部左右限位

**判据**（`src/head-limits.ts`，几何常数与着色器一一对应）：视锥边界 46 条视线逐条判断，全部满足才算可用：
1. 视线要打到侧壁，且打到的点沿机身方向离眼睛不超过「眼睛所在深度处、与侧壁成 12° 的水平视线」的落点——侧壁沿机身无限长，更斜就是消失点附近无限重复的窗，平行 / 背离侧壁就是用户截图里的纯黑。上下方向侧壁弯回来（上接行李架、下面内收），俯仰不受限（头最高 / 最低贴窗的截图 `vert/` 都没露馅）。
2. 在碰到真有的两排座椅（本排 / 前排）或侧壁之前，不能进入按同一排距外推的「幽灵座椅」包围盒（前后各 4 排）——那就是「该有座椅却只有光秃侧壁」的空白舱。
3. 眼睛到本窗窗板开口近侧边缘的视线与窗板法线夹角 ≤ 33°——更斜时窗板开口近侧出现竖直纯黑带（着色器缺陷，见下「发现的问题」），网格实测起始 35.4°。

对照（`FOCUS-ZOOM-gpu-close-jobs.json`）：不聚焦、头贴窗（z = −0.03）的 noon-cumulus 整帧 3.06 ms，比默认坐姿 2.51 ms 本来就贵 22%；4× 聚焦 3.58 ms 只比贴窗再多 17%。大头是**窗外占满全屏**（舱内便宜的像素换成了窗外 / 云 / 机翼的像素），不是 LOD 失控。按 `research/PERF_PREVIEW_wave8.md` 的口径（用户 3840×1950、160 Hz、晴天积云 5.37 ms），4× 聚焦约 7.7 ms，**超预算约 23%**。

处理：① 聚焦中及还原后 1.5 s 暂停自动调档（`quality.pauseDecisions`，main.ts 每帧续期）——过渡 200 ms 本来就到不了降档的 700 ms 持续门槛，但按住看几秒就会降档，一降云缓冲分辨率变、时间累积重置，正好在用户凝神细看时整片糊一下；聚焦是短暂的主动操作，宁可这几秒掉一点帧。② 真要省（建议另开 PERF 任务）：聚焦时按倍率降云缓冲分辨率（窗外角分辨率已经高了倍率倍，云本来就糊）；机翼 pass 放大时的边缘超采样与步数按像素足迹降；两项都是画质 / 性能权衡，需要性能工程师预审。

## 发现的问题（不在本任务归属，未修）

1. **窗洞近侧黑带**（`scene.ts` / 窗洞合成）：很斜地看本窗（眼睛到窗板开口近侧边缘的视线 ≥ 约 35°）时开口近侧出现竖直纯黑带，越斜越宽（`grid/`、`yaw/`、`yaw2/`、`crop-mid-xneg.png`）。根因未查清（猜测是内衬挡住窗板的那一条按窗外合成、那里没有有效着色——**假设**）。现在由限位判据 3 在相机上避开；修好后可放宽 `PANE_EDGE_MAX_DEG`。
2. **机翼襟翼 / 后缘的亚像素缝**：放大后成稀疏点线（见上），建议 W-EDGE 顺手看。

## 已推翻

- 限位判据最初把「已建模两排座椅前后范围以外、座椅高度以下」整片当露馅：连默认坐姿、经济舱「看前方 / 后方」预设都被判不合格（本排座椅背后本来就是下一排的腿部空间，不是座椅）。改成按排距外推的「幽灵座椅」包围盒。
- 判据 1 最初用三维夹角（`rd.z ≥ sin 12°`），头高 0.18 贴窗时连正对窗口都不合格，截图证明那里没露馅（侧壁上下弯回来）；又试过「只看水平面分量」，仍误伤陡峭朝下的视线；最后改成「打到侧壁的点沿机身离眼睛的距离」。
- 曾加「侧壁命中高度在地板与行李架之间」的判据（WALL_Y），同样被头最高 / 最低的截图否定，删掉。
