## 1. T38 根因（probe 读数，不是目测）

- 云步进根本不知道地形：`seg` 只由云壳和 400 km 决定，视线打到山上以后照样一路走下去；窗外 pass 按「背景 × T + 云」合成。
- 读回（`handoff/T38-probe-depth.mjs`：云步进把平均深度写进云缓冲，窗外输出地面距离）：富士山坡上带云的像素，云的平均深度 65–290 km，地面只在 38 km——山后的云被合成到山体前面。
- 清晨 4 km、层云 1.2–3.4 km：山顶那段视线在层顶以上（前方没有云），地平线附近的远云带正好落在山腰的视线上，于是「山顶浮在带子上，带子下面山体又露出来」。云量 0 时没有云，现象消失；6 km 时远云带落到山体以下。美术总监的假设「按地形深度截断用错深度」不成立：没有截断。
- 霾（T18）与此无关（关霾、关谷地雾照旧，和美术总监的对照一致），没改大气。

### 修法

- 云缓冲加宽一倍：左半照旧（RGB + 透射率），右半存 (深度 × 不透明度, 不透明度)，窗外用同一个 sampler 取，相除得到按不透明度加权的平均深度 D。窗外 / 机翼 sampler 数不变。
- 窗外在真实地面像素上：`k = 1 − smoothstep(1.0, 1.3, D / 地面距离)`，云的辐亮度 × k、不透明度 × k。
- 走过的弯路（都在 README 坑点）：
  1. 只按「视线在云壳里均匀、前段透射率 T^f」估计：山后浓云 T ≈ 0 时 T^f ≈ 0，整条带留在山前；读回 D/t = 1.7–2.0 的不透明云都被保留（`T38-probe-k.mjs` + `T38-readrow.mjs`）。
  2. 直接累积深度：没有云的帧深度是 400 km，稀疏小云累积出 150–360 km，sunset-wing 海面上一大片云被去掉。改按不透明度加权后，sunset-wing 同一行 160 个像素只有 5 个 T 变了 ≤ 0.01（打包精度）。

## 2. T44 遗留：近塔「圆桶」

读回（`handoff/T38-probe-tower.mjs`，视线透射率降到 0.6 处的直射 / 环境光 / 受光光学厚度 / 高度）：

- 受光光学厚度只有 227 和 457 两个值：受光步长逐步翻倍，后几步一步几公里，精简密度只在中点取 0 / 1。某个高度以上中点出了塔，背光面直射项 0.5 → 0.13，亮度跳 4 倍：半腰一条分界、下半截整片发暗（「拱洞」）。
- 环境光：塔身按整个台风外壳（0–20.5 km）归一化，3 km 处只剩约 35%，再乘隆起遮蔽 × 高度遮蔽，底部约 20%；明暗只随高度变、不随形状变。
- 形状：塔侧面是一根直筒。

改：
1. `gLightLen`：受光步进把这一步的长度交给雨带塔精简密度，过渡带按步长放宽（≈ 这一步落在塔里的比例）。试过取样点随机（每帧换）：分界抹平了，但受光面（砧顶）满是颗粒，撤回。
2. 眼外（2.5–4Re 过渡）的塔环境光改按 0–10 km 归一化、下限 0.4；塔身的遮蔽里隆起的权重加大（0.35 → 0.25 下限）、高度的权重减小（0.5 → 0.75 下限）。
3. 腰身：半径随高度 ±约 10%（两个不成整数比的周期，相位每座塔不同），一节节鼓出 / 收进，侧面有层次。

## 还不够好

1. 山前一层薄云、山后还有浓云时，山前的薄云一起被去掉（平均深度被拉远）。要精确得存深度分布（例如两个矩），缓冲右半还有 B / A 两个通道空着。
2. 只对真实地面生效（`onGround`）；程序生成的岛（关掉真实地理时）不处理。
3. 富士山的轮廓本身是地形 clipmap 的台阶锯齿（改前就有，地面归属，没动）。
4. 近塔背光面整体仍偏蓝灰：背光面的亮度按物理本来就只有受光面的几十分之一；更亮要靠「被照亮的邻近云 / 裙边反射」这类多次散射项，没做。
5. 云 resolve +0.06 ms：右半只需要深度和不透明度，现在邻域夹取读了 9 次颜色 + 9 次深度，可以只读 A 通道的精简版（没做）。
