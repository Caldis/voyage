## 做了什么

| 文件 | 内容 |
| --- | --- |
| `src/weather.ts` | ①`WeatherField`：按 (lat, lon, simTime, seed) 取样、可重复的低频场。云型得分 = 大尺度 fbm 云量 + 对流潜势（陆地当地太阳时 15 点峰值、海上清晨小峰；夏季、热带放大）+ 锋面带（冬 ~24°N、盛夏 ~33°N，沿经度起伏、时有时无；南侧层积云、北侧高积云）+ 信风（18–28°N 海上积云）+ 卷云噪声；积云 / 浓积云同族，云顶随对流从 3 km 连续长到 6.8 km。②雷暴系统：2.5° 格子 × 3 小时窗口哈希出生，出生概率随成熟时刻的对流潜势与锋面，寿命 2.5–5.5 h、正弦强度包络，25°N 以北往东漂、以南往西漂，孤立 / 团簇 / 飑线三种排布。③台风：8° 格子 × 4 天窗口，西北太平洋生成，季节加权，西北行、22–30°N 转向东北（示意路径）。④粗略东亚海陆分布 `coarseLand`（大陆折线 + 岛屿胶囊，示意，只用于气候倾向；飞机正下方有地形数据时用真实的 `state.floor`）。⑤`WeatherSystem` 加 `addStorm / removeStorms / setHurricane / translate`，`syncUniforms` 公开；`Storm` 带 `id`（「系统#序号」）与 `quiet`（不打闪电） |
| `src/weather-director.ts`（新） | 天气驱动，导演持有（`director.weather`）。见下「导演策略」 |
| `src/director.ts` | `DirectorHost` 加天气相关接口；`cancel(id)` / `hasPending(id)`；每帧调 `weather.update`；换预设（用户跳变）时 `weather.onJump()` 直接对齐天气场；关连续航程时撤掉排队的天气切换；信息栏加一句天气描述 |
| `src/clouds/clouds.ts` | `CloudParams` 类型、`params()`、`setParams(p, gradual)`：gradual 时不清时间累积、云影图不整张一帧重建而按后台分片节奏跟上（否则每次推进都是 3–8 ms 的整张重建）。未改着色器 |
| `src/main.ts` | 导演 host 的天气接口实现；`rebaseFrame` 改用 `weather.translate`；`?gateDemo` 开关。只动了连续航程 / 导演段 |

## 导演策略

- **连续项**：每 5 模拟分钟取样一次，云量限速约 40 模拟分钟满幅、云顶约 3 km/h、形状系数 30 分钟满幅（接近目标时减速）；推给云着色器最短间隔 0.25 真实秒。30 分钟运行里单步最大台阶：云量 0.0087、云顶 0.016 km。
- **换云族**（层积云 / 高积云 / 卷云 / 积云族之间）：目标族持续 20 模拟分钟才动手，排 `cloud-regime` 请求借穿云 / 深夜硬切；等的同时把当前云量淡出，淡到 0（晴空间隙，窗外没有云可跳）也会切，新云型从 0 淡入。目标晴空只淡出不换族。
- **雷暴 / 台风**：取样时列出 280 km 内的活跃系统（整组摆放，最多 4 个单体），离开 340 km 或消散就排移除；台风中心 600 km 内摆放、720 km 外移除。生成 / 移除走 `request({covers:["cloud","night"]})`，`force` 是「整组都在窗外视野以外」（离窗外方向 55° 以外，或扣掉视半径后 450 km 外）。
- **构图**：机头前方、离航线 ±200 km 内的雷暴系统，摆放时整组挪到窗外一侧 40–90 km（`composeForWindow`）；再保证每个单体离航线 ≥ 5 × 半径 + 8 km（不穿进雷暴）。台风中心离航线 ≥ 220 km（外围雨带 / 卷云盖外缘的视角）。摆好后固定在世界坐标，飞机从旁边经过。
- **奇观之门**：`director.weather.openGate({aheadKm, onCover})` 在航线正前方放一个安静的云墙单体（半径 9 km、不打闪电），穿云持续 0.4 s 时移除云墙并回调 `onCover("cloud")`；航线转弯错过了云墙（飞过去 15 km 还没穿云）时以 `"forced"` 回调，由奇观系统决定要不要硬切。

## 验收结果

全部在 vulkan 私有 headless 上跑；回归在 d3d11。

- **长跑**（`tmp/screenshot/T19b/`，60×，真实 30 分钟 ≈ 模拟 30 小时，HND 15:30 出发，12 个航段，`montage.jpg`）：控制台 0 error；连续性同 T19a（最大位移比 1.0x、爬升率 0.012、转弯 ≤2.4°/s）。天气日志 26 条：2 次换云型借深夜、2 次借晴空间隙（层积云 ↔ 积云在北海道附近），2 次台风生成 / 移除（1 次借深夜，1 次在视野外），4 组飑线 / 雷暴群 / 孤立雷暴在视野外生成与移除；**没有一次在视野内硬切**。渐变单步最大台阶：云量 0.0087、云顶 0.016 km（3417 次推进）。
  不足：这一轮的雷暴都在 130–500 km 外、不在窗外一侧，窗里看不到（所以后来加了「构图」）；云型大部分时间是积云族 / 晴空，层积云、高积云各出现过一段。
- **聚焦跑**（`tmp/screenshot/T19b-focus/`，长江中下游 13:00 出发，12 分钟，开奇观之门演示）：`storm-*.png` 是雷暴在窗前（离窗外方向 < 28°）时自动加拍的，积雨云塔在 69–84 km 外从窗前经过（`storm-05` 最清楚）；奇观之门 6 / 6 次都在穿云遮挡里执行（`[cloud]`），没有一次 forced。
- **性能**：天气驱动开 / 关的 A/B（正午出发 3 分钟）帧间隔中位 p95 都是 12.4 ms、最差都是 31 ms，驱动本身不增加开销。远处雷暴 / 台风的 GPU 开销见坑 1。d3d11 回归（`tmp/screenshot/T19b/regression/`）：noon-cumulus 2.1、storm-day 3.5、typhoon-bands 5.7、night-city 2.6、route-hnd-cts 1.9 ms，画面正常（连续航程默认关，不影响回归）。
- typecheck / build / check:glsl 通过。

## 坑 / 已知限制

1. **占据网格只覆盖 ±128 km**，网格外的雷暴 / 台风照样逐点求值：4 个单体放在 300 km 外仍 +1–1.5 ms/帧，台风放在 750 km 外 +2–3 ms/帧（vulkan，`T19b-storm-cost.mjs`，基线本身有约 1 ms 抖动）。所以摆放范围收紧到 280 km（雷暴）/ 600 km（台风）。根治要在云程序里给远处的雷暴 / 台风做 LOD（例如网格外只算解析大形），不在本任务归属内。
2. **天气渐变不能走 `applyPreset` / `snap()`**：会清掉时间累积、整张一帧重建云影图；要用 `clouds.setParams(p, true)`。
3. 夜里（月光下）借「深夜」遮挡的换云型 / 生成台风，理论上在有月光时仍可见（T19a 坑 2 同源）。深夜阈值是太阳 < −12°。
4. 用户在面板上改云参数时，驱动会从新参数接着走（不会硬拉回去），但下一次取样后会按天气场慢慢推。关掉 `director.weather.enabled` 才完全手动。
5. 长时间 60× 运行（约 18 真实分钟后）白天的帧间隔 p95 变差（12 → 40–70 ms，p50 仍 6.3 ms），和有没有雷暴无关（无云无雷暴的时段也一样）；3 分钟的 A/B（天气驱动开 / 关，正午）完全相同。怀疑是长时间加速后地面瓦片 / GC 的累积，没有定位。
6. 窗板上夜里有一条中间断开的横向亮带（舱内灯带的反射，T24 范围），不是天气。
