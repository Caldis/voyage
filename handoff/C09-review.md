## 2. 物理与实现

**前向峰按路上再散射次数展宽（C）**：推导与代码一致。
- HG⊛HG = HG(g₁g₂) 在球面卷积（Funk–Hecke，勒让德系数相乘）下是精确的，不是近似；k 次峰散射后的角分布是 HG(0.9^(k+1))，代码里 0.81 / 0.729 / 0.6561 对应 k = 1 / 2 / ≥3。
- 能量：Σₖ e^(−od)(0.75·od)^k/k! = e^(−0.25·od)，与 master 的 delta 缩放总量逐项相同；k ≥ 3 的余量 `max(exp(−0.25od) − pkSum, 0)` 在 od 小时是 O(od³) 的相消，fp32 误差约 1e-7，可忽略；`max` 只防负。
- 与 C01 的多次散射八度 + 扩散尾巴**没有新增重复计能量**：峰通道（k ≥ 1 的那部分本质上也是多次散射）在 master 里就以 e^(−0.25·od) 的形式和八度并存，C09 只改了这份能量的角分布，总量不变。
- 相函数挪到循环外：`cosT = dot(rd, uKeyDir)`，rd 逐像素常量、uKeyDir 是 uniform，循环里没有任何地方改 cosT；高阶循环展开后 k = 1：a = b = msDecay、g 乘 0.5（−0.125 / 0.4），k = 2：a = b = msDecay²、g 乘 0.25（−0.0625 / 0.2），与原循环逐项相同，雷暴 msDecay = 0.6 时同样成立。`hg(` 在整个 src 里只有这一处调用点，探针 / 影子程序没有另一份受光公式需要同步。
- 非阻塞（写法 / 文档）：
  - `f = 0.75` 是沿用 T12 的经验值（为了与原 e^(−0.25·od) 衔接），不是 Mie 的物理比例；同一段注释上面还写着「水滴的散射里约一半是衍射峰」，而 Jendersie & d'Eon 2023 的拟合也是约一半窄峰（g ≈ 0.99）+ 约一半 Draine 瓣（g ≈ 0.55–0.6）。建议注释里明说「f 取 0.75 是为了总能量与 T12 的 delta 缩放一致，属经验值；物理上约 0.5，但 f = 0.5 时薄处噪声 +36%，所以没用」。Jendersie & d'Eon 在 C09.md 里只用来解释被否掉的变体 A，代码里没有引用，这样没问题。
  - k ≥ 3 全部塞进 HG(0.656)：od 大时真实的 k ≈ 0.75·od（od = 16 时约 12 次，对应 g ≈ 0.28），所以深处的展宽是**偏保守**的（仍偏窄）。建议补一句，免得后人以为是精确解。另外「每次峰散射后光仍沿太阳方向传播、受光 od 按直线算」是小角近似，也值得点一句。
  - 副作用：HG(0.656) 在 90° 处约是 HG(0.9) 的 4 倍，深处的峰能量被摊到侧向，侧光 / 顺光的云深处略亮。实测 HDR 云亮度 variety +2.1%、cu-side +2.1%、backlit-cu +3.4%、noon −1%，显示上 ≤ 1.6/255，可接受。

## 开发体验反馈

- **哪里慢**：用官方 `flicker --cloud-live` 两个端口各跑一遍做 A/B，每次约 1.5 分钟，8 个姿态 × 2 端口约 25 分钟；而且两端口的姿态并不相同（见下），白跑了一半，后来改为自己写同页换着色器的脚本（约 13 个作业 × 3 变体，约 15 分钟）。
- **哪里卡**：
  1. `flicker` 不调 `pinGeometry`：applyScene 等待期间飞机在飞，即使场景写了固定 offset，两个端口的 backlit-close 取景也差一截（两张 f31 平均差 2.91/255、8.7% 像素超阈值），跨端口 A/B 实际比较的是姿态。
  2. `shots --pair '' --base-shader <端口> --cloud-live`：换上基线着色器后立刻截图 b，没有预热帧，云的时间累积里 b 大部分还是 a 的历史（blend 0.12），会系统性低估差异；a2 同理。这是 DX-22 之后仍然存在的「对照工具对云半瞎」。
  3. `flicker` 不支持 `--base-shader`，云的时间行为没有正式的同页 A/B 入口；`--out` 相对「运行脚本那棵树」的仓库根解析，在临时 worktree 里跑时截图落进 `tmp/c09rev/tmp/screenshot/…`，找了一会儿。
  4. headless 下 eox 影像瓦片的 CORS 报错刷屏（每个场景几十条），淹没真正的 console.error，监控脚本要先过滤。
- **怎么绕的**：`D:\Code\opus-test\tmp\c09rev-ab.mjs`（同页、pinGeometry 后冻结，从另一端口活页面读同一云变体原文整段换上；每个变体预热 96 帧后读 HDR 云缓冲 64 帧 + 16 张显示截图；支持多姿态 job 文件和变体拆分）+ `tmp\c09rev_metrics.py`。
- **希望有**：把上面的做法收成 `dev-browser.mjs flicker --base-shader <端口> --offsets "x,y;…"`（同页 new → old → new2、换着色器后预热 N 帧、直接读云缓冲、输出多姿态几何均值 / 最差值）；`--base-shader` 在 `--cloud-live` 下换完着色器后自动预热；`check` / `shots` 汇总 console error 时按「外部瓦片」分组折叠。
