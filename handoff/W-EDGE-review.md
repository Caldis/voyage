## 2. 正确性

- **非机翼逐位**：quick 5 场景（biz / sun / night / 云里 2 姿态）里，old 与 new 覆盖率都为 0 的像素 HDR 差 0，新长出的覆盖 0。live 任务的 hdrWing 对照也是只有机翼像素不同。
- **与 STROBE-FLASH（afec713）**：merge-tree 无冲突（它改的是 `wingLampIntensity` / `wingLights`，这次改的是 `wingView` 末尾与 `wingTrace`）。它会改翼尖灯的亮度，从而影响亮像素判据的触发面（见下）。后合并的一方要重跑 night live。
- **阈值 0.05 与着色点 0.4 分开**：读代码没发现不一致。`dHit` 与四面体采样都取在着色点 P（w.t）上，拉普拉斯曲率自洽；探测从真命中 tBest 出发；擦过又离开 0.4 像素带时 w.t 会作废，内轮廓不受影响。
  覆盖率偏浅约 0.15 的来源是两套估计器口径不同，不是着色 / 覆盖脱节，我没看到边缘颜色带。
- **亮像素判据（中位，建议顺手改、不阻塞）**：
  - `lum(col) > 3·refL` 本身是一个**没有迟滞的逐像素开关**：单样本 ↔ 5 样本 + 去亮点，正是这次修掉的那一类。门限附近的像素颜色会跳（覆盖率不跳，因为用的是 covA）。
  - biz 实测，去掉判据后小翼前缘带内 474、主翼前缘 33，现版是 623–711 / 62–75，也就是判据在商务舱正午反而添了闪烁；sun 基本无差；night 不升。
  - 改法：在 2–4 倍之间按 smoothstep 把单样本颜色与超采样颜色混合（2 倍以上就做超采样），或者把门限改成与像素位置无关的量。
- **小问题（低）**：
  - 亮像素路径用在外侧像素（中心没打中）上时，`colC` 是空中最近点的着色，仍以权重 1 计入平均。wingView 里「中心射线能进到这里一定是打中了」这条注释已经不成立。另外，子样本全没打中时 lMin = lC，亮点不会被压。
  - nearGraze（步数用完、判为打中）的像素现在也会进探测：w.t = tBest，这一点离表面可能有 1–3 像素，于是得到 cov ≈ 0.5，旧版是 1。这类像素很少，写进注释即可。
- 夜间 / 湿窗：night 不升；云里静帧差和 −37%，覆盖率误差 0.071，没发现误触发。

## 6. 开发体验反馈

- **哪里慢**：等测量锁，一次 7 分钟，几个代理在排队。live 三场景加变体每次 5–10 分钟。FXC 在负载下两次结果差 20 个百分点，冷编译没法下结论。
- **哪里卡**：
  - `ab` 的 live 统计只按矩形区域算，矩形里一大半是云时，机翼边上的回归会被淹没。实现者就是这样漏看的。
  - `gpu-ab` 的变体里不能同时写 `wingMat` 和 `wingMat.wet`：只画了其中一个时，它直接报「没画到」并退出。实现者的 gpu-jobs 能用，是因为它按场景分开写；从 live jobs 复制过来就会失败。
  - 实现者自写的 heat 脚本上下翻转写错了，没人发现。
- **怎么绕过去的**：写了 `wedgerev_mask.py`。它在同一个 job 里加 covOld / covNew / dump 三个冻结变体，读出覆盖率，把 live 录像拆成轮廓带 / 内部 / 窗外三类分别统计。
- **希望有**：
  - `ab` 的 `job.live` 支持 `mask: "wing-edge"`，自动用冻结覆盖率算轮廓带，统计时分「带内 / 带外」两列。
  - `recordLive` 的存盘格式（自上而下）写进 README「调试与验证」。
  - `gpu-ab` 遇到「材质没画到」时自动跳过这个材质并警告，而不是退出。
