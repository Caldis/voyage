## 诊断

### 1. 水平横纹：受光挑格点的随机数与采样深度相关

| 对照（backlit-cu 地平线云带） | 横纹 |
| --- | --- |
| 步数上限 192 → 384 | 逐位不变（没有用完步数） |
| mip 降 2 级 | 仍在 |
| 步长 ×1/2（mip 不变） | 略少 |
| 步长 ×1/4（mip 不变） | 消失 |
| 进云锚定（割线 / 二分定位表面后从表面按 dt 重走，0–5 次探测） | 更明显 |
| S 换常数（只剩不透明度） | 消失 |
| 受光 od 置 0 | 消失 |
| `gDetailRnd` 固定 0.5 | 消失（但会露 T32 的六边形格点边） |
| `gDetailRnd` 换一条与 jitter 无关的序列 | 消失 |

根因：`gDetailRnd = fract(jitter + i·φ)` 和采样位置 `t + stepLen·jitter` 共用 jitter。时间累积收敛到 E_j[受光(深度(j), 格点(j + iφ))]，随「在第几步进云」这个整数 i 跳变；掠射看云带时 i 逐行变，就是一条条横纹。研究报告说「步长减半横纹变少」没错，但步长只是让它变弱，不是原因。

修法（定稿，返工后）：`gDetailRnd = fract(ign(gl_FragCoord.yx + vec2(19.0, 47.0)) + uFrame * 0.41421356 + float(i) * 0.6180339)`，见文末「返工」。第一次交付的 `fract(ign·13 + uFrame·0.7549 + i·φ)` 在实时单帧里有菱形交叉细纹，已替换。试过的 `fract(jitter * 13 + i·φ)` 也能消横纹，但 13φ ≈ 8.034，每帧只走 0.034，时间上几乎不动，没用。

注：表里「换一条与 jitter 无关的序列 → 消失」用的是诊断变体 RND_NEW（`ign(yx·1.37 + …) + uFrame·0.7549`），不是第一次交付的写法；交付写法在最终指标上只把横纹能量降了 12–19%（口径不同，见下）。

### 2. 边宽：命中概率受空白步长限制

掠射薄弦长度 c 小于空白步长 2dt 时，命中概率只有 c / 2dt，命中后按整步饱和，所以不透明度随弦长线性爬升。

| 做法 | 边宽（op_w） | 云步进开销 | 问题 |
| --- | --- | --- | --- |
| 雷暴式「退回 + 8 小步」（`refine8`） | 不变 | +140% / +175% | 提不高命中概率；noon int_rng 0.22 → 0.14 |
| 全程半步（`half`） | −20–27% | +71% / +79% | 太贵 |
| 空白不走 2 倍（`noE2`） | — | +60% | 太贵 |
| 靠近表面变细步（`gLayerNear` = 形状包络 / 侵蚀阈值，空白步长 2dt → 0.5dt，只在第一层云前（T > 0.9）） | noon 2.6→2.1–2.2、sunset 2.8→2.3–2.4、cu-side 5.2→4.4、backlit 1.7→1.5–1.6、variety 1.7→1.6（−3–19%） | +16–22% / +23–31% | 64 帧平均里出现横纹，见下 |

### 为什么没做细化

「靠近表面变细步」有两类新条纹：

1. **光照条纹**：进云那一步越短，落进被照亮的几十米表皮的概率越大，受光随步长变。受光深度改按原来的 2dt 统计（`baseLight`）可以消掉这一类，同时云芯对比还升了（noon int_rng 0.26 → 0.31）。
2. **不透明度条纹**：步长由上一个样本决定，上一个样本的位置又是 jitter 的函数，帧间采样位置不再均匀，收敛成与高度相关的条纹（`diag14/var.png`、`diag15/var.png`）。细步区间换一个去相关的随机数（`blDec`）也消不掉，边宽收益还会跟着掉光。

按铁律，这类新条纹比「边宽 −15%」更出戏，所以没合。要真正做下去，大概需要 Nubis³ 那种与 jitter 无关的距离场（预计算表面距离，步长由位置决定而不是由上一个样本决定），或者每步用独立的随机数（高维序列，时间累积噪声会变大）。建议另开任务评估。

## 已推翻

- 「横纹来自步长 / 步长减半能修」（研究报告 §1.5）：步长只改变横纹强弱，根因是随机数相关。
- 「照搬雷暴 refine 能让层状云边更锐」（研究报告 §3 C03）：它修的是进云那一段的积分，不是命中概率，边宽不变。
- 「进云锚定（定位表面后重走）能消横纹」：在随机数相关没修之前测的，横纹反而更重。
- （第一次交付）「new 的交叉细纹是 64 帧未收敛，实时里没有」：审查在实时路径的稳态单帧里看到了菱形网纹，对角高频 variety +34%、backlit +12%。它来自 13·ign（整数倍 ign 仍是 jitter 的函数，只换图样，还毁了 IGN 的蓝噪声邻域）。
- （第一次交付）「实时 adj 没升高 = 没有新噪点」：交叉纹和横纹此消彼长，adj 量不出，要看对角高频能量。
- （第一次交付）「flicker 与 master 相同 = 不闪」：`flicker` 在 freeze 下跳过 `clouds.render`，云缓冲整段不变，对云的时间噪声是瞎的；variety 两边逐位相同说明测的不是云。
