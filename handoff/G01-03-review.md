## 必改

### R1　黄昏窗口里，高清细节会改掉城市灯点和路灯；到 −4° 时最细两级整层重建，灯光会跳变

- **现象（读代码得出，截图没有抓到）**：交接文档和 README 都写「夜景零回归靠的是：夜里高清细节整个不用」，但开关门限是太阳 > −2° 开、< −4° 关。灯光在这之前就亮了：
  - 路灯：`terrain-shading.glsl.ts` 的 `groundRoadLights` 在 `uSunDir.y ≤ 0.06`（约 +3.4°）时开始按片区亮灯。它的照亮宽度写在影像 A 通道里，由 `packRoads` 里的 `urbanOf(albedo)` 聚落地毯决定。而 `packRoads` 读的正是 `blendDetail` 改过的 RGB。
  - 城市灯点：`groundLand` 里的 `urban` 逐像素读 `alb.rgb`，**完全没有太阳门限**，天一暗就能看到。
- 所以从太阳 +3.4° 到 −4° 这二三十分钟里（日落前后，正是观感最重要的一段），第 0、1 级的灯光按「航拍细节 + 反差放大」之后的颜色来判断建成区。`urbanOf` 本身是非线性的（先平方，再过两个 smoothstep），低频均值不变，不等于判出的建成区不变。太阳落到 −4° 时 `detailOn` 翻转，最细两级按纯 EOX 重建，灯点和路灯宽度会**当场换一版**。日出方向同理，在 −2° 时换。黄昏里第 1、2 级交界处的灯光强度也可能对不上。
- 「A 通道完全不变」只在语义上成立：`blendDetail` 只写 RGB ✓，而且在 `packRoads` 之前 ✓；但 A 的**取值**（道路照亮宽度）会随 `urbanOf(混合后的 RGB)` 改变。
- **修法（二选一，建议都做）**：
  1. 把 `DETAIL_SUN_ON` / `DETAIL_SUN_OFF` 提到路灯亮灯门限以上，例如开 +6°、关 +4.5°。这样灯光可见之前最细两级已经按纯 EOX 重建，而且重建发生在白天，只是细节变淡，看不出来。README「高清细节只在白天用」那条的「约 −3°」同步改掉。
  2. `packRoads` 的聚落地毯用混合**之前**的 EOX RGB 来算：在 `blendDetail` 之前先把 `carpetCells` 统计出来，或者留一份 RGB 副本。这样 A 通道就与细节层完全无关，契约更干净。
- **复现 / 验收**：hnd-cts，2026-09-27，太阳 −1°→−5°，低空 2–3 km，`cabin-light: false`。用 `__voyage.freeze` 冻结后分别在 −3.9° 和 −4.1° 各截一张（或者只拨 `detailEnabled` 做同机位对照），比较近处灯点和路灯。本次审查拍的 `dusk-1052`（−1.4°）因为两个场景之间飞机移动了、机位不同，没能直接对比；这时灯光还很弱，也看不出差别。所以这一条是**代码层面确定、视觉幅度未测**。

## 建议（不阻塞合并，可以记进看板）

### S1　日本覆盖框有几处漏掉真实陆地

`GSI_PHOTO.bounds` 的 7 个框，加上「瓦片中心在框内」的判断，逐个核了海岸线：

- **佐渡岛北半**（38.0–38.33°N）：关东中部框的北边界是 38.0°，东北框的西边界是 139.3°E，佐渡在 138.2–138.6°E，两个框都没盖住。结果是 38.0° 处有一条笔直的清晰 / 模糊分界（羽化只有 2 纹素）。粟岛（38.47°N 139.25°E）同样漏掉。
- **纪伊半岛东南岸**（尾鹫 34.07°N 136.19°E、熊野、新宫一带，约 33.4–34.2°N × 135.9–136.4°E）：近畿框的东边界是 135.9°，关东中部框的南边界是 34.2°，中间漏了一块。
- **隐岐岛后**（36.2–36.35°N，133.2–133.4°E）：近畿框的北边界是 36.1°。
- 冲之鸟岛、南鸟岛不在任何框里（面积极小，可以不管）。国后等北方领土在北海道框里，GSI 在那里有没有数据未核，理论上可能刷 404。

实际上既然已经有 DEM 筛海和负缓存，框只需要挡住朝鲜半岛、萨哈林、俄罗斯滨海边疆区、中国大陆和台湾。建议把框改粗，或者补上这三块。

DEM 筛海本身（第 0 级约 31 m、第 1 级约 62 m 一个高度像素，只要有像素 > 0.5 m 就算有陆地）对填海地（一般 2–5 m）和海岸线都没问题，会漏掉的只有 < 30–60 m 的小礁，漏了也只是显示 EOX，可以接受。

### S2　最细一级的重建被 GSI 队列挡住

`build()` 用 `Promise.all` 等所有数据，其中高清细节要先等 DEM、再等 GSI 瓦片。GSI 的突发量是 80、之后每秒 5 张，刚进入日本或刚降到低空时第 0 + 1 级要 100–160 张，排队最长约 20 秒（本次飞行 `queuedMax = 120`）。这段时间里连 EOX、水体都不会跟着重新居中。第 0 级半宽只有 3.9 km，按 250 m/s 飞，十几秒就飞出范围，会先退回粗级别（发糊），再整片变清晰。

稳态下每公里只补 9–18 张，没有这个问题。建议：GSI 在一定时间内（比如 3 s）没取齐时先按纯 EOX 出这一版，高清细节留给下一次重建补上；或者把高清细节做成独立的一次 RGB 更新。

### S3　细节比逐通道算，暗通道里可能放大色度噪声

`d = 1 + 0.9·g·(h/hLow − 1)` 是 R、G、B 各算各的，g 最高 2.5，d 夹在 [0.3, 3]。植被区蓝通道的线性值很小（约 0.02），GSI 的 JPEG 色度噪声经过比值再放大 2 倍多，可能成为彩色斑点。本次截图（kanto 低空、工厂屋顶）**没有看到**明显的彩色噪点。建议把细节比改成按亮度算一个值，再乘到三个通道上：形状细节不变，也不会引入色偏。

### S4　其他小项

- `?eox=2020` 这类切年份只改影像源和 `EOX_S2.attribution`，面板署名仍写死 2025（`index.html`）。这是调试开关，可以不改，但最好注明。
- EOX 的并发从「不限」改成 32，启动时 `queuedMax` 约 300，地面首屏可能比 master 稍慢。本次没有对照测量首屏时间，建议性能工程师在波次收尾时顺手测一下。
- 高度在 5.5 / 6.5 km 附近、或切换「看机翼」视角时，最细两级会整层重建：白天从 EOX 切到细节版，只在画面下沿，观感上可以接受。

## 逐项核对

### 1. 外部请求 ✓

- 请求头：`fetch(url, { mode: "cors" })`，没有自定义头，也没有 User-Agent 或个人信息 ✓。
- 限速：`HostGate` 是令牌桶（每分钟配额 + 突发量）加并发上限，先来先服务；缺令牌时定时补发，缺并发槽时等 `release` 再补发，逻辑正确 ✓。GSI 每分钟 300 张、并发 6。重新抓了[地理院タイル一覧](https://maps.gsi.go.jp/development/ichiran.html)：页面只要求注明出处并附一览页链接，没有写访问量或节流的限制。这个数值是礼貌上限，合规 ✓。EOX 每分钟 1200 张、并发 32，高于 60× 实测的约 700 张 / 分，低于 README 记录的「约 7000 张 / 分会被拒」✓。
- 「确定没有」缓存：只有 404 / 410 / 占位图才写 `missing`；`!r.ok` 的其他状态（429 / 5xx / 403）计为 throttled，网络错误计为 failed，都不缓存；失败的 Promise 会从 `bitmaps` 里删掉，下次重建再试 ✓。
- 实测（hnd-cts 低空，1× 飞 90 s，细节开）：GSI 请求 369 次，成功 367 次，确定没有 0，限流 0；**控制台 0 条 error** ✓。
- 署名：面板上 EOX 2025 带 cloudless.eox.at 链接；国土地理院带一览页链接，并写了「を加工して作成」✓。README 的数据来源表里 EOX 引了 GetCapabilities 的 Abstract 原文，GSI 引了一览页的利用条件原文和利用规约链接 ✓。

### 2. 数据契约

- A 通道：`blendDetail` 只写 `albedo[i4 + c]`（c < 3）✓；在 `packRoads` 之前调用 ✓；缺影像（A < 128）的像素跳过，保持缺影像状态，由着色器回退 ✓。**但道路宽度的取值受混合影响**，见 R1。
- 低频色调：E_low / H_low 是按覆盖率加权的两遍盒滤波（σ≈3.7 纹素），异常掩码按本级中位数的相对比值判断。设计上 30 m（第 0 级）/ 60 m（第 1 级）以上的平均色仍是 EOX 的 ✓。逐像素的 `landClasses`（白天 `forestHere` 和森林边缘压暗、ground-detail 分类）会随航拍纹理起伏，交接文档已写明 uDebug 21 没测成。这属于白天纹理层面的变化，不算回归。
- 夜间关闭：夜里（< −4°）这一条成立 ✓，黄昏不成立（R1）。
- 闪烁：见第 4 条，实测没有增加。

### 3. EOX 2025 让夜景变亮（night-city 窗内均值 73.1 → 82.6）：**接受，不调阈值**

看了 `night-night-city.png`。结构不变（同样的城区和主干道），新增的主要是一簇簇小村镇的点状灯（画面中上部、右侧），主干道沿线的灯带更连续。判断是**更真实，不是误亮**，理由：

- 灯点亮度 = Black Marble 夜光² × 建成区判据。夜光 < 0.02 的地方根本不会亮，所以新亮起来的点都落在 VIIRS 确实有光的地方。影像只决定「这片光落在哪些像素上」，不会凭空造光。
- 这个场景是骏河湾到静冈一带，属于日本人口稠密区，村镇连成片亮灯符合实际。EOX 2020 的建成区发糊、偏暗，反而把一些真实村落漏掉了。
- 残余风险：大棚、光伏板在 2025 影像里是灰白、低饱和的，可能被判成建成区。不过它们同样受夜光门限约束，只在有夜光的地方会亮。

建议：现在不动阈值，也不必按年份校准。如果以后要校准，参照物应该是 Black Marble 的总能量（窗内灯光总量），而不是某一年影像的均值。美术总监看后认为「偏亮」的话，优先把 `emit` 系数整体降 5–10%，不要去动 `urban` 的判据。

### 4. 性能与 Worker ✓

- 主线程：hnd-cts 低空 1× 飞 90 s，细节开和关都是**长任务 0 个**，帧时间 p50 6.3 / 6.2 ms、p99 6.4 / 6.4 ms，超过 50 ms 的帧都是 0 个。`buildDetail` 在主线程上的 drawImage + getImageData 没有造成可测的长任务 ✓。
