# NIGHT-AP · 月夜远处空气透视偏暗（根因调查）

调查：美术总监兼根因调查员（只调查、不改代码），2026-09-29，master `950e6c8`。
起因：TW02 审查（`handoff/TW02-review.md`「月夜」段）发现，满月在观察者身后、高度约 36° 时，422 km 的远塔和地平线附近的远处体积云都画成**比地平线天空还暗的暗褐色剪影**。

## 结论先行

1. **根因：空气透视 LUT 只有太阳一路，月光没有进去。** `atmosphere/luts.ts` 的 `AERIAL_FRAG` 只按 `uSunDirLocal` 积分，`main.ts:478` 每帧也只传太阳高度。天空用了两张天空视图 LUT（太阳一张、`skyViewMoon` 一张），可空气透视 3D LUT 只有太阳这一张。到了夜里（太阳 −38.7°），云和远塔的合成 `L·T + apL` 里，透射率 T 照常起作用：水平掠射 400 km，蓝光基本被吃光，剩下的偏红；内散射 apL 却几乎是 0，只剩 T46 补上的一点气辉（`nightglow × 0.6 × (1 − T)`，比满月的天光小约两个数量级）。结果就是远处的东西**只被压暗、被染红，没有月光照亮的空气把它补回来**，而它背后的天空（`skyViewMoon`）含有整条视线上被月光照亮的空气。
2. **不是云的夜间受光过弱。** 把云和远塔的空气透视整个关掉（`noAP`），远砧的自身亮度是 0.044 cd/m²，是地平线天空的 2 倍，颜色中性偏暖（饱和 0.30）。把主光源照度 ×2（`key2`）后远砧只是变成更亮的褐色（饱和 0.96），色相不变。
3. **不是曝光 / 色调映射造出来的褐色。** 关掉 T48 的保色（`keepOff`：`uMesopicKeep` 移出范围、`uNightChroma.x = 0`），远砧的屏幕颜色是 29/22/21 → 30/22/20，完全没变。褐色在 HDR 里就已经有了：远砧 R:G:B = 2.95 : 1 : 0.15，饱和 0.95。浦肯野最多只混 80% 视杆灰蓝（`exposure.ts:482` 的 `scotopic * 0.8`），剩下 20% 的原色在这么高的饱和度下仍然透出褐色。曝光只是没能把错的颜色盖住，颜色不是它造成的。
4. **把月光空气透视补上（页面内临时实验 `moonAP`）后问题消失**：远砧 0.030 cd/m²，是地平线天空的 1.35 倍，饱和 0.33，屏幕 67/68/72，是冷灰；地平线远云带从天空的 0.40 倍变成 1.10 倍；近处云也从米黄（屏幕色相 44°）变回银灰（210°）。**这个缺口不只影响远塔：所有月夜里的云都偏暖、偏暗**，远处最明显。
5. **修法**：让空气透视 LUT 同时积分太阳和月亮两路，按「当前占主导的光源」参数化方位角。消费方（云步进、远塔、地形、火车远景、雨虹、奇观）只把 `uSunDir` / `uSunIlluminance` 换成新的 `uApDir` / `uApIlluminance`。不加 sampler，消费方的指令数不变，冷编译基本不受影响。LUT pass 实测 0.07–0.15 ms，加第二路光源预计多 0.05–0.1 ms，白天可以用 uniform 分支跳过。任务拆分见文末。

## ② 根因定位（对照实验，不是读代码推断）

逐个排除调查要求里的四个假设：

| 假设 | 实验 | 结果 | 判定 |
| --- | --- | --- | --- |
| 空气透视内散射在夜里只算了太阳（月光没进 LUT） | `moonAP`：另建一张以月亮为光源的空气透视 LUT，云 / 远塔改用它 | 远砧 0.49 → 1.35 倍天空，饱和 0.95 → 0.33，屏幕从暗褐变冷灰；远云带 0.40 → 1.10 倍 | **是根因** |
| 透射率把远处压暗后，没有相应的月光内散射补上 | 同上。`noAP` 显示自身亮度是天空的 2 倍；`base` 的 T 把它压到 0.49 倍并染红（R:B 从 1.4 变成 20） | T 在正常工作，缺的是 (1 − T) 那一份被月光照亮的空气 | 与上一条是同一件事 |
| 云的夜间受光过弱 | `noAP`（看自身亮度）、`key2`（主光源 ×2） | 自身亮度 0.044，已经亮于天空；×2 只让褐色更亮（饱和 0.96） | 否 |
| 曝光 / 色调映射对暗部色相的处理 | `keepOff`（关 T48 保色） | 屏幕逐级不变；HDR 本身饱和 0.95 | 否（只是浦肯野的 0.8 上限没能盖住错的颜色） |

**褐色从哪来**：云和远塔自身被月光照亮，颜色略暖（月光本身 1.04 : 1 : 0.9，`main.ts:529`；再乘上到云的透射率），R:G:B ≈ 1.16 : 1 : 0.81。它再乘上 400 km 掠射路径的透射率：巡航高度这条视线最低降到约 8.6 km，蓝光的瑞利光学厚度约 4，T 的蓝通道只剩约 2%，红通道约 50%。结果是 2.95 : 1 : 0.15。本该叠在上面的是蓝灰色的月光空气光，而那一份缺了。

旁证：`clouds.ts:882–887` 的 T46 注释写的正是这个现象（「夜里远处的云只剩自身 × 透射率……读成比海面、地平线天空都暗的红褐色斑」），但当时只补了气辉。无月夜靠它确实够了，满月下气辉比月光的天光小约两个数量级，补不上。README「大气与曝光」T48 那条的坑（「满月的地平线远云被长路径消光染成棕红，饱和度 0.88……亮度门限下沿放在 −2.0 才不把它们变棕」）是同一个缺口的另一种表现：当时在曝光这边绕开了，没有回到空气透视去找原因。

**同一个缺口还出现在这些地方**（都是 `texture(uAerialInscatter…) * uSunIlluminance`，夜里一律缺月光；本次只测了云和远塔）：
- `render/terrain-shading.glsl.ts:123`（真实地形远处的空气光：月夜的远山、海岸也会发暗发红）；
- `rail/far-view.glsl.ts:272`、`render/outside-pass.ts:181–182`（火车远景）；
- `render/optics.glsl.ts:418–419`（雨幕合成的 airL）；
- `render/wonder-sky.glsl.ts:532`、`wonders/pillars.glsl.ts:255`（奇观）；
- `clouds/clouds.ts:153`（台风体积阴影分段，只在白天走）。

### 实验方法（可复现）

临时脚本在 `apps/voyage/tmp/night-ap/`（`run.mjs` 摆场景、套变体、截图、读回 HDR；`analyze.py` 按 ROI 统计；`crop.py` 拼放大图；`lut-cost.mjs` 计时。这个目录已忽略，没有提交）。核心是下面这段页面内 js，不改仓库代码：

```js
const v = __voyage, A = v.atmosphere, su = v.sceneMat.uniforms;
const M = new A.constructor(v.clouds.pass);              // 第二份大气，只用它的空气透视
const am = M.aerialMaterial.uniforms;                     // 透射率 / 多次散射 LUT、霾参数与主大气共用
am.uTransmittanceLut = A.sharedUniforms.uTransmittanceLut; am.uMultiScatteringLut = A.sharedUniforms.uMultiScatteringLut;
am.uHaze = A.hazeUniforms.uHaze; am.uHazeShape = A.hazeUniforms.uHazeShape;
const orig = A.updateAerialPerspective.bind(A);
A.updateAerialPerspective = (r, c) => { orig(r, c); M.updateAerialPerspective(r, su.uMoonDir.value.y); };
for (const d of [v.clouds.marchMat.uniforms, v.farTowers.mat.uniforms]) {   // 步进各变体共用 marchMat 的 uniform 对象
  d.uSunDir = su.uMoonDir; d.uSunIlluminance = su.uMoonIlluminance;
  d.uAerialInscatter = { value: M.aerialInscatter.texture }; d.uAerialTransmittance = { value: M.aerialTransmittance.texture };
}
```

太阳在 −38.7° 时，`sunTransmittance` 被地球挡成 0，多次散射 LUT 在太阳天顶角余弦 −0.62 处也近似为 0，所以「用月光 LUT 替换太阳 LUT」在这个时刻等价于「两路相加」。

## ③ 目标外观

依据：物理量级估算，加上夜航舷窗 / 驾驶舱月夜照片的常见观感（图库里「moonlit clouds from aircraft」一类照片，例如 Getty Images 的 moonlit clouds 合集）。这些是描述性参考，不是逐像素定标。

- **满月在身后（远处的云被正面照亮）**：远处的积雨云砧和云带是**淡银灰、略带蓝**的形状，亮度与地平线天空接近或略亮（约 1.0–1.6 倍），对比很低，远塔像是「从地平线的雾光里浮出来」；塔脚和中下部融进地平线的亮带。**任何距离上都不能是暖褐色或黑剪影。** 近处的云顶是明显的银白，与海面拉开（约 1.5–3 倍）。
- **月亮在前方**：月亮附近的天空更亮，背光的远塔可以比身边的天空暗一些，但必须是**冷灰或中性灰**的暗影，只在正对月亮时有一圈银边；从高处看下去的云顶照样被照亮，略亮于地平线天空。
- **无月**：云和海都只是比黑略亮的灰蓝，远云读成地平线气辉亮带前面淡淡的暗影（现状基本如此）。
- 色相：人眼在这个亮度（0.01–0.05 cd/m²，中间视）下看月夜是**银蓝 / 冷灰**。长曝光照片里月光照亮的云偏白、偏暖，那是相机把月光当日光记录的结果，不是人眼看到的样子，不能拿来当目标。

`moonAP` 的实测值已落在这个目标里：身后时远砧 1.35 倍、远云带 1.10 倍，屏幕冷灰；前方时远云带 1.53 倍，中性灰。唯一的遗留是前方远云带屏幕上略带紫（55/53/54，色相 333°）：这是透射率的偏红与内散射的偏蓝叠加出来的，饱和度只有 0.44，肉眼接近中性，修完后由审查确认是否还要处理。

## ④ 修法方案与成本

### 方案对比

| 方案 | 做法 | 优点 | 代价 / 风险 |

### 推荐方案 A 的要点

- **切换点**：用 README T36 实测的天空视图 LUT 中位数估算（估算，不是本次实测）。太阳 −10° 时天光约 4e-8 × 120 klux ≈ 0.005 cd/m²，−12° 约 0.0008 cd/m²；满月天光约 0.01–0.02 cd/m²（本次实测地平线 0.022、高处 0.010）。满月下两者约在太阳 −9° 交叉，半月约 −11°。建议按两路光源在地平线处的估计亮度比切换（CPU 上用月光照度 × 月相与太阳高度的查表，或者读回天空视图 LUT 一个像素），并加 0.5° 迟滞。切换那一帧只有「次要光源的镜像误差」在变，跳变应该很小，验收要实测。
- **次要光源门控**：`uApSecondScale = 次要光源照度 / 主导光源照度`（vec3）。白天月光 / 日光约 2e-6，可以直接置 0 并用 uniform 分支跳过这一路，白天的 LUT 就逐位不变。
- **半精度退路**：LUT 以「主导光源照度 = 1」为单位，夜里主导光源是月亮，数值和白天同一量级，没有 T36 那种下溢；没有 32 位浮点线性过滤的设备反而比现在好。
- **T46 的气辉补项保留**（`clouds.ts:887`、`far-towers.ts:138`），它管的是无月夜。
- **冷编译**：消费方只是换 uniform 名，程序结构和采样数都不变，FXC 耗时应该在噪声以内（单任务门槛 ≤ 10%，要用 `shader-budget.mjs` 按 outside-default / cloud-march / far-towers 与 master 交替测两轮确认）。`AERIAL_FRAG` 程序本身很小，不在关键路径上。
- **GPU**：`lut-cost.mjs` 实测（RTX 5090、d3d11，40 次取均值，6 轮中位）：空气透视 LUT pass 0.118 ms / 次，6 轮范围 0.068–0.152 ms；同时量的整帧 `benchFrame` 约 4.6 ms。加第二路预计 +0.05–0.1 ms，只在夜里 / 暮光付。
