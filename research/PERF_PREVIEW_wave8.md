## 2. 通用条款（每份美术简报都要带上）

1. **帧预算口径**：用户的屏幕是 160 Hz（6.25 ms/帧）、2560×1300 视口 × 1.5 DPR（画布 3840×1950，是 1600×1200 的 3.9 倍像素），高档画质 `cloudScale = 1`、`dprCap = 1.5`，所以用户实际画的就是 3840×1950 全分辨率。验收一律用 `dev-browser gpu-ab`（8 轮 ABBA + 一个 A/A 变体）在 1600×1200 上量相对增量；绝对值按 §1 的倍率换算到用户分辨率。
2. **集显折算**（[引] C10b 审查 §4）：5090 对 Iris Xe / M1 约 30–45 : 1。集显会自动落到「低 / 最低」档：云缓冲 `cloudScale 0.5`（像素 1/4），最低档 DPR 封顶 1。所以**云类 pass 的增量 × 8–11、全分辨率 pass（窗外 / 舱内 / 机翼）的增量 × 30–45** 就是集显同分辨率下的量级。
3. **冷编译**：当前启动关键路径是**窗外程序**（真冷约 7.5 s，[引] PERF-WING §1），机翼约 5.3 s（加 W-EDGE B′ 约 5.8 s），舱内约 4.7 s，座椅约 1.6 s，默认云程序约 0.8–1.0 s。
   - **碰窗外程序（`outside-default`，海面 / 地面 / 天空 / 交通 / 闪电）的任务**：直接加在关键路径上，单任务离线 FXC ≤ +3%（不是 10%——这一波已有多项要碰它，见 §4 的累计表），不新增 sampler（窗外 14/16，余 2 个留给真正需要的）、不新增循环、不新增重函数调用点。
   - **碰机翼程序的任务**：机翼离关键路径只剩约 1.7 s（[引] PERF-WING §5，B′ 之后）；单任务 FXC ≤ +5%，且真冷启动「批次各程序编好」里机翼要比窗外早 ≥ 1 s。
   - **碰云程序的任务**：默认云程序离关键路径很远（0.5 s 对 7.5 s），可以按 SOP 的 10%；但**雷暴变体**（离线约 4.1 s）在 TW01 合并后变成连续航程里的常态程序（南海 / 华南夏季午后 400 km 内有雷暴 > 90%，[引] TW01.md），它编不好雷暴就不能出现，所以雷暴 / 台风变体单任务也按 ≤ +10%，绝对值雷暴 ≤ 5 s、台风 ≤ 8 s。
   - **新程序**一律首帧后后台按需编译，不进启动批次。
4. **不按画质档出着色器分档**（[引] C10b 审查 §2(c)）：`quality.ts` 的档位只改 `cloudScale` 与 DPR，着色器分档会让云变体数翻倍（冷编译、预编队列一起翻）；用 uniform 分档则自动档升降时整窗跳。**替代做法**：所有「近处细节」按**像素足迹**淡入——低档 `cloudScale 0.5` 时足迹自动变大一倍，细节自然少算，不需要任何档位开关。
5. **云步进循环里不加「平时不走」的分支**（[引] README 硬约束：W00 实测加一段不走的分支让整体步进慢一倍）。夜间、雷暴、台风才有的东西：①能折进已有的 uniform 就折进 uniform（CPU 算好，着色器零新代码）；②不能的写进已有的 `#ifdef CLOUD_STORM / CLOUD_TYPHOON / CLOUD_WEATHER`。
6. **受光步进（6 / 8 步的小循环）里不加密度调用**：它套在主步进循环里，每多一次 `cloudDensityLite` 就是「每个有云样本 ×1」，量级 +10–20%。
7. **不许悄悄变贵的「让云变薄」**：云变透明后视线要走得更远、步数更多（被挡住的视线原本早退）。凡是让大面积云变薄的改动（台风卷云盖、砧外缘、雾海），验收要带 `ab` 的 `cloud-steps` 诊断，步数上限 384 的撞线比例不许上升。
