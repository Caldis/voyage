# 调试面板审计 · 第 1 次（UX-1）

> 交互设计师首次介入，2026-09-28。只读审计：截图 + 代码走查（`src/ui.ts`、`index.html`、`src/style.css`、`src/quality.ts`、`src/main.ts` 的面板相关行、`src/director.ts` / `src/weather-director.ts` 的接管逻辑、`scripts/scenarios.mjs` 的 `applyScene`）。
> 规范见 `research/PANEL_UX_GUIDE.md`（下文「§x」指规范的章节）。落地改动由协调者另派实现代理。
> 基线：master `55cd90f`（VOY-DEFAULT 尚未合并；它的 WIP 分支 `9da1be8` 已读，建议已考虑「连续航程默认开」）。

## 0. 结论

1. **面板太长**：1600×1200 下内容 2719 px，可见 1168 px，要滚 2.3 屏；开了连续航程、奇观、声音后 3065 px。1280×720 下要滚约 4 屏；手机（390×844）上 2534 px 塞进 380 px 的框，约 6.7 屏。57 个可交互元素平铺成一列，没有分组、没有折叠。
2. **连续航程开着时，面板上显示的值是错的**：实测开连续航程后，云量滑条仍显示 42%（实际 34%），海面风速显示 7 m/s（实际 1.0 m/s），地点下拉仍是「西太平洋上空…」（实际航段已经是羽田 → 关西）。VOY-DEFAULT 合并后这会成为**默认状态**，所以这是本次**最高优先级**的问题。
3. **普通功能和调试功能混在一起**：「召唤（调试）」「立即触发到达 / 接下一段（调试）」「调试小地图」「手动曝光 EV」、画质状态行里的 GPU 毫秒数，都和座位、遮光板排在同一列。
4. **有几个现成的小 bug**：自动曝光开着时「手动曝光」一行仍然显示（`[hidden]` 被 CSS 覆盖，和 T49 修过的 `.row[hidden]` 是同一个坑）；复选框是浏览器默认的红色；底部提示「移动鼠标 = 挪动头部」已经过时（现在是按住拖动）；手机上没有收起面板的办法（只能按 `H` 键）。
5. 按收益排序的改动清单在第 4 节，前 3 条（小修、接管显示、分区折叠）做完就能解决大部分观感和误导问题。

## 3. 违反规范的问题

严重度：**高** = 误导用户或功能失效；**中** = 明显拖累使用、常见场景可见；**低** = 细节 / 一致性。

### P1（高）连续航程接管时，面板显示的值与实际不符，手动改的语义也不清楚 —— §5.3

- **证据**：`ux1-expanded-top.png` 的场景 `js` 返回：`coverage` 滑条 0.42（显示 42%），`uCoverage` 实际 0.336；`wind` 滑条 7，`state.wind` 实际 0.97；`weather` 下拉 `fair`、`cloud-preset` 下拉 `cumulus`，而信息栏写的是「天气：晴天积云 34%，海面风 1.0 m/s」；地点下拉仍是「西太平洋上空 · 东京以南约 600 km」，实际航段是「HND → KIX」。
- **根因**：`ui.ts` 只在用户拖动时写这些控件（`bindRange` 只挂了 `input`），系统改状态时没有回写：导演改云参数走 `setCloudParams`（`main.ts` 约 288 行），风速写 `state.wind`（`weather-director.ts`，README WX11g 已记），换航段时 `director.ts` 约 461 行直接把 `s.preset` 换成现编的航段预设（下拉里没有这个选项，所以下拉也没法显示它）。
- **手动改的后果也不透明**：连续航程开着时在「天气」里选「孤立雷暴」，天气导演下一次规划时会把「没有 id 的手动雷暴」交给天气场接管，排队在看不见的时候移除（`weather-director.ts` `planStorms`，「面板预设留下的（没有 id）一并交给天气场接管」），下拉却一直显示「孤立雷暴」。云滑条拖了以后，导演下一次推参数又把它拉走。
- **「时间流速」**：连续航程开着时整行按钮变灰（`ux1-expanded-top.png`），没有任何文字说明为什么。
- **影响**：VOY-DEFAULT 合并后，**每个新用户打开页面看到的都是这种状态**。
- **修法**：见任务 UX-2。

### P2（高）信息架构缺失：57 个控件平铺，要滚 2.3–6.7 屏 —— §2、§9

- **证据**：见第 1 节尺寸表；`ux1-default-top/mid/bottom.png` 三张图才看完整个面板。常用的「座位 / 视角 / 遮光板 / 舱等 / 舱内灯光」散落在第 2 屏和第 3 屏，被航向、奇观、声音隔开；「舱内灯光」在第 3 屏。
- **根因**：`index.html` 按功能加入的时间顺序追加控件（T19a、T49、W01、T11 各自插在中间），没有分组。
- **影响**：找控件难；面板长期挡住右侧 18–22% 的画面（桌面），手机上挡住 41% 且压住舷窗中心。
- **修法**：见任务 UX-3。

### P3（高，但都很小）现成的 bug 与过时文案

1. **自动曝光开着时「手动曝光」一行仍然显示**（`ux1-default-bottom.png`，「手动曝光 EV 14.0」出现在勾着的「人眼式自动曝光」下面）。根因：`ui.ts` `syncAuto` 设了 `#manual-row` 的 `hidden`，但 `style.css` 的 `#panel label { display: flex }` 盖住了浏览器自带的 `[hidden] { display: none }`——和 T49 修过的 `.row[hidden]` 是同一个坑，当时只修了 `.row`。修法：`style.css` 加全局 `[hidden] { display: none !important; }`，删掉 `.row[hidden]` 那条特例。识别：凡是给 `display` 设了值的选择器，配合 `hidden` 属性都会失效。
2. **复选框是浏览器默认的红色**（所有截图）：`accent-color` 只给了滑条。修法：`#panel input[type="checkbox"] { accent-color: var(--accent); }`（之后换成开关样式）。
3. **底部提示过时**：「移动鼠标 = 挪动头部，滚轮 = 靠近 / 远离舷窗」——现在是按住拖动才转头（`view-presets.ts` `setupViewControls`），「视角」标签里写的「在画面上按住拖动转头，滚轮前后挪，双击复位」才是对的。两处说法互相矛盾。修法：删掉底部那行，只保留一处。
4. **快捷键守卫不一致**：`H` 没有任何守卫（`ui.ts` 约 298 行），`B` 只排除 `input`，`M / N` 排除 `input` 和 `select`，方向键排除四种。修法：`isTypingTarget()` 统一（§8.1）。
5. **禁用控件没有原因**：火车模式下 9 个飞机专用控件和飞行阶段、航向按钮变灰（`ux1-train.png`），没有 `title` / 提示。修法：`setupVehicleUi` 里给这些控件设 `title = "火车模式下不可用"`。
6. **面板下拉选完不还焦点**：只有 `nav-dest` 做了 `blur()`，其他下拉选完后按方向键会改下拉的值，而不是转向。

### P4（中）调试功能混在用户区 —— §2.2

- 「召唤（调试）」下拉和两个按钮、「立即触发到达 / 接下一段（调试）」、「调试小地图」开关、「手动曝光」、画质状态行里的「GPU x ms / 预算 y ms」、信息栏的日月高度角和三位小数的经纬度。
- 修法：并入 UX-3 的开发者区（`?dev` / `Shift + D` 显示），**DOM 保留**（场景表会按 id 设 `minimap-on` 等）。

### P5（中）同一件事两组控件、离散量用滑条 —— §4.1、§5.3 规则五

- 「时间流速」和「航程流速」是两行，连续航程开着时前一行整行变灰（`ux1-expanded-top.png`）。VOY-DEFAULT 之后，默认状态下用户第一眼看到的就是一整行灰按钮。
- 奇观「稀有度」0–3 四档用了滑条。
- 座位、舱等、舱内灯光、座位相对机翼都是 2–3 项的下拉，要多点一次才看得到其他选项。
- 「飞行阶段」4 个按钮折成两行（`ux1-default-mid.png`），因为标签「飞行阶段（10× 加速）」占了一半宽。

### P6（中）手机 / 小窗 —— §9

- 390×844：面板占 41% 面积、盖住舷窗中心，**没有收起按钮**（标题写着「按 H 隐藏」，手机上没有键盘）；要看全面板得在 380 px 高的框里滚 6.7 屏。唯一能收起面板的是「背景板模式」按钮，而它会顺带打开连续航程。
- 1280×720：面板贴着舷窗右框（`1280x720/ux1-small-default.png`），面积 22.4%，超过 20% 的上限。

### P7（中）文案不合规 —— §3

- 标签里塞括号说明，导致换行：「连续航程（自动接续东亚航线、时间流逝）」「奇观模式（偶尔在远方出现不真实的东西）」「声音（飞机舱内 / 火车车内；按 M 开关）」「调试小地图（航向 / 云回波 / 交通 / 奇观，快捷键 N；点击地图切换量程）」「真实地理数据（卫星影像、地形、水体，联网）」都折成两行。
- 按钮文案过长：「背景板模式（隐藏面板，按 Esc 或 B 退出）」「立即触发到达 / 接下一段（调试）」。
- 术语不统一：「地点」（实为起点 / 航线）、「云」（实为云型）、「天气」（实为天气系统）；舱等状态「（准备中…）」与火车状态、地面精度状态三种写法。
- 选项括号过长：「商务舱（皮革、胡桃木、氛围灯）」「经济舱（织物座椅、塑料侧壁、冷白灯）」。

### P8（中）对比度与焦点 —— §8.2

- 次要文字 3.88:1（舱壁背景），压在白云上时 2.6:1（第 1 节实测）；数据来源段叠了 `opacity: 0.7`，更低。
- 没有 `:focus-visible` 样式，半透明深底上几乎看不到键盘焦点。
- 分段按钮用 `.on` 类表示选中，没有 `aria-pressed` / `aria-checked`；`#panel` 没有 `aria-label`；滑条没有 `aria-valuetext`。

### P9（低）脚本改状态后面板不同步

- `ux1-train.png`：接在「连续航程 + 奇观」场景后面，`applyScene` 直接设了 `wonders.enabled = false` 和 `director.setActive(false)`，面板上「奇观模式」「连续航程」仍然是勾着的。只影响截图 / 调试时的判断，但根因和 P1 一样：面板不读系统实际状态。UX-2 的定时同步会一并修掉。

### P10（低）记忆与复位不成体系 —— §7

- 现有三套各写各的记忆：`audio.ts`（`voyage.sound`）、`quality.ts`（`voyage.groundRes`）、VOY-DEFAULT（`voyage.continuousJourney`，带 `isTrusted` 守卫，做法对）。座位、视角、舱等这类观看偏好不记。
- 没有「恢复默认」；滑条没有默认值刻度，也不能双击复位。
- 声音的 `isTrusted` 守卫：`audio.ts` 的记忆在 `setVolume` / `setOption` 里写，脚本派发事件也会写（场景表里目前没有声音相关的键，风险低）。

### P11（低）加载 / 准备中的反馈不全 —— §5.2

- 选雷暴 / 台风时天气变体后台编译（冷缓存约 5 / 9 s，README PERF-10），这段时间画面没变化，面板上也没有提示。
- 舱等「（准备中…）」、火车状态文字、地面精度状态格式各不相同。

## 5. 与 VOY-DEFAULT 的关系

- VOY-DEFAULT（`9da1be8`）的做法——URL `?voyage=0/1` 优先、`isTrusted` 才写 localStorage、URL 强制时不写——正是 §7.3 要推广的规则，已写进规范。
- 它合并后，**默认用户看到的就是 P1 的「接管」状态**，所以 UX-2 应该是它之后的第一个面板任务。
- 测量工具默认带 `voyage=0`，回归场景仍是连续航程关，所以 UX-2 的「回归场景逐位不变」验收可以成立。
