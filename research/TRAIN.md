# 日本火车（P8）· 设计研究

> 研究代理产出，2026-09-27。只是设计文档，没有改动 `src/`，也没有下载任何素材。
> 数字的标注方式：写了出处的是查过的；标「估」的是按几何或常识推算的；标「待核」的是记得但没有找到原文、实现前要核对的。
> 任务编号用 `TR`（Train Rail）前缀，避免和看板上的 T 编号撞车；协调者排进 `TASKS.md` 时可以改号。

## 0. 结论先行

1. **火车和飞机的难点位置正好反过来。** 飞机上，近处（舷窗）是静止的，远处靠大气藏拙。火车上，窗外 2–15 m 的东西每帧横移几十到几百像素，**本来就看不清**。真正要经得起盯着看的是 **30–500 m 的中景**：民居、稻田、电线杆和电线、树林。眼睛会自动追着这一段看（铁路眼震，即视动性眼震）。
   所以「近处是真实度的起点」这条铁律，在火车上要拆成两半：
   - **静止的近处**（窗框、玻璃、遮阳帘、座椅）照飞机的标准做精。
   - **飞掠的近处**（电杆、护栏、道砟）不比细节，比**时间特征**：节奏对不对、拖影的形状和亮度对不对、有没有频闪。
2. **核心技术主张：把运动模糊当成各向异性的预过滤，写进程序化图案的着色公式里，而不是渲染完再做后处理。** 现有的 T08 / T43 已经在按「像素足迹的长轴」过滤细线。火车只要在长轴上再加一段「快门时间内的位移」`v·T/z`，电杆、枕木、稻行、隔音墙板、护栏这些周期图案就同时解决了模糊、锯齿和时间走样（车轮倒转效应）。这正对应铁律 2「锯齿 / 闪烁最高优先」。
3. **推荐的架构是三层混合，每一层用最适合它的技术**（§2）：
   - **近景「走廊解析层」**：全屏，在走廊坐标系里做射线与平面的解析求交，时间积分也是解析的。
   - **中景「实例化栅格层」**：民居、树、电杆本体用 three.js InstancedMesh 加 MSAA；电线仍然走解析画法。
   - **远景**：直接复用现有的地形、影像、大气、云。

   三层按离轨道的横向距离分带，按画家算法叠加，不需要深度合成。
4. **首发线路推荐**（§4）：
   - ① **JR 大糸线 松本—信浓大町（安昙野）**：水田平原、北阿尔卑斯作远景、单线直流电化、道口多。远景正好是我们最强的部分。
   - ② **JR 东海道本线 小田原—热海（根府川一带）**：线路在海边的崖上，海在下方远处，隧道多。隧道天然就是「遮挡切换」和换场的机会。
   - ③ 江之电放到后期，算「最终考验」：房子近在咫尺，还有路面段和停站，近景是静止的。
5. **第一期（TR01–TR08）的目标**：盛夏的白天，大糸线，车速恒定 90 km/h，不停站。画面里要有：窗框、双层玻璃倒影、接触网支柱的掠过、路边电杆和起伏的电线、绿色稻田上风吹过的稻浪、散落的瓦顶民居、远处的阿尔卑斯和积云；声音上有「ガタン、ゴトン」。
   能尽快看到「像坐在日本电车里」，靠的是四样东西：**节奏**（电杆、声音）、**中景的层次**、**真实远景**、**窗框**。停站、道口、隧道、季节、夜景都放到第二期。
6. **最大的风险**（§8）：
   - 中景民居和树的「程序化痕迹」：规则、重复、像 SimCity。
   - 相机贴地后，地形求交和云步进的开销和走样会变化。
   - 近景解析层扛不住复杂结构（车站、跨线桥），只能靠分带和「用遮挡换场」绕开。
   - OSM 建筑轮廓覆盖不均，缺的地方要程序化补，补得不好就露馅。

## 1. 视角与难点

### 1.1 几何：每一层每帧移动多少像素

前提：竖直视场 50°、画面高 1200 px（`uTanHalfFov = tan 25°`，与 WONDERS §1.1 同一口径），一个像素约 7.27×10⁻⁴ rad。车速取 90 km/h（25 m/s），视线垂直于车行方向（这是最坏情况）。每帧屏幕位移 = `v·Δt / (z · 像素角)`：

| 横向距离 z | 典型物体 | 60 Hz（px/帧） | 160 Hz（px/帧）* | 看起来是什么（估） |
| --- | --- | --- | --- | --- |
| 2 m | 本线接触网支柱、护栏 | 287 | 107 | 一帧里一闪而过的竖条，只剩一道暗影 |
| 5 m | 对向线路的支柱、道口、路肩的草 | 115 | 43 | 拖影，还认得出「有东西过去」 |
| 15 m | 线路边的民居、竹林 | 38 | 14 | 模糊但认得出形状，追不上 |
| 50 m | 农道的电杆、民居、稻田 | 11.5 | 4.3 | **眼睛开始追得上：主舞台** |
| 150 m | 村落、树林边缘 | 3.8 | 1.4 | 清楚、细节丰富 |
| 500 m | 远处聚落、山脚 | 1.1 | 0.43 | 几乎是静止的画 |
| 2 km 以上 | 山、云 | < 0.3 | < 0.1 | 和飞机巡航时的远景一样 |

\* 160 Hz 按 README「rAF 间隔约 6.2 ms」推算，这是本机显示器的刷新率。

由此得到三条推论：

- **2–15 m**：远超可追踪速度，细节根本看不见。要保证的是**能量守恒的拖影**：平均亮度和颜色对，不频闪。
- **30–500 m**：每帧 1–12 px，眼睛会自动追这一段（铁路眼震）。被追住的物体在视网膜上是清晰的，所以这一段**不能加太多模糊**，又要有足够的细节。是否模糊要看运动量，建议快门系数按运动量分段：每帧超过约 30 px 用满快门，低于约 8 px 用四分之一快门（估）。
- **1 km 以外**：运动是亚像素的，现有管线（时间累积、各向异性过滤）可以照搬。

### 1.2 节奏：窗外的「时钟」

| 周期性元素 | 真实间距 | 出处 | 90 km/h 时的频率 |
| --- | --- | --- | --- |
| 接触网支柱（径间） | 约 50 m | [JRTT「電車線」](https://www.jrtt.go.jp/construction/technology/catenaries.html)：吊架线以约 50 m 间隔支撑 | 0.5 Hz，约 2 s 一根 |
| 吊弦（ハンガ） | 约 5 m | 同上 | 5 Hz，在窗里几乎看不见 |
| 路边配电杆 | 约 30–50 m，北海道最大到 60 m | [SWIFT 電柱の間隔](https://www.swift2016.co.jp/column/425/)（电力公司的约款各不相同） | 0.5–0.8 Hz |
| 定尺钢轨（接缝） | 25 m | [民鉄協 鉄道用語「レール」](https://www.mintetsu.or.jp/knowledge/term/16489.html)；[乗りものニュース](https://trafficnews.jp/post/79702) | 1 Hz，也就是「ガタンゴトン」的一个周期 |
| 枕木 | 约 0.6 m（估，25 m 钢轨按约 40 根算，待核） | — | 约 42 Hz，**超过 60 Hz 帧率的奈奎斯特频率 30 Hz，必然产生车轮倒转式的走样** |
| 插秧的行距 | 约 30 cm（估，常见机插行距） | — | 约 83 Hz，同样会走样 |

结论：**枕木、稻行、隔音墙板、栅栏在时间上都是欠采样的。** 只能用预过滤，也就是按「空间足迹 + 运动足迹」把频率高于奈奎斯特频率的成分衰减掉。靠后处理的运动模糊救不回来，因为走样在采样那一刻就已经发生了。

### 1.3 和飞机相比：哪些能复用，哪些必须新做

| 模块 | 复用程度 | 说明 |
| --- | --- | --- |
| 大气 LUT（Hillaire 2020）、太阳 / 月亮 / 星空、`astro.ts` | **原样复用** | 相机高度约 2.5 m，比现在 0.5 km 的下限还低。大气 LUT 本来就按相机高度参数化，要验证的是 0 km 附近的数值稳定性（TR03 验收里要测） |
| 边界层霾、谷地辐射雾（T18，`haze.ts`） | **原样复用，而且更重要** | 日本潮湿，安昙野清晨的雾、梅雨季的灰霾都是真实天气。「宁可有雾」在火车上是主力手段 |
| 体积云与天气（`clouds/*`） | 复用，要验证 | 从地面仰望积云是新的视角。近水平的视线在云层底下要走很远，步进可能变贵（参照 T33「有雷暴时开销与距离无关」）。云影图（T27）直接复用 |
| 地形与影像的 clipmap（`ground/*`） | 当远景复用 | 最细一级现在是 8 km / 1024 ≈ 7.8 m 一个纹素，只够远景用。要新增火车用的参数（更细的一级、国土地理院 DEM），还要设一个**最近求交距离**（约 300 m），近处交给走廊层 |
| 海面（`ocean.glsl.ts`，Cox–Munk + 12 个方向的波） | 在崖上看远处海面可以复用 | 根府川一带的海在下方几十米、几百米以外（估）。贴着海岸线的近处碎浪还做不了，所以选线时就避开 |
| 夜光、道路灯带（T08 / T43） | 远景复用 | 近处的路灯、道口的红灯要新做 |
| 曝光、局部适应、AgX、眩光 | **原样复用** | 窗外和车内分开测光的逻辑一样，隧道进出的明暗适应正好用得上 |
| 窗板光学（划痕、油污、水痕的折射） | 部分复用 | 玻璃变成大块平板双层玻璃（复層ガラス）。雨水的流向变成随车速斜向后流，要改流场 |
| 车内倒影（`cabin-reflect.glsl.ts`） | 思路复用、几何重做 | 夜里和隧道里，倒影是主角（§3.6） |
| 织物（`fabric.glsl.ts`）、座椅的距离场（`seats.glsl.ts`） | 织物复用，座椅重做 | 座椅面料（モケット）可以沿用经纬纱的做法 |
| 音效框架（`audio.ts`：频域噪声床、泊松事件、离线检查 `audio-check.mjs`） | **框架复用** | 新增按确定时刻排程的钢轨接缝撞击、隧道混响、道口声源的多普勒（§6） |
| 导演（`director.ts` 的遮挡排队切换、换原点） | **复用，而且更好用** | 隧道就是现成的「遮挡」，用来换原点、切数据块、换季节 |
| 颠簸（`flight.ts` 的 `updateTurbulence`） | 替换 | 改成车体振动模型：空气弹簧上下约 1–1.5 Hz、横摆约 0.5–1 Hz（估，待核），接缝撞击再加冲击 |
| **必须新做** | — | 线路数据烘焙；走廊坐标系与列车运动；近景走廊解析层；中景实例化层（民居、树、电杆）；电线的解析画法；稻田（分季节）；车厢；接缝节奏的声音；隧道、道口、桥梁、会车 |

## 2. 渲染架构

### 2.1 三种方案对比

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 全部光线步进（照现在的「窗外 pass」风格） | 近中景都写成距离场，在全屏 pass 里步进 | 和现有管线同构；解析抗锯齿好做 | 几千栋民居、树放不进距离场；步数爆炸；FXC 冷编译暴涨（README 坑点：循环、重函数）；「平时不走的分支也变慢一倍」（W00） | 否 |
| B. 全部栅格化（普通游戏的做法） | 所有东西都是网格，加 MSAA、速度缓冲、后处理模糊 | 物体数量几乎不受限；着色器小、编译快 | 细电线、电杆的边缘在高速横移时锯齿、闪烁严重；枕木、稻行的时间走样后处理救不回来；需要 MRT 输出速度，而 PERF-1 已经规定新程序尽量单输出 | 否 |
| **C. 三层混合** | 近：走廊解析层（全屏，解析求交 + 解析时间积分）；中：实例化栅格化（民居、树、杆的本体）加 MSAA；电线仍是解析画法；远：现有管线 | 每层用最擅长的技术；按横向距离分带就能用画家算法叠加，不需要深度合成；着色器程序各自独立，冷编译互不连累 | 分带的边界（跨线桥、车站）要特殊处理；程序数量 +3 | **推荐** |

### 2.2 走廊坐标系（火车模式的地基）

- CPU 端把线路中心线建成一条样条，参数是里程 s。离相机前后各约 2 km 的窗口内，按 1–2 m 的间隔烘焙成一张**走廊数据纹理**（例如 2048×4 的 RGBA32F，只占 1 个 sampler），每行存：
  - 中心线的位置与切向（相对于局部原点）；
  - 曲率、超高（カント）、纵坡；
  - 结构类型：路堤 / 路堑 / 桥 / 隧道 / 车站 / 道口；
  - 左右两侧的环境类别：水田 / 民居 / 树林 / 海 / 隔音墙；
  - 本段的支柱相位与种子。
- 着色器里把世界坐标换算成 (s, d, h)，即里程、横向偏移、高度。局部线路近似为「直线 + 常曲率」，这在 ±200 m 内误差很小（估）。
- 列车位置 s(t) 由速度曲线积分得到。相机 = 样条(s) + 车体姿态（偏航、超高带来的侧倾、振动）+ 头部。**超高**：在来线的最大超高常说是 105 mm（待核），1067 mm 轨距下约合 5.4° 侧倾，过弯时地平线的倾斜是很强的真实感线索。

### 2.3 近景走廊解析层（0–15 m，新程序 `rail-near`）

- **层平面法**：近景物体几乎都「薄且贴着走廊」，比如支柱排在 d ≈ 2.5–3 m、栅栏在 d ≈ 4 m、对向线路的支柱在 d ≈ 6 m（均为估值）。每一层是一个 d = 常数（或随 s 缓变）的竖直平面：
  1. 射线和平面解析求交，得到 (s, h)；
  2. 按 s 找到最近的一两个格子（支柱、栅栏桩……）；
  3. 在格子里对圆柱、方柱、横梁做解析覆盖。

  层数固定不超过 8，循环写成 `N + uLoopGuard`，每层是 O(1) 的，没有步进。
- **解析时间积分（运动模糊）**：在层平面上，快门时间内的位移是 Δs = v·T_shutter。宽度为 w 的柱子，其覆盖率 = 区间 [s₀, s₀+Δs] 和 [柱左, 柱右] 的重叠长度 ÷ Δs，再和空间足迹的帐篷核卷积（T43 的做法）。结果：
  - 拖影的亮度守恒；
  - 形状是真实的梯形；
  - 频闪不可能出现，因为这就是盒式时间滤波的精确解。
- **周期图案**（枕木、隔音墙板、栅栏、护栏桩）：用「空间足迹 + 运动足迹」的长轴，对周期函数做解析的盒式平均。等价于把高频成分乘上 sinc，频率超过奈奎斯特的部分自然衰减成平均色。
- **电线**：沿车行方向的线（馈线、架空地线、配电线）在运动方向上**不会被模糊**，所以要锐利。它们是细线，按 T43 的帐篷核做解析抗锯齿，线的高度用悬链线（抛物线近似）h(s) = h₀ − 4f·u(1−u)（u 是径间内的归一化位置，f 是弧垂，估 0.3–1 m）。
  坐着从侧窗看，本线的接触线在车顶正上方，**看不见**。能看见的是：
  - 支柱上的腕金和馈线；
  - 复线上对向线路的吊架；
  - **路边配电线随电杆一起上下起伏**，这是最标志性的车窗画面。

  配电线离得较远，d ≈ 10–50 m（估），归到中景层去画，但画法相同。
- **光照**：近景物体都在 100 m 以内，太阳的可见度（地形遮挡、云影）在 CPU 上按列车位置算一次，作为 uniform 传进来。**不在这个程序里再调用 `cloudShadow` / `keyLight` 这些重函数**，遵守「重函数只一个调用点」。
- **输出**：预乘 alpha 的 HDR，叠在中景和远景之上。

### 2.4 中景实例化层（15–500 m）

- 用 three.js InstancedMesh 画民居、仓房、树（体块加噪声法线）和电杆本体，4×MSAA，写到带深度附件的单输出目标里（不用 MRT，见 README 坑点 PERF-1）。
- **速度不需要单独存**：火车的相机运动 = 平移 + 缓慢偏航，屏幕速度可以从深度加相机运动解析推出来，所以后处理模糊只要读深度（McGuire 2012 的重建滤波的简化版，只沿一维水平方向收集，样本数 `12 + uLoopGuard`）。快门系数按 §1.1 的分段规则。
- 数据：
  - 实例放置按 500 m 一块，在 Worker 里生成（照 `road-raster.worker.ts` 的模式）。
  - 车速 130 km/h 时，大约 14 s 才需要一块新的（估），CPU 压力很小。
- 中景的地面（稻田、旱地、道路）不是网格：用走廊解析层的同一套「地面平面 + 田块哈希」画出来，也就是 d 在 15–500 m 的一个地面带。民居网格在它上面按深度遮挡。**地面带不能用网格**的原因：田块的边（畦畔）在掠射角下就是一条条细线，需要解析抗锯齿（T08 / T43）。

### 2.5 远景（500 m 以外）

- 复用现有窗外程序，但做成 `#define RAIL` 的**变体程序**，不在默认程序里加分支（W00 教训：平时不走的分支也会让程序变慢一倍）。变体里去掉交通、奇观、岛屿、宝光这些火车用不到的东西，腾出 sampler。窗外程序现在是 16/16 满的。
- 地形求交设最近距离约 300 m（估），在这个距离把中景地面带和地形接起来。山脊上的杉林轮廓（日本山地最典型的锯齿状天际线）在 1–5 km 外只有一两个像素宽。建议在高度场上加一层按像素足迹淡出的「林冠粗糙度」，而不是去种树。

### 2.6 各层怎么衔接

- **分带叠加**：远 → 中（深度测试）→ 近（alpha 叠加）。
- 分带之间的过渡不能有硬边：在 d 的边界附近 ±20% 的范围内，两边同时画、交叉淡化。按 s 分格的内容要放在格子中段，离格子边留出余量（照 T42 的坑点）。
- **跨带的结构**（跨线桥、车站雨棚、隧道口）：不要硬做成跨层物体，改用「事件」处理，在 §3 里给出技巧。

## 3. 近景与中景内容

### 3.1 接触网与支柱

- 真实参数：
  - 径间约 50 m（JRTT）；
  - 在来线接触线离轨面 5 m 以上（[日本鉄道電気技術協会「技術基準省令 第6章」](https://www.rail-e.or.jp/library_archive/ch06)，隧道、桥下除外）；
  - 吊弦间隔约 5 m（JRTT）；
  - 大都市圈周边的 JR 在来线多为直流 1500 V（[OSM wiki：OpenRailwayMap Tagging in Japan](https://wiki.openstreetmap.org/wiki/OpenRailwayMap/Tagging_in_Japan)）。
- 形态：
  - 单线是单侧的支柱加可动腕金；
  - 复线常见跨两线的门形或 V 形梁（ビーム），也有各线外侧独立的支柱；
  - 材质有混凝土柱（灰白、圆锥形略收）和钢管柱（锌灰），**同一线路上会混用**，这是随机性的来源。
- 节奏的随机性：
  - 径间不是等长的。弯道上要缩短（受拉出值限制，估 30–40 m）；道口、桥、车站前后也会调整。
  - 不能写成 `s mod 50`：在烘焙数据时按曲率生成支柱位置，再加 ±2–4 m 的抖动（估）。
- 从窗口能看到的部分：离窗约 2 m 的柱子，柱顶在窗上沿以外。所以它是**贯穿整个窗高的暗竖条**，上面带腕金的一小段斜影。**支柱的影子扫过车厢内部**（§5.3）比柱子本身更有感染力。

### 3.2 路边配电杆与电线（「上下起伏的电线」）

- 配电杆高约 12 m 级（1/6 埋入地下），间距 30–50 m（[電柱図鑑](https://denchu-zukan.com/zukan/denchu/pole-dimensions)、SWIFT）。杆上有高压三线、低压线、通信线（估），还有变压器罐、支线和拉线。
- 真实感的来源：
  - 电线在杆之间下垂；和铁路平行的农道上的电线，随列车前进在窗里有节奏地「下沉、上扬、再下沉」。
  - **杆距和支柱径间不相等**，两种节奏互相错开，这就是「随机性造就真实」。
- 数据：OSM 里日本的 `power=pole` / `power=minor_line` 很稀疏（估）。所以按 OSM 道路（`highway=*`）程序化放置：沿道路一侧放杆，偶尔过路换边，每 N 根有一根挂变压器。

### 3.3 稻田（按季节）

- 田块几何：
  - 平原上经过圃场整备的标准区画常见 30 m × 100 m（估，常见 30 a 区画，待核）；
  - 畦畔高约 30 cm、宽约 30–50 cm（估）；
  - 田块边界从 OSM 的 `landuse=farmland`（及 `crop=rice`）多边形或国土数值情报的土地利用细分网格（100 m 网格，含「田」这一类，见 §4.3）里取遮罩，块内再按道路和水渠的方向做沃罗诺伊 / 网格细分，每块的朝向、行向、生长期略有差异。
- 季节（长野、关东的大致农时：4 月下旬到 5 月灌水，5 月到 6 月插秧，9 月下旬到 10 月收割；见 [UMM 農業](https://ummkt.com/blog/3410)、[全米販 田植え時期](https://www.gohansaisai.com/fun/entry/detail.html?i=784)）：

| 季节 | 画面 | 做法 |
| --- | --- | --- |
| 灌水、插秧（4 月下旬–6 月） | **水镜**：倒映出天空、云、阿尔卑斯的雪峰；秧苗是一行行稀疏的小绿点 | 掠射角下菲涅尔反射率很高。**技巧**：命中水面的像素，先把视线按水面镜像，再走**同一个** `outsideRadiance` 调用点（远景和倒影互斥，不增加重函数的调用点）；近景层对镜像后的射线再求交一次。秧行是周期图案，按 §2.3 预过滤；风吹起的涟漪用小风速的 Cox–Munk 方差打散倒影 |
| 盛夏（7–8 月） | 浓绿、及膝到齐腰的冠层；**风吹过去的稻浪**（亮暗条带在田里移动） | 冠层当表面画：各向异性的光泽（叶片的朝向）× 移动的低频噪声。稻浪是低成本高收益的真实感线索 |
| 秋收（9–10 月） | 金黄、稻穗低垂；长野一带有**はざかけ**（晾稻架） | 颜色曲线按日期插值；晾稻架是中景的实例（细长架子挂满稻束） |
| 冬（11–3 月） | 稻茬、灰褐色；长野北部有积雪 | 稻茬行按预过滤处理；雪直接改地表反照率，加雪霾 |

### 3.4 民居

- 类型（估，按地区挑权重）：
  - 老式农家：入母屋式屋顶，黑色或银色的熏瓦（いぶし瓦），常带仓（白墙、黑色腰壁）和屋敷林；
  - 现代住宅：两层、外墙挂板、平板瓦或金属屋面；
  - 农用小屋、塑料大棚。

  地区差异（例如岛根的红色石州瓦、北陆的釉面瓦）用来做「这是哪里」的记号。屋顶颜色、朝向、有没有太阳能板都要随机。
- 几何：从 OSM 建筑轮廓挤出。日本很多市町村导入了基盘地图信息，所以有轮廓，但覆盖不均（估）。屋顶按轮廓长轴生成切妻 / 寄栋 / 入母屋，屋檐出挑 0.5–0.9 m（估）。缺轮廓的「建物用地」网格里程序化补点，间距、朝向都随机，避免整齐排列（WONDERS 的城市网格教训、W02 的街网教训）。
- 材质要克制：瓦的纹理在 50 m 外只剩一两个像素的横向细纹，要按足迹淡出成均匀色，不能出摩尔纹。窗户白天是暗的，傍晚偶尔亮一盏暖灯。

| --- | --- | --- |
| 道砟、枕木、钢轨（往下看时） | 近 | 灰褐色道砟加上钢轨头的一线亮光；枕木按 §1.2 预过滤 |

### 3.6 用「技巧」回避做不精细的部分（火车版的「低空用雾遮」）

| 难点 | 技巧 | 代价 |
| --- | --- | --- |
| 2–15 m 的物体细节 | 解析的运动模糊，只保留节奏和平均色 | 几乎没有；这是物理上正确的做法 |
| 复杂结构（车站、跨线桥、隧道口） | 全部放到**隧道 / 隔音墙 / 路堑之后**再出现；第一期不停站，只以特急通过的速度掠过车站 | 线路选择受限 |
| 数据切换、换原点、换季节 | 在**隧道里**做，复用导演的遮挡排队切换（`director.ts`） | 需要线路上有隧道（东海道线很多，大糸线的平原段少） |
| 夜景 | 开灯后**窗玻璃上是车内的倒影**，窗外只剩灯点、道口红灯、远处的聚落夜光。真实的夜车本来就是这样 | 要做好车内倒影（复用 T24 / T34 / T42 的经验） |
| 隧道内部 | 窗外全黑加隧道灯的亮线拖影（间隔估 20–50 m，待核），窗变成一面镜子 | 几乎没有；隧道是「近景最便宜」的场景 |
| 天气 | 梅雨、雾、雨：雨滴在窗上斜向后流（受风压和车速控制），能见度下降，远景自然就藏起来了 | 要改窗上水痕的流场 |
| 低清的地面影像 | 影像只当遮罩（田、林、建成区），不当颜色；颜色一律由程序化材质按季节生成 | 影像的时相（拍摄季节）不再影响画面 |
| 会车（すれ違い） | 对向列车在 1.5–2 m 外以 200 km/h 的相对速度掠过，画面一片被模糊的车体墙（不锈钢加色带），同时有一声轰响和一次压力冲击 | 只要一个近景层事件：一整片带窗户节奏的平面 |

## 5. 车厢

### 5.1 选哪种车厢

- 通勤车的长条座椅（ロングシート）看的是对面窗户，中间隔着站着的乘客，不适合「漫无目的看窗外」。
- 推荐**特急的普通车或绿色车（グリーン車）靠窗座位**：
  - 大块固定窗、窗边有小台面、可以升降的遮阳帘、斜倚的座椅、行李架上有下照灯、天花板有间接照明。
  - 这也符合用户对舱内定下的「高级、先进、奢华的真实感，不要脏旧廉价」。
- 第二个选项是地方线的四人对坐（ボックスシート），更有「旅情」，但偏旧，和审美定位有张力。**建议列成选项交给用户**，默认用特急。
- 不照搬任何车型的涂装、标志、座椅花纹（商标和外观设计的风险），做成「日本特急风」的通用设计。

### 5.2 真实感要点

| 部件 | 要点 | 复用 |
| --- | --- | --- |
| 窗 | 双层玻璃（两层倒影，间距约 1–2 cm，估）；UV 隔断玻璃的淡绿色调；窗框是铝型材加橡胶密封条；窗宽约 1.0–1.6 m、高约 0.8–1.0 m（估，按车型各异） | 窗板倒影、划痕、指纹的做法；T24 以来的倒影 |
| 窗台 | 窄台面（可放饮料），在视野下沿；阳光照在台面上的光斑要跟着车的朝向转 | 窗光斑的解析照度 |
| 遮阳帘 | 带横向肋条的卷帘或百褶帘，可停在任意高度（フリーストップ）；半透光时隔着帘能看到外面的剪影 | 织物 |
| 座椅 | 前排的椅背和头枕套进入视野边缘；面料是モケット或皮革 | `fabric.glsl.ts`，座椅的距离场重做 |
| 行李架 | 窗上方，金属或玻璃；绿色车带下照灯 | 倒影里的行李架（T42） |
| 灯光 | 天花板的 LED 条灯（冷白或暖白）；夜里主导窗上的倒影 | 车内色适应（T28） |
| 车体振动 | 画面随车体轻微晃动；接缝处的小冲击；过弯时侧倾 | 颠簸的框架 |

### 5.3 光影线索（性价比高）

- **支柱和树的影子扫过车内**：阳光从侧窗照进来，每根支柱在座椅和台面上投一道快速扫过的影子（0.5 Hz 的节奏）；树丛则投出一片闪烁的碎光（木漏れ日）。
  做法：车内的光斑再乘上一个一维的「窗外遮挡函数」，从近景层的同一份数据在 CPU 上按时间算出来，作为 uniform 传进去。成本很低，真实感很强。
- **进出隧道的曝光**：人眼的明暗适应（现有模型：亮适应快、暗适应慢）加上车内灯。隧道里，窗外变暗，车内倒影浮现出来。

## 6. 音效

### 6.1 「ガタン、ゴトン」：由几何推出节奏

- 前提：
  - 定尺钢轨 25 m；焊成 200 m 以上的叫长钢轨，长钢轨上没有接缝声（[民鉄協](https://www.mintetsu.or.jp/knowledge/term/16489.html)、[マイナビ 鉄道トリビア](https://news.mynavi.jp/article/trivia-8/)）。
  - 车长约 20 m（E233 系的连结面间距 20,000 mm，[Wikipedia](https://ja.wikipedia.org/wiki/JR%E6%9D%B1%E6%97%A5%E6%9C%ACE233%E7%B3%BB%E9%9B%BB%E8%BB%8A)）。
  - 台车中心距 13.8 m（E231 系，[Wikipedia E231 series](https://en.wikipedia.org/wiki/E231_series)）。
  - 轴距 2.1 m（常见值，待按车型核对）。
- 算法：每根车轴（车内坐标 a）经过接缝 J_k 的时刻是 t = (J_k − a)/v。一个钢轨长 L 内，每根轴的撞击相位是 (−a mod L)/v，音量按到听者的距离衰减。
- 例：听者在车厢中部，自己车厢的轴在 ±5.85、±7.95 m，相邻车厢最近的轴在 ±12.05、±14.15 m。L = 25 m，90 km/h 时一个周期 1.0 s，其中：
  - 0.23 s 和 0.32 s：本车一个台车「タタン」（响）；
  - 0.43–0.57 s：相邻车厢的四下（较轻）；
  - 0.68 s 和 0.77 s：本车另一个台车「タタン」（响）。

  两组「タタン」之间相隔 11.2 m 和 13.8 m，**不对称**，这正是「ガタン、ゴトン」的韵味所在。这个结论是由几何推出来的，要用录音的节奏核对。
- 真实的变化：
  - 接缝的实际间距有误差；道口、道岔、伸缩接头附近有短轨；
  - 左右两轨的接缝是对齐的（相对式）还是错开的（相互式），决定每一下是一声还是两声（待按线路核对）；
  - 长钢轨区间整段没有接缝声，只剩滚动噪声；
  - 桥上会有空洞的轰鸣。
- 合成：
  - 每一下撞击 = 一段很短的滤波噪声冲击，加上车轮和钢轨的几个共振峰（频率待定，按录音的频谱估），经车体的低通（隔着地板）后进入噪声床。
  - 滚动噪声：连续宽带，声级约随 30·log₁₀(v) 变化（Thompson, *Railway Noise and Vibration*, 2009 的经验关系，待核）。
  - 电机：牵引电机的音调和车速成正比（加上 VVVF 变频器载波的变化）。做成通用音色，不模仿特定车型的「名曲」。

### 6.2 道口警报：多普勒

- 规格：旧国铁规格是 700 Hz ±15 与 750 Hz ±15 两个音交替（接近小二度，刻意做成不和谐音），每分钟 130 ±5 次；各公司不同，例如小田急是 450 / 550 Hz（[Wikipedia 踏切警報機](https://ja.wikipedia.org/wiki/%E8%B8%8F%E5%88%87%E8%AD%A6%E5%A0%B1%E6%A9%9F)、[鉄道総研 人間科学ニュース](https://www.rtri.or.jp/rd/news/human/human_201511.html)）。
- 多普勒：90 km/h 时，靠近阶段的频率乘 c/(c−v) = 1.079（约升 1.3 个半音），离开阶段乘 c/(c+v) = 0.932（约降 1.2 个半音）。700 / 750 Hz 靠近时约为 755 / 809 Hz，离开时约为 652 / 699 Hz。道口离听者 3–5 m（估），所以这个音高的跌落在约 0.3–0.4 s 内完成。
  音量上：远处约 10 s 前就开始隐约听见（估）；经过的瞬间最响；之后迅速远去。整体再乘上窗户的隔声（高频衰减得多）。
- 做法：一个 PeriodicWave 声源，按几何每帧计算频率和增益（10 Hz 节流，照 `audio.ts` 的做法用 `setTargetAtTime`）；道口红灯的闪烁和声音同相。

### 6.3 隧道

- 真实：列车进入隧道时产生压缩波，车内会「耳朵一闷」（耳つん）；新干线乘务员室里测到过 5 s 内 9.9 mb 的气压变化（[杏林医学会雑誌](https://www.jstage.jst.go.jp/article/kyorinmed/13/4/13_KJ00003279650/_article/-char/ja/)，[鉄道総研 トンネル内圧力変動](https://www.rtri.or.jp/rd/division/rd51/rd5120/rd51200106.html)）。在来线速度低，变化要小得多（估）。
- **技巧**：扬声器放不出次声，所以用心理声学来表现「耳压」：
  - 进洞的一瞬，一声低沉的「ボッ」冲击；
  - 随后 1–2 s 里，高频被暂时削掉（像耳朵被捂住），再慢慢恢复；
  - 隧道里整体变响、带混响（估 +5–10 dB）；
  - 出洞时混响突然消失，声音「打开」。

  混响用合成的冲激响应（ConvolverNode）或反馈延迟网络，不用录音。

### 6.4 车内广播（只做示意）

- 不录制、不采样任何真实广播。
- 提示音：选公有领域的旋律（例如《鉄道唱歌》1900 年，作曲者多梅稚 1920 年去世，按日本的保护期已进入公有领域，待核），自己编配、合成。
- 人声：做成**听不清内容的广播腔喃喃声**（带通噪声加共振峰包络，模拟音节节奏），面板上用字幕显示「次は 信濃大町」这类事实信息。可选：浏览器的 ja-JP 语音合成，但它输出不进 Web Audio 图，没法加车内滤波，所以列为可选。

### 6.5 会车、桥梁

- **会车**：对向列车以约 200 km/h 的相对速度掠过，一次宽带的轰响和压力冲击，持续时间 = 对向车长 / 相对速度，10 节编组约 3.6 s（估）。和画面上的车体墙同步。
- **钢桁梁桥**：低频轰鸣增强，接缝声的音色变「空」。

## 7. 性能与编译

按本项目的约束逐条评估：

| 约束（README 坑点） | 对火车模式的影响 | 建议 |
| --- | --- | --- |
| FXC 展开常量上界的循环 | 近景的层循环、单元格邻居循环、模糊的收集循环 | 全部写成 `N + uLoopGuard`；层数不超过 8，邻居 2–3，收集 12 |
| 重函数只一个调用点 | 水镜要看到远景的倒影；近景要受光 | 水镜用「先镜像射线、再走同一个调用点」；近景的太阳可见度由 CPU 按列车位置算好，作为 uniform 传入 |
| 循环里不要做「三角函数 → 矩阵 → normalize」（T41） | 走廊坐标换算 | 在循环外按像素算一次局部坐标系，循环里只做线性组合 |
| 16 个 sampler | 窗外程序已满 | `RAIL` 变体去掉飞机专用的纹理；近景程序单独计数，约需 6 个：走廊数据、噪声 ×2、透射率 / 天空辐照度 / 空气透视 LUT |
| 单输出程序（MRT 首次绘制会同步重编，PERF-1） | 中景要深度 | 深度附件加单色输出；速度由深度解析推出，不存速度缓冲 |
| 「平时不走的分支也变慢」（W00） | 飞机与火车两套逻辑 | 火车全部做成**独立的程序或 `#define` 变体**；飞机的默认程序预处理后必须和现在逐字相同（写进验收） |
| 改哪个文件重编哪个程序（SC-5） | — | 火车代码放 `src/rail/*`，不拼进飞机的程序 |

**帧预算**（估，1600×1200，RTX 5090 量级。要保 160 Hz，整帧应在 6 ms 左右）：

| 部分 | 预算 |
| --- | --- |
| 远景（窗外变体，相机贴地，含云） | ≤ 2.5 ms（要实测：近水平视线在云下走得长，地形求交在掠射角下步数变多） |
| 中景栅格（约 1 万个实例，4×MSAA） | ≤ 1.0 ms |
| 中景后处理模糊 | ≤ 0.3 ms |
| 近景解析层 | ≤ 0.8 ms |
| 车厢合成 | ≤ 0.8 ms |

**冷编译**：新增三个程序（近景、中景、模糊）都应该很小。模糊和中景是普通着色器；近景没有步进，估计离线 FXC 几秒以内。窗外的 `RAIL` 变体约等于现有的窗外程序（约 7 s）。它们和其他程序并行编译，按「关键路径是云程序」的现状，总时长不应明显增加（要在 TR03 / TR04 里用 `shader-budget.mjs` 与 `dev-browser.mjs cold` 实测）。

**CPU**：走廊数据纹理每约 100 m 滚动更新一次（小纹理的部分上传）；实例块在 Worker 里生成；声音的撞击事件按 s 预排 0.3 s（照 T11「只预排 0.3 秒」的经验）。

## 开发体验反馈

- **哪里慢**：README 有 90 KB，Read 工具一次读不完，要分三次读，前后约占总时间的两成。
- **哪里卡**：
  - README 的「坑点」一节是按时间堆的长列表。研究代理要的是「约束清单」（sampler 数、循环、重函数、单输出、变体），只能自己从几十条里摘。
  - 找「相机高度下限」「FOV」「clipmap 最细级别」这类数字要去翻源码。
- **怎么绕过的**：用 grep 定位到 `index.html` 的高度滑块、`clipmap.ts` 的 `GROUND_BASE_KM`、`view.glsl.ts` 的 FOV。
- **希望有**：
  - README 顶部有一张「硬约束速查表」（着色器编译：常量循环 / 重函数 / 16 sampler / 单输出 / `#define` 变体；各程序当前 sampler 数；帧预算），每条链接到对应坑点。
  - `research/` 里有一份「关键参数表」：视场、分辨率、clipmap 级别、LUT 范围、相机高度范围。研究和实现代理都能直接引用，不用每次重新推算。
