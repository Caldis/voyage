## 0. 结论先行

1. **产出很高，瓶颈也换了地方。** 一天合并 28 项（写作期间 W03 在 17:00 合并，共 29 项），派发到合并的中位数约 45 分钟。第 2 波的头号瓶颈是浏览器锁，今天已经没人提。现在最费时间的有三件事：每个任务都在重写测量脚本（今天 `handoff/` 新增 **122 个**脚本文件）；冷编译的计时在满载机器上判不准；逐像素对比经常出假信号。
2. **DX-04..08 做的工具，只要派发时已经合并，基本都会被用上。** 用不上的原因主要在时机：DX-08（freeze / probe / flicker / passes / `--baseline`）15:59 才合并，今天大部分任务在那之前就派出去了。另外有三处缺口，逼得代理继续手写脚本：`compare` 只输出亮度，`--scene` 的 JSON 在 shell 里很难转义，shader-budget 不能做「单项改动的变体对照」。
3. **不做独立审查已经漏了真 bug。** 今天 28 项里没有一项派过独立审查代理。至少两个代码 bug 是后面的任务顺手发现的：T08 的道路宽度解码写错，一个多小时后被 T43 发现；T35 的压纹斜率被 `slope =` 整个覆盖，4 小时后被 T47 发现。还有一次越界改动：T47 改了热点 `scene.ts` 和同时属于 T48 的 `exposure.ts`。本报告第 3.4 节给出「什么情况下必须恢复独立审查」的判定条件。审查可以只看 diff、不开浏览器，所以很便宜。
4. **冷编译在一点点往上涨，没人负责兜底。** 每项都判「≤ 门槛」，可门槛本身就有 5 / 10 / 15 / 20% 四种说法，也没有累计账本。主分支真冷启动大约从 13.2 s（08:46，PERF-1 合并时）涨到 18.1–18.3 s（15:01，T44+T45 的测量）。之后 T12 没测准，T47、T48 各贴线几个百分点。这里面有多少是机器负载造成的，要等性能工程师在机器空闲时复测。

## 3. 组织设计

### 3.1 并行度

- 今天实际同时有 5–6 个实现代理，加上协调者和按需派的研究代理 / 美术总监。吞吐量很高（28 项），但饱和的迹象都已经出现：

### 3.2 插单 / 主干比例

- 路线图新功能（T08、T09、T11、T12、T17、W00、W01b、W02、W03、T19b 等）约 11 个。

### 3.4 「看图退回一次、自己核验合并、不另派审查」漏了什么

SOP 第 5 节要求每个任务都派独立审查，「测试的节制」只放宽了**返工后的复审**。今天 28 项没有一项派独立审查，这是对 SOP 的实质性偏离。

**已经发生的漏检**（证据）：
1. T08 的宽度解码：编码是 `128 + 宽度×127/40`，着色器按 `A·2−1` 解码，「不亮」的 128 变成 0.16 m。13:15 合并，T43 发现（handoff/T43.md 第 17 行）。
2. T35 的亚麻压纹斜率被后面的 `slope = …` 整个覆盖。12:16 合并，T47 发现（handoff/T47.md 第 23 行）。
3. T47 越界改了热点 `scene.ts` 和 `exposure.ts`，而 `exposure.ts` 当时正是在途 T48 的归属文件。协调者「已知情」后合并，没有第二双眼睛看两个任务在同一个文件上的语义是否冲突：一个是倒数混合，一个是色度保持。
4. 语义契约变了却只靠截图核验：T41 把窗外输出的 alpha 改成「1 + 可见点星量」（TASKS 里特意注明「改窗外输出别写回 1」）；T45 改云步进提前终止的规则（全局）；T46 把中间缓冲换成 32 位浮点。
5. T12 自报「浏览器真冷启动未测准」，照样合并。

两个 bug 都是**读 diff 一眼能看出**的类型（赋值写成覆盖、编解码公式不对称），看截图查不出来。

**什么情况下必须恢复独立审查**（满足任一项即派；审查只读 diff 加对照截图，10–20 分钟，不开浏览器也可以）：
- (a) 改动涉及**编码 / 解码、缓冲格式、精度、输出通道语义**等跨模块契约；
- (b) 碰了**热点文件**，或**越出归属范围**；
- (c) 自报冷编译「贴线」「未测准」，或冷编译增量 > 5%；
- (d) 新增程序 / 变体 / 循环 / 重函数调用点；
- (e) 全局规则变动（如云步进终止条件、曝光混合方式）；
- (f) 同一波里另一个任务也在改同一个文件。

纯参数调整、只在一个 `*.glsl.ts` 内部的外观微调、纯文档 / DX 工具，可以继续「协调者看图合并」。

### 3.5 冷编译「贴线」累积由谁兜底

- 现状：T45 +5.7%，T44 +4.4%（合计 +10.3%）；T12 没测准；T47 的舱内程序约 +0.4–5%；T48 的曝光合成程序 +3–6%；W01b 窗外程序 +15%（离线）；T17 窗外程序 +20%（离线，被并行掩盖）；W02 云间层变体 +8–10%。每一项单看都「≤ 门槛」，**没有账本，也没有 owner**。
- 真冷启动的读数（交付报告里「主分支」一栏，d3d11）：13.2 s（08:46）→ 14.0–15.2（T09，约 12:30）→ 16.2–17.3（T17 / W00，约 13:40）→ 18.1–18.3（T44+T45，15:01），**这一天约 +37%**。测量时的机器负载各不相同，所以这是**待复测的假设**，不是结论。
