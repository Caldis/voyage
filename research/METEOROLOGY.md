## 0. 结论先行

1. **单层云是最大的缺口**，这是结构问题，调参数补不上。航路上最常见的画面是「脚下积云或层积云，头顶一层卷云或卷层云」（WMO 称为 *duplicatus*，即多层并存）。现在全场只有一个云型，卷云和积云互斥，锋面云系、晕和幻日底下的积云、暖锋前「卷云 → 卷层云 → 高层云」的递进都画不出来。
   T17 的 22° 晕会漏到更低的云上，根子也在这里：晕没有一层属于自己的冰云可以挂。
2. **天气场的气候倾向有几处和东亚的真实气候相反**（[实测] 统计，附录 A）：
   - 1 月日本海 67% 的时间是「晴空」，北海道 73%。真实情况是冬季风寒潮把整片日本海铺满雪云街，日本海一侧阴雪。
   - 1 月长江中下游 53% 晴空、层积云 0%。真实情况正相反：青藏高原下游的中国东部是全球唯一以**陆上冷季层云**为主的区域（Klein & Hartmann 1993），2 月和 10 月是两个峰值。
   - 7 月华北 71% 晴空，可 7 月下旬到 8 月上旬恰恰是华北雨季（「七下八上」）。
   - 锋面带 8 月还停在 33°N，活跃度 71–96%，而梅雨在 7 月中下旬就结束了。1 月冲绳以东 150 km 内有雷暴的时间占 23%。
   - 台风每年约 60 个，是气象厅平年值 25.1 个的 2.4 倍；5–11 月各月差不多平均，真实情况是 8 月最多（5.7 个）、9 月其次（5.0 个）。
3. **风只是个常数，一处都没用上**：高空风方向 `uUpperWind`、卷云风 `HIGH_WIND`、云街低层风 `LOW_WIND` 在全场、全年都是同一个值，海面风速恒定 7 m/s。所以积雨云砧的朝向、卷云丝缕、云街、海浪、颠簸之间没有因果联系。东亚是冬季急流最强的地方（日本上空），夏季华南高空吹东风，砧该往西吹，这些都表现不出来。
4. **缺几个东亚航线上「有名、常见又好认」的天气景观**：日本海冬季雪云街 / 寒潮开放单体、中国东部冬季层云海、黄海和三陆的海雾、富士山的笠云 / 吊るし雲（荚状云）、春季黄沙、梅雨锋的层状云系、午后对流塔的生长过程。这几项大多**只需要改天气场**，或只加一个按需编译的变体。
5. **接真实天气数据在技术上可行，许可也清楚**。首选 **Open-Meteo**：数据 CC BY 4.0，非商业免费，每天 1 万次；实测返回 `Access-Control-Allow-Origin: *`，浏览器可以直接请求；能拿到低 / 中 / 高三层云量、CAPE、冻结高度、能见度、250 hPa 风、300 hPa 湿度。按日期重放用它的 Historical Forecast API（实测 2021-07-15 的高空变量有值）。
   ERA5（2025-07-02 起改为 CC-BY）和 GFS / ICON 适合离线烘焙。METAR 的官方 API **不允许跨域**，只能走代理。气象厅向日葵云图瓦片实测允许跨域，但那是没有公开文档的内部接口。
   融合原则：**数据只给 ≥ 50 km、≥ 1 小时的大尺度，程序化负责小尺度**。导演的「借遮挡切换」机制保持不变。

**推荐先做的 5 项**（按「真实感和体验的提升 × 1/工作量」排序，编号见 §4）：

| 序 | 编号 | 内容 | 改哪里 | 工作量 |
| --- | --- | --- | --- | --- |
| 1 | **W10** | 天气场气候态校准：冷季中国东部层云、冬季日本海寒潮雪云街、梅雨锋季节时间表、副高晴空、台风频次 / 月份 / 两类路径 | 只改 `weather.ts` | S–M（约 1 天） |

### 1.2 云属 / 云种覆盖（对照 [WMO] 十云属）

| 云属 | 覆盖情况 | 差距（按真实感排序） |
| --- | --- | --- |
| 卷云 Ci | ✓ 毛卷云 / 钩卷云近似（顺风丝缕、马尾） | 只能单独出现；缺密卷云 *spissatus*（积雨云砧残留的厚块）、脊状 *vertebratus*、辐辏状 *radiatus*（从地平线一点散开的平行带）；丝缕方向被常数风锁死 |
| 卷积云 Cc | ✗ | 细小的鳞片 / 波纹，常见于锋前。可以作为高层薄云层的一种纹理，成本低 |
| 卷层云 Cs | ✗ | **晕的载体**，锋前最典型。乳白的薄幕、太阳周围有晕、地面阴影变淡。T17 的晕现在只能挂在「卷云」上，挂不到 Cs 上 |
| 高积云 Ac | ◐ 只有一种（换了高度的层积云噪声） | 缺荚状 *lenticularis*（山地波）、堡状 *castellanus*（中层不稳定，午后雷暴的前兆）、絮状 *floccus*、波状 *undulatus*、透光 / 蔽光、雨幡 |
| 高层云 As | ✗ | 几公里厚的均匀灰幕，太阳像隔着毛玻璃。锋面云系的主体；**巡航高度常常就在它的顶部或里面** |
| 雨层云 Ns | ✗（只在台风眼壁和雨区里隐含着有） | 锋面降水的主体：云底低而模糊、下面挂着雨帘或雪帘、碎雨云 *pannus* |
| 层积云 Sc | ✓ 闭合 / 开放单体 | 缺日变化（清晨最厚），缺冷空气爆发从闭合单体转成开放单体的下游演变 |
| 层云 St / 雾 | ✗（下限是 1.0 km 的层积云） | 海雾、层云海（顶高 0.2–0.6 km，山和岛冒出来）、谷雾已有（T18）。从巡航高度俯看，海雾和层云是「白而平、边缘贴着海岸线」 |
| 积云 Cu | ✓ 淡积云 → 中积云 → 浓积云连续变化；云底絮团 | 缺碎积云 *fractus*、云街方向和尺度的物理依据、海上 / 陆上不同的日变化；缺**生长过程**（现在是 5 分钟取一次样、按限速插值，不是一座塔长起来） |
| 积雨云 Cb | ✓ 秃状和鬃状、砧（*incus*）、乳状（*mamma*）、雨幡（*virga*）、降水、上冲云顶 | 缺幞状云 *pileus*（塔顶的帽子，出现在上升最猛的时候）、缘状云 *velum*、弧状云 *arcus*（飑线的阵风锋）、滚轴云；单体生命周期（生长 → 成熟 → 消散后只剩砧）；多单体的新旧交替；夜间 MCS 大片层状云砧 |

WMO 的「特殊云」里有一项已经有了：人为云 *homogenitus*，也就是航迹云。缺的有卷积云里的**雨幡洞 *cavum***（飞机穿过过冷高积云后留下的圆洞，和航空很有关）、火积云 *flammagenitus*。

### 1.4 天气系统的空间结构（东亚）

| 系统 | 真实结构 | 现状 | 差距 |
| --- | --- | --- | --- |
| 暖锋 | 锋面坡度约 1:100–1:200。地面锋线前约 1000 km 起依次是 Ci → Cs → As → Ns，降水区在锋前约 300 km 以内 [教科书] | 「锋面带」只是提高层积云 / 高积云得分的一条纬度带 | **没有横截面**。以 850 km/h 穿越，完整序列约 70 分钟，1× 播放正好能体验一遍 |
| 冷锋 | 更陡（约 1:50–1:100），窄带积雨云或飑线；锋后干冷，开放单体积云，能见度极好 [教科书] | 飑线是独立哈希出来的，和锋面无关 | 锋后「突然澄澈」的对比没有 |
| 静止锋 / 梅雨锋 | 东西向，绵延数千公里。中国一侧是层状云夹嵌入对流，日本一侧偏层状；5 月到 6 月上旬是华南前汛期，6 月中到 7 月中是江淮梅雨和日本本州梅雨，7 月下旬北跳到华北（七下八上），9 月有秋雨锋 [气候，中国气象局和气象厅的季节划分，约数] | 纬度正弦随季节从 24°N 移到 33°N，1 月也 70–90% 活跃；8 月仍在 33°N | 时间表错位（§0 第 2 条）；缺梅雨锋的层状云 + 嵌入对流 |
| 温带气旋逗点云 | 逗头（Ns / As 的大片云盾）、干舌（晴空楔）、冷锋尾巴 [教科书] | ✗ | 大尺度结构，巡航时要几小时才看得出。可以作为锋面系统的组合 |
| 副热带高压 | 下沉气流、晴空或少量信风积云，夏季覆盖冲绳到日本南部 [教科书] | ✓ 信风积云，冲绳以东夏季约 77% | 合理。但 1 月这一带出现 23% 雷暴不对 |
| 冬季寒潮 / 冷空气爆发 | 冷空气流过温暖的对马暖流和黄海：离岸几十公里是无云区，然后是顺风的**云街**（滚轴对流，间距与边界层厚度之比约 2–4），云顶 2–4 km；日本海中部有 JPCZ（日本海寒带气团辐合带）的一条粗云带；日本海一侧阴雪，太平洋一侧晴 [气候、气象厅解说，教科书；比例为量级] | 1 月日本海 67% 晴空，积云族在冬季被压成 0 | **现在最大的气候错误**，而且非常上镜（ICN / FUK / KIX ↔ CTS、HND ↔ FUK 都会经过） |
| 青藏高原下游 | 中国东部冷季有大片层云（Klein & Hartmann 1993；10 月到次年 3 月最多，2 月和 10 月双峰，7 月最少），冬季上海 / 长江上空常是连日阴天 | 1 月长江 0% 层积云 | 错。PVG ↔ PEK、PVG ↔ CAN 冬季应该是「云海之上」 |
| 信风积云 | 18–28°N 海上，云顶受信风逆温限制在约 2–3 km [教科书] | ✓ | 合理 |

### 1.6 雷暴

- **类型**：现有孤立、团簇、飑线。东亚真实的组织形式以多单体和中尺度对流系统（MCS）为主，超级单体较少 [教科书、气候：东亚超级单体研究较少，比例未量化]。**缺**：
  - 单体生命周期（积云 → 浓积云 → 积雨云，约 20–40 分钟；成熟后砧向下风扩展；消散时塔身崩塌，只剩一片孤立的砧和雨幡）；
  - 多单体的新旧交替（新塔总在上风 / 右前侧冒出来）；
  - 飑线前沿的弧状云和阵风锋；
  - 夜间 MCS 大片层状云砧（几百公里）。
- **时间尺度**：单体上升速度 5–20 m/s，塔顶每分钟涨 0.3–1 km [教科书]，1× 播放下肉眼就能看出「在长」。现在按 5 分钟取样限速插值，而雷暴单体一经摆放就不再生长（只在摆放时按强度缩放）。
- **闪电频率**：平均每单体 5 s 一次（12 次/分钟），属于强雷暴的量级；普通雷暴约每分钟 1–10 次 [教科书，量级]。建议按生命周期和强度调节。

### 1.7 能见度、霾、沙尘、雾

- ✓ 边界层霾（T18）的物理很扎实。
- ✗ **抬升的气溶胶层**：春季黄沙（3–5 月，在 1–6 km 输送，气象厅的黄沙观测日数这几个月最多 [气候]）、东南亚春季烧荒烟（3–4 月，2–4 km）。这些层在混合层**上面**，巡航时俯视是一层黄褐色的「顶」，地平线整片发黄。现在的 LUT 只有混合层霾，没有抬升层。
- ✗ **海雾 / 平流雾**：黄海和东海 4–7 月（春夏暖湿空气流过冷海面）；北海道东部和三陆夏季（亲潮冷水，やませ）[气候，概述]。从高处看，一片平而白、边缘顺着海岸线的雾顶（0.2–0.6 km），岛和半岛从里面冒出来。在东亚航线上很常见。
- ✓ 谷地辐射雾（T18）。

### 1.8 降水类型与可见现象

### 1.9 高空风与云的形态

- **风切变**：卷云马尾、砧向下风延伸、塔身倾斜，现在都用一个固定方向。真实方向因地因季不同：冬季东亚急流中心在日本上空，200 hPa 常年最强约 70 m/s 以上，吹西风 [教科书]；盛夏华南到南海高空是东风（青藏高压南侧），**砧往西吹** [气候]。
- **Kelvin–Helmholtz 波状云（*fluctus*）**：切变层上的一排「浪花」，存在时间只有几分钟，罕见而上镜。可以作为高层 / 中层薄云层的一种短暂纹理。
- **山地波、荚状云、背风波**：稳定层结 + 风向大致垂直于山脊 + 风随高度增强时，山的下风方出现一排排静止的荚状云（波长 5–25 km），以及山顶上的笠云 [航空：FAA AC 00-6B 山地波一章]。**富士山的笠雲 / 吊るし雲**在日本很出名（民间有「笠雲がかかると雨」的说法 [经验，未量化]），而 HND ↔ ITM / KIX / FUK 的航线正好经过富士山附近。台湾中央山脉和日本阿尔卑斯的背风侧也常见。现在完全没有。
- **背风侧的焚风晴空**：冬季日本海一侧下雪，越过脊梁山脉后太平洋一侧晴空（云在山脊上戛然而止，形成**焚风墙** / 云瀑）。和雪云街一起做，性价比最高。

### 1.10 湍流 / 颠簸的气象成因

| 成因 | 真实 [航空] | 现状 |
| --- | --- | --- |
| 对流 | 积云里轻度，浓积云里中度，积雨云附近 20 海里内可以到严重程度 | ✓ 云密度 + 靠近雷暴 |
| 晴空湍流 CAT | 急流附近的强切变区（理查森数小），冬季日本上空是全球 CAT 高发区 | ✗ |
| 山地波 | 背风波和转子（rotor）；高空也可以有强波动 | ✗ |
| 尾流 | 近距离跟在别的飞机后面 | ✗（T40 把远处飞机放得很远，不需要） |

ICAO 附件 3 用涡耗散率（EDR）分级报告颠簸（阈值见原文，**未逐字核对**）。建议把颠簸源拆成「对流 / CAT / 山地波」三路，外加机长广播和「系好安全带」灯（体验上的真实感）。

### 1.11 结冰条件

结冰主要发生在 0 到 −20 °C 的过冷液态云里，积状云是明冰，层状云是雾凇 [航空]。现在窗上挂水按 ISA 气温判断，没有冻结高度随季节变化这一项，也没有过冷水滴撞到窗框和机翼前缘结成的霜白。巡航时（−50 °C 左右）几乎遇不到。**对乘客观感是次要项**，只在低空和进近时有意义。放进 W18，顺带做。

### 2.2 「按真实日期重放当天天气」的可行性

- **可行，代价低**。选定日期和航段后：
  1. 沿大圆每约 75 km（按 Open-Meteo 的 0.1–0.25° 网格，远粗于我们程序化的尺度，够用）取点，一次请求 Historical Forecast API，拿当天 24 小时的三层云量、CAPE、冻结高度、能见度、250 / 500 / 850 hPa 风、300 hPa 湿度；
  2. 缓存到 IndexedDB，键是（日期, 航段）。同一段航线重放不再请求；
  3. 台风用 IBTrACS 或气象厅最佳路径做离线小表（随包发布，注意署名）。
- **限制**：模型的云量是网格平均，没有「云型」。云型要靠规则从变量推出来，例如「低云多 + 静力稳定 + 冷季 → 层积云 / 层云」「CAPE > 1000 J/kg 且午后 → 积雨云」「高云多 + 300 hPa 湿度高 → 卷层云；湿度中等 → 卷云」。这些规则属于**经验映射**，要标成估算。
- **真实性标注**：数据驱动时信息栏写「天气：Open-Meteo（CC BY 4.0）· 2024-07-15 重放 · 云型由规则推断」；程序化时写「天气：示意（非真实数据）」。这是 AGENTS.md「数据要真实，示例要标」的要求。

### 2.3 「实时天气」

- 技术上和重放一样（换成 forecast API，每小时刷新一次）。一段 2 小时的航程约 2–4 次调用，离每天 1 万次的上限很远。
- **导演取舍冲突**：`composeForWindow` 会把雷暴挪到窗外一侧，用真实数据时应当关掉或减弱，否则就不是「真实」了。反过来，真实天气常常一整段都是「晴空」或「平淡的层云」，背景板模式可能变单调。建议做成三档：「示意（默认）/ 真实日期重放 / 实时」，在前两档里保留导演构图。
- **MSFS 的做法**（公开资料，细节未核实）：MSFS 用 Meteoblue 的实况加预报数据驱动三维云，再注入 METAR 修正机场附近的云底和能见度。我们规模小得多，Open-Meteo 已经覆盖同类变量。

### 2.4 与现有程序化天气场的融合（架构）

```
             ┌─────────────── 大尺度（≥ 50 km、≥ 1 h）───────────────┐
 数据源（可选） → AnalysisProvider.sample(lat, lon, t) → { 低/中/高 云量, CAPE, 冻结高度, 风, 能见度, 天气码 }
                                   │（缺数据 / 离线 / 示意模式时回退到 WeatherField 的气候态函数）
                                   ▼
 WeatherField.sample() ——规则打分——→ WeatherSample { layers: [低, 中, 高], 风, 霾, 对流潜势 … }
                                   ▼
 WeatherDirector（不变）：限速插值、借遮挡换族、雷暴 / 台风「系统」按 CAPE / 最佳路径摆放
                                   ▼
 渲染（不变 + 新变体）：程序化噪声给出 < 50 km 的一切形态
```

要点：

1. 数据只替换 `WeatherField` 内部的「大尺度 fbm 云量 / 对流潜势 / 锋面带 / 卷云噪声」这几个输入项，打分和导演的逻辑都不动。这是最小的侵入。
2. 数据是网格值，在空间和时间上做**双线性插值**，避免 1 小时一跳；导演原有的限速插值（云量约 40 分钟满幅）会自然平滑剩下的变化。
3. 雷暴：数据给「这一带有没有对流、多强」（CAPE、对流降水、`weather_code` 95–99 表示雷暴），单体的位置仍然用哈希生成（模型分辨率本来就解析不了单体）。
4. **离线兜底**：请求失败、超限、没有网络时，自动回退到气候态函数，不影响渲染。

## 4. 与现有架构的衔接和分期任务

### 4.1 什么便宜，什么贵

- **便宜（只改天气场）**：`WeatherField` 的打分、季节 / 日变化项、系统的生成规律、`WeatherDirector` 的节奏，以及 `uUpperWind`（已经是 uniform，只是没人写）、`state.wind`、航迹云参数（uniform）、颠簸。对着色器零改动、冷编译零影响。
- **中等（改 uniform / 常量）**：GLSL 里的 `HIGH_WIND`、`LOW_WIND` 两个常量改成 uniform。云步进的程序文本会变，要重编一次，但不是新变体。**风险**：W00 / T12 的教训是「小改一处都可能让云步进跳到慢一档」，必须用 `scripts/passes.mjs` 按 pass 计时，对比 noon-cumulus 和 typhoon-bands。
- **贵（改云渲染）**：多层、新云种（荚状、层状降水、雾）。**任何新天气类型都要做成按需编译的 `#define` 变体**，和 PERF-10 的拆分方案（晴天 / 雷暴 / 台风变体，启动只编晴天版，首帧后在后台预编译）保持一致：
  - 默认程序预处理后的文本要和改动前**逐字相同**（W00 的验收法）；
  - 新变体第一次需要时在后台编译，编好之前用降级画法（例如高层薄云先不画，或者退回现有的卷云变体）；
  - 变体数量会组合爆炸（晴天 / 雷暴 / 台风 × 卷云 × 高层 × 奇观 …）。建议 PERF-10 之后先定一个**变体组合策略**：互斥的放进同一个轴（例如高层薄云的 Ci / Cs / Cc / As 顶部是同一个变体里的 uniform 分支，**在薄层 pass 里**而不是在云步进里，不受 W00 的坑影响），可以共存的才拆成独立的 define。

### 4.2 多层云的渲染方案（W12b 的核心论证）

- **沿视线的遮挡顺序是确定的**：在相机高度以下的层，永远挡在相机高度以上的层前面。
  - 向上的视线高度单调增加，碰不到下面的层；
  - 向下的视线先穿过下层，越过切点后高度才回升，最后在几百公里外才可能碰到上层。

  所以合成顺序只取决于「这一层在相机之上还是之下」，不需要逐像素排序。
- **高层薄云不必进体积步进**：Ci / Cs / Cc 的光学厚度只有 0.03–3，几何厚度 0.5–2 km。现成的做法是 T44 给卷云盖外围用的「本点消光 × 斜程的解析光学厚度」，加上单次散射（冰晶 HG + T17 的晕、幻日份额）。它可以做成**单独的全屏 pass**：二维噪声（丝缕 / 鳞片 / 幕），一条视线只算一次球壳交点，成本约等于一次海面耀斑，不会碰云步进的寄存器分档。
  - 合成：相机在层下时，`L = 云步进结果 + T_步进 × (L_薄层 + T_薄层 × 天空)`；相机在层上时反过来。云缓冲右半的深度（T38）照样可以写。
  - 相机**在层里**（巡航高度在卷层云里）时：窗外整体偏乳白、太阳带晕。用「相机所在层的光学厚度」给窗外加一层均匀的雾就能近似，不用步进。
  - 云影：高层薄云对低云和海面的影子用二维透射率图（云影图多一个通道，或乘在现有云影图上）。
  - **顺带修掉 T17 遗留的「22° 晕漏到低云上」**：晕只在薄层 pass 里生成，按薄层的透射率合成。
- **中层厚云（As / Ns）**真要立体感时，要让云步进支持**第二个球壳区间**（两段步进，各有步数预算），这是 L 级别，放到后面（W12c）。锋面序列的第一版可以先让 As 用「薄层 pass + 较大光学厚度」近似（从巡航高度俯看 As 顶部就是一片平而微起伏的灰白），Ns 用现有层积云族加厚应急。

## 开发体验反馈

1. **编号冲突**：`W` 前缀在看板上已经给奇观用了（W00–W03），这次按指派从 W10 起编，天气任务会和奇观任务混在一个前缀下。建议气象系列改用 `WX` 或 `M`（meteorology）。
2. **天气场缺一个离线统计工具**：`handoff/T19b-field-stats.mts` 只沿一条航线跑。这次写的「月份 × 地区 × 时段」统计很快就发现了几处气候错误，而且不开浏览器、不占 GPU、几秒跑完。建议收进 `scripts/weather-stats.mts`，并把附录 A 的目标区间写成断言。W10 的验收可以完全自动化，也适合做回归检查。
3. **`uUpperWind` 没有任何写入方**。grep 只有读（`weather.ts:215`、`clouds.ts` 的缓存键），初值 (0.8, 0.6) 等于常量，不容易被发现。「看起来是可调的 uniform，其实全程常数」这类情况，建议在 PARAMS.md 里单列一行，或者加一个 lint 检查。
4. **测量锁和截图顺畅**：`measure-lock.mjs`、`dev-browser shots --respect-lock` 一次成功，4 个场景没有 console error。
5. **外部数据的 CORS 结论值得记进 README**：Open-Meteo 和 JMA bosai 允许跨域，aviationweather.gov 不允许，并且要求自定义 UA。以后派数据任务时可以直接引用，不用再测。
6. 本文没有新增仓库脚本（按「只产出文档」的要求），复现逻辑写在附录 A。如果协调者同意，把两个统计脚本收进 `scripts/` 很便宜（见第 2 条）。
