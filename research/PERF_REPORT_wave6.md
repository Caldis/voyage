3. **march 的增量按任务拆开**（离线 FXC，沿合并链轮转 3 轮取最小值，占基线的百分比）：
   - T37 **+20%**；

### 4.1 判定

- **所有场景的 GPU 合计都在第 3 波预算内**，也低于绝对线 7.4 ms。雷暴、台风比第 3 波（7.3–8.8 ms）便宜了一半多。

- 按今天的增量看（没有超预算，但涨了）：

## 八、开发体验反馈

- **哪里慢**：一共约 1 小时 40 分。最费时间的是等机器安静：TR02 截图占了约 15 分钟；18:40 起有别的进程在跑 `cc1` 并伴随 Defender 扫描，使扫描 A 整轮作废，重跑又花了约 25 分钟。离线 FXC 串行跑一轮全部程序约 2.3 min，因为 exposure-meter 一个程序就占 25 s。
- **哪里卡**：
  1. **`shader-budget --baseline` 对不同时期的树直接失败**（`Cannot read properties of undefined (reading 'fragmentShader')`）。它用**当前**树的 `collectPrograms` 去枚举基线树的材质，基线里没有的材质（奇观、卷云、经济舱）一访问就崩。绕法是两侧各跑自己的 shader-budget，自己写脚本交替。建议：两侧各用自己树里的 `lint-shaders.mjs` 枚举，按程序 id 取交集，缺的程序标「新增 / 删除」。
  2. **shader-budget 只输出中位数**，没有最小值、MAD 和原始轮次（DX-10 已列）。`--out` 的 JSON 里有原始值，我自己算了。
  3. **exposure-meter 离线 25 s，浏览器里 0.25 s**，偏差百倍，账本和串行测时都被它拖累。建议 shader-budget 默认跳过、标注它，或者查清 ANGLE 实际用的编译标志。
  4. **passes.mjs 认不出 `CLOUD_CIRRUS` 变体**，卷云步进算进了「其他」。另外，GPU 空闲时它也打印「还有 N 个查询没读到结果（GPU 被占满时常见）」，提示会误导人。
  5. **passes.mjs / scenarios.mjs 不能对老版本做基线**：老页面没有 `cabin-class` 控件时，`set()` 直接抛错。建议 `applyScene` 对不存在的控件和不存在的下拉选项容错（打印警告后跳过），`js` 失败也只记录不中断。这样 `--baseline` 可以跨版本对照。本次在基线 worktree 里放了一份容错副本，已随 worktree 删除。
  6. 没有「一键测某个程序沿合并链的变化」的工具，我写了 `march-chain.sh`。这类归因以后每波都要做，建议并入 DX-10：`shader-budget --chain <提交列表> --only <程序> --rounds 3`，内部用临时 worktree 轮转。
- **怎么绕过的**：两侧各跑各自的工具，用 bash 交替；场景脚本做容错副本；所有判定按交替轮最小值；测前、测中看 `\Processor(_Total)` 与各进程 CPU 占用，发现 `cc1` 后作废整轮重测。
- **希望有**：`shader-budget --chain`、跨版本容错的 `--baseline`、passes.mjs 按材质名自动归类（DX-16），以及一个「测量锁」：性能工程师测量时，其他代理暂停编译 / 截图。这次靠协调者口头通知，还是撞上了一次不明来源的 `cc1`。
